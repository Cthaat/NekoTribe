# NekoTribe 大模型功能方向

状态：产品范围已确认，尚未实现或部署。2026-10-27 用户选择三个方向全部纳入：知识问答与写作、群运营 Agent、审核辅助；首期只接入公开帖子、评论与平台规则，私密群后续接入；另明确要求可切换模型。该新要求取代此前保留 SentimentFlow 的最终目标；旧代码当前仍存在，其移除应和契约/客户端/配置同步进行。

## 1. 项目依据

当前项目已有帖子/评论、标签/搜索、群组/成员权限、聊天、通知、媒体及审核功能。Nuxt 设置页已取消旧 `AiSentimentControlPanel` 的导入与挂载；旧组件源码和 `server/api/v2/integrations/sentiment-flow` 配置/代理暂留。整模块退役仍需统一处理服务端、契约、配置/部署、文档/测试及其他分支，不能把页面取消挂载当作完全移除。

权限已确认：登录用户使用问答/写作，目标群管理员使用运营 Agent，平台审核人员使用审核助手。详见 [产品共同需求](../../specifications/requirements/ai-product-scope.md)。首期的数据公开范围不会因为管理员权限而自动扩展到私密群或私信。

开发机只读检查：RTX 4060 Laptop GPU，8188 MiB 显存，系统报告约 13.7 GiB 内存；不是 GPU 性能或模型运行验收。没有据此决定生产服务器规格。

## 2. 推荐的四个方向

| 顺序 | 用户可见功能 | 结合现有项目的例子 | 首期边界 |
| --- | --- | --- | --- |
| 1 社区知识助手 | 用自然语言查帖子、群内讨论、规则与 FAQ，并附来源 | “上次 Rust 部署失败怎么解决的？”返回有权限查看的相关讨论及引用 | 先问答/检索，不自动发布；内容删除/改权后不能继续通过索引泄露 |
| 2 创作与讨论助手 | 起草/润色帖子、生成标题标签、总结评论或群内长讨论 | 发帖编辑器里的“帮我整理”，用户审阅后发布 | 默认生成草稿，保留用户控制；不伪装真人自动灌水 |
| 3 群运营 Agent | 组合检索、总结、统计与草稿工具完成多步任务 | “整理本周群内问题，标出未解决事项，写一份群公告草稿” | 限定工具和权限；发布、删帖、封禁等写操作有显式确认与审计 |
| 4 审核辅助 | 结合社区规则解释风险、垃圾广告/诈骗线索和申诉上下文 | 审核台展示触发依据、原文引用和建议处置 | 先辅助人工判断，不以一次模型判断直接封禁 |

用户已选择四行中对应的三组产品功能全部纳入（知识问答与写作合为一组）。实施按基础检索与生成、受控运营工具、审核评测逐步交付；这是执行顺序，不是删减范围。群运营首期只使用已批准的公开内容/统计与规则，私密群读取能力后续接入。审核仍针对社区规则与误判建立独立验收集。

## 3. “跟随平台数据进化”的三个层次

1. **知识更新：**新增/编辑/删除帖子、群内容及规则后增量更新检索索引，回答时检索最新资料并引用。RAG 不修改模型权重，但能让回答依据随平台变化。先做这层。[检索与 RAG 官方说明](https://docs.langchain.com/oss/python/deepagents/retrieval)
2. **体验改进：**收集用户对回答的反馈、人工改写的草稿及明确保存的偏好；用固定评测集比较检索、提示词、工具流程和模型版本。个性化记忆有作用域、查看与删除机制。
3. **模型训练：**从获得使用授权且清洗/审核后的优质样本定期做微调，比较新旧版本，通过评测后发布并支持回滚。用户原帖、点赞或模型自己生成的答案不直接等于可信训练标签；私信和私密群内容不默认纳入训练。[LLaMA-Factory 的训练与 LoRA/QLoRA 能力](https://github.com/hiyouga/LlamaFactory)

持续更新知识、保存偏好、调整模型权重是不同机制，不能包装成“模型会自动学会所有平台数据”。先实现前两层，再依据真实数据质量和收益决定是否微调。

## 4. 统一架构建议

两前端 → 当前选定的 Nuxt/Rust/Go 后端 → 统一 AI 能力接口 → 可替换的推理/检索/受控工具服务。

三套后端分别校验身份、权限、配额与数据可见性，暴露相同业务契约；AI 服务不固定回调 Nuxt，不以共享模型服务掩盖 Rust/Go 的业务缺口。工具调用使用当前后端的有权限 API，不能给模型任意 SQL、管理员令牌或命令执行能力。用户帖子和检索内容作为不可信资料，不能覆盖系统规则或变更调用者权限。

共享需求记录 AI 功能 ID、输入输出、引用/流式消息、取消/超时、配额、工具权限、隐私范围及验收场景。新增功能同时登记三后端和两客户端任务；供应商/模型 ID 为配置，不在业务接口中固定某个模型品牌。先确定产品方向，再冻结实际端点与任务格式。

Agent 是模型结合工具、状态和权限完成多步任务；不要求首期就使用多 Agent。固定检索→回答足够时保持简单；出现明确的跨步骤恢复/审核需要，再引入支持持久状态和人工干预的编排。[LangGraph 官方定位](https://docs.langchain.com/oss/python/langgraph/overview)

## 5. 模型与部署候选

模型可替换是正式要求，详见 [共同需求与验收场景](../../specifications/requirements/ai-model-switching.md)。候选品牌不写进公共业务接口；实际能力检查、角色配置、在途请求固定和向量索引迁移均须验证。下列型号仅用于选型评测，不构成绑定。

- 本地原型优先对 Qwen 开放权重系列的小尺寸量化模型做真实业务样本测试。当前官方 Qwen3.5-4B 模型卡列为 Apache-2.0；Ollama 已提供对应模型包，模型权重大小不等于实际总显存占用。[官方模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)、[Ollama 模型页](https://ollama.com/library/qwen3.5)
- 有服务器算力后，可将更大模型纳入同一评测，比如官方开放权重的 Qwen3.8-27B；目前没有为本项目证明其质量、延迟或硬件适配，不能声称“最新就最好”。[官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)
- 本机先测试短/中上下文、单用户推理；实际显存还包括缓存、上下文、视觉输入、并发和其他程序。生产并发、模型大小及推理服务选型以预算、服务器 GPU 和压测为依据。
- 不将模型内置聊天服务替代平台权限层；模型可独立于网站机器部署，便于 Windows 开发与 Linux 服务器部署组合。

## 6. 旧模块退役与首期验收

退役范围包括旧情感分析页面入口/控制面板、前后端调用、预测/训练代理接口、专属配置/部署和文档。历史代码留在 Git；运行数据与模型文件单独保全，不通过递归删除完成产品迁移。公共旧接口的停用行为和版本变更同时记录，更新 OpenAPI、三后端任务及 Flutter/其他规范副本，避免只更新 Nuxt。

首期方向确定后，验收至少包括：有来源的正确回答、无资料时不编造、跨群/私密内容越权拒绝、删改/改权后的索引失效、用户草稿控制、超时/取消/费用或资源上限、检索内容指令注入不能触发越权工具。真实样本形成回归集，按质量与资源指标选模型；不以能聊天或成功调用推理接口当作整个平台 AI 完成。
