# 安全页身份变化与即时失效

继续完整多框架/业务/AI目标下的双客户端安全页工作。现有响应归属守卫不能清除已经显示的secret/URI/恢复码/敏感表单，也不能可靠阻止旧页面在同账号重新登录后再次发起操作。

设计：复用每Nuxt app的认证队列及每Flutter TokenStore的会话版本，增加同步观察通知和身份变更在途状态。登录/2FA完成/退出从意图开始到结束保持在途；本地清理同样通知，普通刷新不变更身份。不广播token或用户数据。

安全页以创建时的仓储/app与版本为owner。通知到达后移除整组旧表单，卸载清理/定时器照常执行，旧动作入口和迟到结果仍须守卫。身份变更未结束时不允许重新绑定旧凭据；结束后提供“重新打开安全设置”，新建子页面/表单并重新读取当前状态，不复用旧秘密或旧OTP。Flutter还响应AuthRepository实例替换；Nuxt每app/SSR各自隔离。

- [x] 完成相关认证/客户端回归、类型/静态检查、共同规则/功能登记与接手更新。

不解决跨标签页/跨设备广播，不承诺擦除不可变字符串的物理内存。真实平台Cookie/存储、Oracle/OTP/六组合及部署仍待C3；不启动Docker或真实依赖，不改日常数据、分支、提交或原交接档案。
