# Nuxt 认证响应运行时校验

目标：让登录、双因素完成及刷新在发布状态前拒绝畸形响应，与既有Flutter安全字段校验规则对齐。不增加后端新接口，不启动Docker或真实服务。

实施：

1. 共同JSON向量保存完整合法用户/令牌/挑战基准和显式路径变更，覆盖三种操作的合法、缺失、错误类型/身份、非法日历/时区、到期顺序。Nuxt实际service和Flutter实际parser/TokenPair消费相同文件，复制到三个契约目录并登记SHA。
2. 新增纯校验模块，输入unknown、固定安全错误，不附带响应/令牌。普通登录必须有布尔开关；挑战完成可省略开关，若存在必须false；成功至少验证安全正整数user_id、非空username以及完整令牌。保留既有完整资料mapper，校验其失败统一为安全错误，不改变其他用户接口。共同向量使用完整用户资料，不据此宣称所有资料字段/兼容缺省已跨端统一。
3. 令牌日期使用显式日历/时间/偏移范围检查，允许1至9位小数，按Flutter微秒精度比较时间；拒绝等于/倒序，不按当前客户端时间拒绝过去样例。Web只返回会话ID/到期信息到VM，不把token新增到可读偏好。
4. Pinia在原版本内刷新，若原本已有sessionId则核对不变；无本地sessionId时不编造旧凭据。错误不发布、不重放，只按原版本失败清理。Cookie是否已被浏览器接受仍须C3验证。
5. 先运行失败向量，再实现、运行相关Node/Flutter测试与analyze/typecheck、contracts/parity，更新共享需求和最新交接。Rust/Go本步只同步规范与样例，不重编译未变的运行代码。
