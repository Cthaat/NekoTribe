# H2：两个客户端的 AI 启用状态

范围：接入现有 `GET /api/v2/ai/availability`，不新增后端权限、不声称真实模型可用。不启动 Docker 或真实依赖。沿用现有问答/写作页面和错误恢复机制。

交互采用单个状态区域与刷新按钮，而非隐藏页面或只在生成报错后提示：四态为读取中、已启用、未启用、读取失败。进入页面读取；手动刷新重新读取，期间旧启用结果不可继续放行发送。读取失败或任一必需字段不是布尔值时按未知处理，不把字符串/数字转成 true。分别使用 knowledge/writing 字段，不相互替代；不展示群运营/审核的未来能力。

发送与重新生成仅在本页用途最近一次查询为已启用且不在读取中时放行；页面和 controller/callback 都检查。状态只用于客户端体验，服务端在每次生成时仍独立授权和复核配置。允许在未启用/未知时编辑输入、查看/恢复/删除历史及刷新已有会话；刷新状态不得清输入、会话或重复追加消息。不自动重试生成。状态不保存到本地持久缓存，旧查询不得覆盖较新的结果。Flutter 的 provider 随 API client 变更重建状态。

实施顺序：

1. Nuxt：先写状态/请求校验/竞态和保留输入测试，再增加共用 API、controller 状态及页面区域和中英文文案。
2. Flutter：先写 API 解码和 widget 行为测试，再增加 typed model/API、autoDispose provider、界面与中英文文案。
3. 将 UI 行为追加共同需求并同步 Rust/Go 副本；登记两客户端实现位置、三端目标 revision 和共用场景，不提升 accepted。
4. 运行 Nuxt 针对测试/类型、Flutter 相关测试/analyze、contracts/parity 检查，记录实际通过和未做的浏览器/真实后端矩阵。

验收：两用途互不混淆；缺失/非法响应/503 均呈现未知；停用和未知不发 create/append/generate；刷新后可恢复生成且草稿不丢；慢旧结果不覆盖新结果；历史与删除不受 availability 故障阻断；未知/停用状态不假称模型离线或权限授予。
