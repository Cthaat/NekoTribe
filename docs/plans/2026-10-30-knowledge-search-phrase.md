# 知识会话：问题与检索词分离

状态：开发中。现有知识生成把整个用户消息作为精确子串搜索，通常无法检索自然语言问题。本计划为过渡方案；它不替代后续语义检索、向量索引或完整多轮上下文。

## 行为与兼容性

- 用户问题仍通过原有消息接口持久化；模型接收最近一条用户消息作为问题。生成请求可另外携带检索词，仅用于搜索当前用户允许访问的公开内容，不改变原问题、不提供额外权限。
- 保持现有空请求兼容：缺省检索词时继续用最近问题作为搜索词。新客户端可发送 JSON 对象 `{"search_phrase":"猫"}`，字段以外的内容、非对象、非字符串及非法输入均应明确拒绝，不接受模型地址或凭据。
- 检索词首尾空白和有效性遵守 `ai-knowledge-discovery.md`：ECMAScript trim、有效 Unicode、1–256 UTF-8 字节、无控制字符。三端必须共同执行相同向量；请求体需有大小限制。问题仍受现有消息与模型上下文预算约束。
- 检索词不保存为新消息，不进入模型系统指令或日志。重新生成时可显式再次提供；当前阶段不会在历史恢复后保存或自动恢复检索词。查询、推理及写入继续执行原有权限、来源复核、序号冲突、取消和失败关闭规则。
- Nuxt Web 和 Flutter 提供独立的问题与检索词输入，清楚说明当前精确匹配；无证据时允许用户调整检索词重试且不重复追加原问题。发送失败结果不确定时先刷新，不自动重复写入。

## 推进与验收

1. 各后端内部将问题和检索词分开，验证模型收到原问题，检索只用检索词，无证据不写入，权限和来源复核不变。Nuxt、Rust、Go 内部链路已有实现及隔离测试；公开接口尚未接入。
2. 统一 OpenAPI、三端请求解析和公共边界场景，验证空请求、合法/非法对象、Unicode、长度、未知字段及服务端密钥隔离；在三端均接线前客户端不默认发送新字段。
3. 更新两个客户端与重试流程，验证修改检索词不重复写入消息；同步共同需求副本与实现证据。
4. 后续以隔离 Oracle、真实模型和两客户端验证检索、授权撤销、并发和跨后端一致性。此计划不能把模拟结果当作最终验收。
