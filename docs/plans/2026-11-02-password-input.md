# 新密码输入规则统一计划

以现有Nuxt注册/重置/安全页6位规则为基准，将其落实到三后端和Flutter。当前后端仅要求trim后非空，Flutter页面没有6位检查，Nuxt页面在trim前计数；这些差异必须消除。登录继续兼容旧短密码。

共同规则：JavaScript trim字符集合（保留U+0085/U+200B，去除BOM等）；新密码trim后至少6个UTF-16代码单元，沿用原Zod/String.length含义；确认值按同一规则去空白后比较。保留内部空白和既有bcrypt UTF-8前72字节兼容语义，不增加复杂度、字符组合或新长度上限。注册按既有字段/条款/确认顺序后校验长度；重置字段解析后、OTP读取/消费前校验，失败不得写数据。

1. 共同合成输入向量；Nuxt实际SFC schema和实际HTTP注册/重置、Go/Rust实际路由、Flutter页面回归先观察失败。
2. 修复三后端新密码检查及安全错误；Nuxt三份新密码schema和登录schema改为trim后验证；Flutter使用明确JS trim工具、归一化快照与新密码提示，保留登录短密码。
3. 跑相关认证/客户端/类型/静态分析/契约与parity检查，更新共享需求、版本和接手状态。Rust沿用禁用增量/debug的离线配置；不启动Docker或真实依赖。

邮箱格式、用户名/显示名长度、完整2FA/删除账号生命周期、限流与并发撤销仍须继续；本切片不代表所有输入或完整业务已完成。新密码API原先允许短密码，现在会400拒绝，这是落实现有Nuxt UI规则的有意收紧；不迁移或强制修改已有密码。
