# 新账号资料输入统一计划

沿用Nuxt现有Zod/v3邮箱规则与注册用户名/昵称trim后最少2个UTF-16代码单元，补齐三后端与Flutter。邮箱保留大小写、内部字符和既有Zod允许范围，不自创RFC全量实现、不增加最大长度或用户名字符限制。旧账号登录、旧邮箱的密码重置API和OTP验证继续兼容，不迁移数据；只有注册、新邮箱修改及用途register/change_email的邮件发码收紧。SMS仍先返回501。

- [x] 建立共同字符串/标量输入向量，运行Nuxt实际SFC schema与三后端注册/新邮箱/OTP路由的失败回归；Flutter实际注册/找回/安全页检验发码与提交。
- [x] Nuxt共享纯校验器复用已安装Zod，服务在原必填/条款/确认/密码检查后、OTP/查询/写库前返回固定400；Go/Rust使用等价ASCII邮件规则和UTF-16长度，不增加依赖。Flutter复用JS trim工具并使用同一邮箱规则，校验后提交快照。Nuxt找回/安全页补发码前邮箱检查。
- [x] 跑相关认证/页面回归、typecheck/analyze、Go全量test/vet与Rust相关离线路由测试；同步OpenAPI、共享需求/向量、parity版本和接手入口，保持in-progress。

验收要求：新输入不合法时不得读取OTP、分配业务ID、写入或发邮件；改邮箱仍先鉴权，不能绕开身份检查；登录仍不套用新名字/邮箱规则。真实数据库、SMTP、平台Cookie/设备持久化和六组合延后C3，不启动Docker/真实依赖。
