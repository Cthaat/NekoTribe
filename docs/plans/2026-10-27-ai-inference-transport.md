# AI 推理传输切片实施计划

属于总体原生后端同步计划 P6 / AI-MODEL-SWITCHING 的组件增量。不能替代 P2/P3 的原生服务/会话/角色接线，也不把模拟提供方当真实模型验收。需求和候选引擎来源见 `specifications/requirements/ai-inference-transport.md`。

1. **统一行为与数据**：冻结非流式文本、工具提议、JSON schema 编码/响应归一化、凭据/超时/取消/体积/深度边界；公共合成 JSON 场景复制到 Rust/Go。设计审查已确认身份编码、可见 ASCII 凭据和有限深度规则。
2. **三套原生实现**：Nuxt 使用服务端 Fetch，Go 使用标准 HTTP client，Rust 复用 reqwest；各自红绿测试公共场景与 loopback HTTP。只调用选定提供方，不借 Nuxt 业务代理；没有工具执行器或产品端点。
3. **协议与质量审查**：先核对组件规范/共同样例，修正后再检查安全边界、可维护性和测试有效性；发现真实差异先加入回归，再修复。
4. **同步与验证**：登记新增 server 来源、三端源文件、公共文件哈希；运行组件回归、全 Nuxt 类型检查、Go test/vet、Rust WSL 编译/测试、两套契约检查。记录失败/未运行，不制造 accepted 证据。
5. **保存检查点**：四个固定工程保持各自分支，分别提交本组件和公共副本；更新检查记录。Flutter 没有新增业务端点可调用时不添加空入口。旧源码恢复包仍是历史快照。

后续必要工作仍包括流式与工具结果回合、真实模型/资源能力检查、管理配置入口与权限、独立认证/业务服务、公共内容检索/索引失效、三组 AI 产品和 Windows/Linux/跨机器验收。实际后端/数据库/Docker/模型保持静态阶段，集中联调按总体计划执行；当前单元测试可临时监听 loopback，结束后关闭。
