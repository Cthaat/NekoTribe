# 通知删除与恢复开发检查点

Nuxt、Rust native 和 Go 对齐删除与恢复接口。删除限定当前用户且仅对未删除通知生效，重复删除返回 404；恢复限定当前用户，对已删除和未删除的现有通知均成功。两者成功后向当前用户发送相应实时事件。Nuxt 的删除时间读取补充用户条件，两个 Nuxt 路由统一使用安全正整数 ID、私有缓存头和错误脱敏；ID 收紧属于公开输入行为的兼容性变更。

共同需求、场景和四份 OpenAPI 副本已同步；Flutter 已有删除和恢复调用，接口契约专项通过。Go 仓储替身与 Rust 执行器替身检查用户和通知绑定、删除条件、恢复和删除时间读取；Go 还检查读取错误时先前数据库提交以及事件发布失败不撤销更新。

验证：Nuxt 全量隔离测试 567 通过、2 跳过，类型检查通过；Go 全量 test/vet 通过，新增发布失败专项通过；Rust 格式整理前离线全量测试通过，真实依赖测试仍忽略，Windows rustfmt 对通知实现及测试文件的格式检查通过，整理后通知专项 7 项通过。三端规范检查覆盖 74 份共享文件，整体仍为 `accepted:0`、`ready:false`。

事件投递不能与数据库更新原子化：删除后的读取失败可能发生在写入已经提交之后，Redis 故障时实时事件可能丢失。Oracle 日期/时区、数据库并发、Redis/TLS、跨实例和两个客户端的真实运行仍需最终隔离验收；本轮没有启动 Docker 或访问日常数据库。
