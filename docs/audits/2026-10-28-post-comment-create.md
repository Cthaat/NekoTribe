# 创建帖子评论安全检查点

Nuxt 原创建评论接口未检查当前用户对目标帖子的可见性。现校验安全帖子 ID 和可选父评论 ID，读取帖子的权限后，在 INSERT SQL 内再次检查帖子可见性、未删除状态及父评论属于同一帖子且未删除；零行重新检查并返回安全错误。插入后的读取同样按会话用户、帖子和评论限定并检查可见性。接口补充私有缓存头和错误脱敏。严格 ID 解析是公开输入兼容性收紧。

隔离测试覆盖无权访问、无效 ID、根评论和回复、父评论不存在、帖子权限或父评论在插入前变化、指定作者通知，以及插入提交后读取失败不回滚。Nuxt 全量测试 569 通过、2 跳过，类型检查通过；随后增加的根评论专项通过。测试的数据库与通知均是替身，不证明真实 Oracle 语句快照、触发器、外键、驱动的空绑定或 Redis 事件。

共享需求、通知和验收场景见 `specifications/requirements/post-comment-create.md` 与 `specifications/scenarios/post-comment-create.json`。Rust 和 Go 的对应副本与四份 OpenAPI 已同步，但 **Rust native 和 Go 仍未实现评论创建或其通知流程**；仍需分别完成原生实现、权限/部分提交测试和最终真实依赖、双客户端联调。共同验收仍为 `accepted:0`、`ready:false`。本轮未启动 Docker 或访问日常数据库。
