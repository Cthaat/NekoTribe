# 用户设置 PATCH 开发检查点

Nuxt `PATCH /api/v2/users/me/settings` 要求 access 会话、设置结构检查、按用户创建默认设置行，再处理更新；`two_factor_enabled` 必须通过双因素流程修改。支持隐私、通知与既有情感分析设置。更新 `show_online_status` 后需发布用户在线状态；用户设置读取、写入与广播都须依据真实权限和共享数据完成。

Go 新增请求转换和白名单 SQL 构造组件，覆盖布尔值、可见性、旧模型名长度、top-k、双因素禁止和在线状态广播标记；未知字段不参与 SQL，绑定 user_id。GET 和 PATCH 原生路由接入会话鉴权、共用结构检查及 Oracle 事务中默认行创建、修改与读取；结构目录由 Nuxt 迁移定义生成，8 个隔离场景覆盖结构、约束与账本异常。PATCH 修改在线状态后查询当前状态，向共享 `ws:presence` Redis 频道发布 Nuxt 格式事件；隐藏状态不包含最后在线时间，Redis 失败降级，状态查询失败则在设置提交后返回错误。事务、路由和事件使用数据库、会话与 Redis 替身测试，真实 Oracle、Redis、并发首次初始化和客户端仍待验收。Go 的 WebSocket 目前只订阅个人通知，尚未消费全局在线状态频道，Go 客户端间广播尚未完成。

仍需建立三端共同需求与场景、Nuxt 行为边界、真实数据库结构检查和迁移、Go/Rust 独立路由与持久化、响应映射、在线状态事件和客户端联调。旧情感分析字段仍为既有兼容契约，日后随旧功能退役统一迁移；此步骤不删除旧数据。
