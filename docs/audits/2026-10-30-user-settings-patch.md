# 用户设置 PATCH 开发检查点

Nuxt `PATCH /api/v2/users/me/settings` 要求 access 会话、设置结构检查、按用户创建默认设置行，再处理更新；`two_factor_enabled` 必须通过双因素流程修改。支持隐私、通知与既有情感分析设置。更新 `show_online_status` 后需发布用户在线状态；用户设置读取、写入与广播都须依据真实权限和共享数据完成。

Go 新增请求转换和白名单 SQL 构造组件，覆盖布尔值、可见性、旧模型名长度、top-k、双因素禁止和在线状态广播标记；未知字段不参与 SQL，绑定 user_id。隔离单元测试覆盖常见输入和恶意字段名。组件尚未接入 HTTP 路由或数据库，不能作为接口可用的证明。

仍需建立三端共同需求与场景、Nuxt 行为边界、真实数据库结构检查和迁移、Go/Rust 独立路由与持久化、响应映射、在线状态事件和客户端联调。旧情感分析字段仍为既有兼容契约，日后随旧功能退役统一迁移；此步骤不删除旧数据。
