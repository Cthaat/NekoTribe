# Nuxt 发帖事务开发检查点

原发帖流程对帖子、媒体、标签、提及逐项自动提交，且仅以客户端提供的媒体 ID 数量判断空帖子。现在这几类写入在一个 Oracle 事务执行，成功后显式提交；选中的前四个去重媒体必须属于当前作者且处于允许状态，无法附加返回 400 并回滚。普通帖子必须有非空内容或实际附加的媒体；无内容转发仍可创建。已有发帖引用权限检查仍在插入语句内执行。

通知和最终帖子读取在提交后进行，失败时帖子可能已存在；通知可能部分成功。提交或回滚本身出错时事务结果可能不确定，不能保证已回滚或自动重试。媒体输入解析及整个发帖业务仍需继续还原并统一；Nuxt 的编辑帖子流程没有被改造成事务。

隔离事务替身测试验证写入不自动提交、去重、作者与状态限定、媒体不可用和标签/提及失败回滚、提交与回滚失败脱敏、提交后通知失败、空内容转发；Nuxt 全量回归 577 通过、2 跳过，类型检查通过。真实 Oracle 的触发器、事务、并发、锁、未知提交状态以及两客户端尚未验收。本轮未启动 Docker 或使用日常数据库。

共同局部需求与场景为 `specifications/requirements/post-create-transaction.md` 和 `specifications/scenarios/post-create-transaction.json`；Rust、Go 已同步需求但尚未实现发帖，不能视作三后端完成。
