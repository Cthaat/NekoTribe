# 三后端评论删除开发检查点

`DELETE /api/v2/comments/{id}` 的共同规则见 `specifications/requirements/post-comment-delete.md`。Nuxt 原实现只在更新前检查作者，未限制帖子可见性，更新语句也没有重新检查作者或评论状态。现要求规范安全 ID、有效会话和帖子当前可见；可见评论仅作者可以删除，其他作者返回 422，不存在、已删除或不可见返回 404。更新语句再次约束用户、评论、未删除状态、帖子状态和可见性；零行返回 404。该规则收紧旧行为，已同步 OpenAPI 和共同需求。

Rust native 与 Go 分别实现相同路由、绑定参数和软删除规则；不依赖 Nuxt 代理。Nuxt 全量隔离回归 570 通过、2 跳过，类型检查通过；Go 全量测试与 vet 通过；Rust 离线全量回归通过、2 项真实连接测试忽略，路由及仓储专项通过。隔离测试覆盖未登录、无效 ID、隐藏/删除/不存在、非作者、本人、重复删除、写入时变化及错误脱敏。

Oracle 的实际触发器、约束、数据类型、语句快照和并发、两个客户端以及跨后端共享数据仍需隔离真实环境验收，不能从替身测试推断已通过。更新与事务提交之间的并发变化不保证完全消除。本轮未启动 Docker，未连接日常数据库；共同登记仍为 `in-progress`、整体 `accepted: 0`。
