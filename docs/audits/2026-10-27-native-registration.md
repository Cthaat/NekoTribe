# 2026-10-27 原生注册检查点

Go 与 Rust 原生后端新增注册接口，复用共享 OTP、Oracle 用户模型、bcrypt 和 self profile；Nuxt 注册入口收口底层错误。共同规则和 29 条合成场景见 [注册规格](../../specifications/requirements/auth-registration.md)。三端分别验证了“创建验证码 → 未验证时拒绝注册 → 校验验证码 → 注册”的隔离流程，未模拟实际 Oracle 或真实邮件服务器。

- 场景覆盖输入与校验顺序、过期/未验证验证码、重复账号、写入失败和写入后资料失败，以及无 Cookie。仓储测试使用假驱动或执行器检查 SQL 及绑定；profile 返回在流程测试中使用替身，不据此证明真实数据库视图或触发器。
- Go、Rust 分别生成的长中文合成密码哈希记录在共同样例中，Nuxt、Go、Rust 均能验证正确密码并拒绝错误密码；真实跨服务登录仍待联测。
- 注册 OpenAPI 补齐必填字段、明确同意条款及 409/422 错误，四个工程的契约副本同步。
- Nuxt 全量测试 467 通过、2 跳过，类型检查通过；Go 全量测试、vet 及 Windows/Linux amd64 构建通过；Rust WSL Linux 离线全量测试通过，2 项真实依赖测试跳过。共同需求检查覆盖 36 份三端文件，总体 `accepted:0`、`ready:false`。

真实 Oracle 的唯一约束并发、初始化触发器、日期解析、资料视图及跨后端/跨机器登录尚未验证；注册和 OTP 尚无统一限流、密码强度和一次性消费策略。本轮未启动 Docker、真实应用、数据库或邮件服务。
