# 媒体类型选择共同样例

Nuxt 的实际类型选择逻辑已单独暴露，Go 和 Rust 实现同样的选择规则：优先采用内容探测器给出的 MIME/扩展，探测为空时按上传 MIME 和有限扩展表回退，再判断允许类型和媒体类别。14 个共同样例覆盖伪装扩展、拒绝不支持类型、大小写、参数、空类型、隐藏文件名及常见媒体类型。原 Nuxt 媒体和头像验证仍使用原有的真实文件探测流程。

共同样例中的探测结果是合成输入，并不证明 Go/Rust 已读取真实文件或实现 `file-type` 的全部格式识别。两端尚需真实二进制检测、图片与音视频元数据、上传路由及持久化接线；Go 当前安全 key 生成对扩展字符和长度更严格，仍需在统一兼容方案中处理。真实格式样本、Windows/Linux 和跨后端验收仍待补充。

本轮 Nuxt 全量 Node 回归和类型检查、Go 全量测试及 vet、Rust 共同样例测试通过；共同需求与 OpenAPI 副本检查通过。这些检查不代替真实文件格式和完整上传验收。
