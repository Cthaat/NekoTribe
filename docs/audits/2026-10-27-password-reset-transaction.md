# 密码重置事务检查点

Nuxt、Go、Rust 的密码重置改为先校验 OTP 哈希，再以同一数据库事务条件消费 OTP、更新唯一用户密码和撤销已存在的会话。消费时除了设置过期时间，还将 OTP 哈希改为不可验证的 `!consumed!`，并以原哈希作为条件，避免仅依赖不同语句的当前时间。密码更新零行、重复行和事务中的失败会回滚；提交或连接关闭失败可能使最终提交状态未知。

三端共享 17 条隔离 HTTP 场景，覆盖错误、事务副作用、失效竞争、长密码和响应隐私。Nuxt 用事务替身测试重放、失败与回滚；Go 使用模拟数据库驱动检查事务 SQL/绑定、失败回滚和模拟并发请求；Rust 对与生产共用的事务编排使用替身测试每步失败及提交失败，并测试 HTTP 场景。这些不代表 Oracle 驱动、真实锁行为或跨机器部署已验证。

事务只撤销执行时已存在的会话：旧密码登录在重置与会话创建之间并发、已发出的双因素挑战、受信设备以及已经建立的 WebSocket 连接仍需后续治理。验证码发送/尝试限流和密码强度也尚未完善。本轮没有运行 Docker、真实数据库或模型，不应将本记录视为完整安全验收。
