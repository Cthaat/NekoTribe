# 媒体上传与本地存储检查点

Nuxt 媒体上传现在使用请求独有的临时目录，上传完成或失败后清理该目录及未选中的文件。数据库插入、读取和响应映射后才尝试提交；提交已开始或回滚失败时保留对象，避免删除可能已被数据库引用的文件。提交前回滚确认成功才补偿删除本次新对象。客户端只收到固定公开错误，数据库及存储异常不会直接暴露路径或驱动详情。

Nuxt 本地存储检查实际目录链、拒绝目录链接及 Windows junction，限制文件 key，并使用排他复制防止覆盖已有对象。公开读取不返回暂存目录，范围读取通过文件句柄流式发送，416 带文件大小，响应包含 nosniff。目录链检查不承诺抵御有本机写权限者并发替换目录；真实部署需要进一步的句柄级隔离和权限验证。本地 provider 在复制成功、删除源文件失败时可能遗留待对账对象。

共同要求见 `specifications/requirements/media-upload.md`、`storage-local-files.md`，69 条路径和范围向量同步到四个工程。Rust/Go 已实现并测试纯路径和范围解析，**尚未接入实际文件 provider、HTTP 文件读取、上传或删除接口**。现有公开文件访问也不是私密帖附件的完整权限控制；S3 provider 仍是未实现占位。

组件提交：Rust `cd0a3f4`、Go `5065cb8`；Flutter 契约提交 `4499234`。

本轮隔离验证：Nuxt 媒体/存储 89 项通过，包括真实 multipart 解析、独立临时文件、回滚和提交不确定结果、Windows junction、文件范围及覆盖保护；全量 Node 回归 825 项通过、2 项跳过。Nuxt 类型检查通过。Rust 69 条共同向量及全量离线测试 235 项通过、2 项真实依赖测试忽略。Go 共同向量、全量测试及 vet 通过。共同需求与 OpenAPI 副本检查通过，`accepted:0`、`ready:false`。

OpenAPI 先前把媒体文件上限误写为 10 MB；本轮按现有代码修正为单文件及全部文件数据各不超过 500 MiB，并注明 `file`/`media` 字段、可空元数据及 501/503 结果。契约和需求检查器的 66 项回归通过；此次契约 revision 为 `2026-10-29-media-lifecycle`。

尚需完成三后端 MIME/文件内容识别、媒体元数据、原生上传/删除、真正的文件流式路由、私密内容访问授权、对象对账、真实 Oracle 与 Windows/Linux 跨机验收。本轮不启动 Docker，不访问日常数据库。
