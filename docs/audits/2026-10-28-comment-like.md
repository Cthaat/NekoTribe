# 三后端评论点赞开发检查点

Nuxt、Rust native 和 Go 实现共同的评论点赞与取消：需要有效会话和安全 ID，在检查、写入及计数读取时限制评论未删除、帖子未删除且当前用户可见。重复点赞或取消不产生额外写入，首次点赞按既有偏好向评论作者发通知；用户自赞不通知。共同规则及待执行场景见 `specifications/requirements/post-comment-like.md` 和 `specifications/scenarios/post-comment-{like,unlike}.json`；OpenAPI 和四工程副本已同步。

Nuxt 全量隔离回归 571 通过、2 跳过，类型检查通过；Go 全量测试和 vet 通过；Rust 全量离线回归通过，2 项真实连接测试忽略。新增隔离测试覆盖会话、ID、不可见或删除的评论、零行时权限变化、重复操作、通知类型/推送偏好和摘要元数据。源码使用已有通知存储和推送组件；模型化替身不能证明真实发送。

点赞写入与计数、通知分开提交，写入后失败可能已持久化；Redis 发布失败不回滚。真实 Oracle 约束、触发器、统计和并发、Redis 推送及双客户端互通仍待隔离验收；语句快照不能消除全部竞争。共同进度为 `in-progress`，不能视作共同验收完成。本轮未启动 Docker 或访问日常数据库。
