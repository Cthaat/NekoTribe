# 媒体删除并发边界检查点

Nuxt 删除媒体按用户和媒体 ID 读取并删除记录。原实现未检查删除行数：若读取后记录被并发删除，后来的请求仍会清理读取到的文件。现在只有数据库确认恰好删除一行时才执行存储清理；零行返回 404，异常行数或数据库错误不清理对象。删除语句使用自动提交，提交状态不确定时对象保留；确认提交后清理失败可能产生孤立对象，需后续对账。

隔离测试覆盖成功、无记录、并发零行、异常行数和数据库提交异常，验证失败时不发起对象清理。Nuxt 全量 Node 回归和类型检查通过，公共需求和 OpenAPI 副本检查通过。此改动不解决共享对象引用、记录读取与删除间被修改、外键行为或真实 Oracle 提交竞争，也不代表 Rust/Go 删除接口已实现。共同需求已明确这些后续验证要求。
