# 2026-10-28 项目需求与进度总览

当前处于原生后端逐块开发阶段：四个工程已经分开，统一需求和检查入口已经建立，Rust/Go 已有认证、用户资料、内容读取与互动、通知等原生实现；完整业务互换、新 AI 产品和最终部署仍未完成。

本次核对以当前源码、共同需求及只读检查为依据。现有隔离测试、历史运行记录和最终验收分别列示；本轮不启动 Docker，不用代理成功或模拟数据库结果替代真实验收。

## AI 的完整范围

| 产品方向 | 使用者 | 首期能力 |
| --- | --- | --- |
| 知识问答与写作 | 登录用户 | 检索并引用资料、回答问题、起草或润色帖子和总结讨论，用户审阅后发布 |
| 群运营 Agent | 目标群管理员 | 结合检索和公开统计生成周报、FAQ、公告草稿；发布、删帖、成员处置须有权人员明确确认并走正常业务接口 |
| 审核辅助 | 平台审核人员 | 依据规则和来源给出风险说明与处置建议，由人工判断，不以一次模型输出自动封禁 |

首期知识来源限于公开帖子、评论和平台规则；私信、私密群不默认入库，管理员身份也不扩大这一范围。内容删改或变为不可见后，索引和引用需要及时失效。

共同能力还包括可切换模型、知识库检索、可恢复/删除的持久化对话、长上下文管理、可版本管理与启停的 Skills、有限步骤的受控工具调用、取消/超时/限额及审计。每次请求固定模型与配置版本；对话模型和向量模型分别配置，向量模型或分块规则改变时验证新索引后再切换。

当前三端只有模型配置、OpenAI-compatible/Ollama 非流式 HTTP 传输，以及工具提议/结果的历史编码组件。**传输工具历史不等于执行工具，也不等于已经具备 Agent。** 尚未选定 Agent 编排框架或向量索引方案；知识库、持久化上下文、Skills、产品接口和页面仍待实现，真实模型切换未验收。范围与证据见 [产品需求](../../specifications/requirements/ai-product-scope.md)、[模型切换](../../specifications/requirements/ai-model-switching.md)、[Agent 需求](../../specifications/requirements/ai-agent-runtime.md) 和 [工具历史检查点](2026-10-28-ai-tool-history.md)。

旧设置面板已取消挂载，但服务端代理、规范中的 13 个旧情感分析操作及原工程/模型文件仍存在；完整退役尚未完成。

## 证据和验收边界

本次实际运行的只读检查均正常退出：

- `node scripts/parity.mjs check --workspace-root ..`：155 个工作项、162 个规范操作、50 份场景文件和 97 份公共文件；131 个源码入口仍待审查，未有完整三后端业务验收，`ready:false`。
- `node scripts/contracts.mjs check --workspace-root ..`：四份规范一致，149 个明确路由、12 个有限上游代理操作；未发现 schema 缺口。

工作项、HTTP 操作和场景文件是不同口径；162 个规范操作还包含 WebSocket 和旧集成。检查成功说明登记和副本一致，不能证明业务全部实现。各模块已有隔离测试应继续作为开发证据，最终还需真实 Oracle/Redis、客户端与跨后端场景。

[2026-10-26 运行记录](2026-10-26-runtime-verification.md) 保留了 Nuxt、Rust compat、Flutter Web、Oracle Free、恢复套件及部分 Windows/Linux 构建运行证据。当时 Rust 业务依赖 Nuxt，Go 尚未提供当前原生服务；这些结果不能转写为当前原生后端通过。Oracle Free 不替代原 Oracle 19c，本机 Linux 容器或 WSL 不替代另一台服务器。Flutter Windows 桌面 C++ 工具链仍按用户选择暂缓，当前以 Web 为主要验证入口。

## 接下来按什么顺序推进

1. 基于 Nuxt 上传和共享路径/范围规则，完成 Rust/Go 的 multipart 上传，补齐共享对象安全、私密附件授权及 MIME/元数据共同场景；强化文件操作并完成跨平台验证。
2. 补齐媒体文件能力，再补用户设置、关系等缺口；每个业务切片同步更新三端任务与共同场景。
3. 补齐群组、聊天/私信、在线状态和审核管理，完成跨实例事件与缓存规则；继续逐项归类旧接口及其他源码入口。
4. 在已明确的数据权限上实现 AI 知识库、持久化对话、Skills 与受控工具，接入三个产品方向和两客户端，保留独立 Python 服务并完成旧情感分析接口兼容迁移。
5. 完成共同场景执行与发布检查；按后续集中测试安排验证真实依赖、阻断 Nuxt 的原生独立性、两客户端与三后端组合及 Windows/Linux 多种部署。所有必要场景通过前，保持项目进行中。
