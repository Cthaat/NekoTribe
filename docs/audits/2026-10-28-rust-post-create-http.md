# Rust 原生发帖与转发接入检查点

Rust native 的 `POST /api/v2/posts` 和 `POST /api/v2/posts/{id}/retweets` 已接入原生请求解析、引用可见性、帖子及媒体/标签/提及事务、提交后通知和完整帖子响应。请求不依赖 Nuxt 业务进程；compat 模式仍按原配置保留代理。最终响应复用帖子映射但不增加浏览量。

Rust 实现提交为 `1b6e402`。公共请求说明同步记录 Rust/Go 的正文限制和错误响应差异，Rust、Go、Flutter 三份契约副本保持一致。

## 请求与写入

请求先验证 access token 和 Oracle 会话，再检查路径及正文。解析保留 Nuxt 的空白、属性存在优先、JavaScript 数值转换、引用安全整数和错误顺序；转发只读取 content/visibility，其他字段不产生关系。合法 JSON 数值溢出、URL 编码正文和路径单次严格解码另有边界测试。80 条公共请求向量同时由独立解析器和实际 Axum 路由消费；不读取兄弟工程源码。

`OracleSessions -> SessionExecutor -> OraclePool.run_blocking` 将整个创建委托到同一 Oracle 连接。引用预检先于分配序列，插入时再次校验引用权限；所有 DML 通过同一个 OracleTx，不使用逐操作自动提交。媒体、标签和提及分别按公共规则去重、限制数量，并保留原始浮点 ID 绑定，避免截断成其他用户。写入失败回滚；回滚失败返回内部错误。提交错误可能已实际提交，不能宣称一定撤销或自动重试。

## 提交后的行为

回复、转发、引用和提及通知复用通知偏好、存储、映射和 Redis 发布。元数据、类型和事件匹配公共规则；摘录保留 UTF-16 截断边界。提及通知遍历全部去重输入，不受关系写入 50 项限制；小数收件人精确查询，自我及非正 ID 仍按既定顺序获取摘录后跳过。

通知数据库、最终帖子映射或连接关闭错误可能发生在帖子已经提交之后，部分通知也可能已存在。Redis 发布失败按现有规则降级。源码复核覆盖认证先后、参数绑定、事务委托、提交后错误和浏览计数隔离，未引入新依赖。

## 验证与后续

本轮 WSL `cargo test --offline` 全量通过 228 项，2 项真实 Oracle/Redis 连通测试按既有设置忽略。新增定向运行覆盖库单元 26、通知仓储 5、请求 5、路由 3、事务仓储 13，共 52 项，其中包含公共 80 条请求向量。全量日志位于管理目录 `.codex-logs/2026-10-28-rust-post-create-full.log`，格式整理后的复核日志为 `.codex-logs/2026-10-28-rust-post-create-final.log`。共同需求及 OpenAPI 副本检查通过；功能继续登记 `in-progress`，没有提升为 `accepted`。

共同需求检查器的 40 项回归也通过；格式检查仅针对本轮新增文件及小范围修改文件，没有重新格式化大型认证仓储。源码、规范和日志分别作为开发证据，未替代真实业务验收。

这些检查没有访问真实 Oracle 或 Redis，不证明驱动数值绑定、约束、触发器、并发、断连时实际提交结果、双客户端或跨后端流程可用。本轮不启动 Docker。非法 JSON 响应、Content-Type、1 MiB 正文限制及 HTTP 层 URL 拒绝仍与 Nuxt 存在记录中的差异，需要共同规则收敛和最终真实环境验收。下一组内容业务继续补齐更新、删除和媒体能力。
