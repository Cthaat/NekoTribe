# Go 原生发帖与转发接入检查点

Go 的 `POST /api/v2/posts` 和 `POST /api/v2/posts/{id}/retweets` 已从路由接入原生实现：认证、请求解析、引用可见性、帖子及媒体/标签/提及事务、提交后通知及完整帖子响应均由 Go 代码处理，不回退 Nuxt。回复、引用与转发共用写入路径；转发入口只读取内容和可见性，路径决定原帖。最终响应读取不递增浏览量。

新增请求需求和 80 条向量，以当前真实 Nuxt 路由/解析逻辑核对，再由 Go handler 消费同一副本。覆盖字符串空白、数值转换、别名存在优先、可选安全引用、错误顺序和转发字段隔离。Go 关系数组改用浮点数原值绑定；提及收件人精确查询，不允许把小数截断成另一个用户。额外回归验证合法 JSON 数值溢出：字符串转换和有限数数组过滤与 Nuxt 一致。

通知在事务提交后运行：回复、转发、引用、提及的类型和元数据分别匹配 Nuxt；提及按全部去重输入发送，不受关系写入 50 项限制。自我或非正 ID 提及仍先获取摘录，再跳过收件人查询。通知数据库、映射或最终读取失败可能发生在帖子已提交之后，部分通知可能已成功；Redis 发布失败降级，不自动重试创建。

验证：Go 全量 `go test ./...`、`go vet ./...` 通过；Nuxt 全量 Node 测试通过，新请求测试执行真实解析及预写入校验，使用观察点与隔离数据库适配器。共同规范和副本检查通过。本轮不启动 Docker，不访问日常数据库。

这不证明真实 Oracle 数值绑定、约束、触发器、并发、提交失败实际结果、Redis 或两个客户端可用。非法 JSON 响应、Content-Type、请求体上限和传输层 URL 拒绝等差异仍需共同规则收敛。Rust 对应创建流程尚未原生实现；两个功能继续登记 `in-progress`，不提升为 `accepted`。后续按共同请求、事务与通知规则补齐 Rust，并集中做隔离环境验收。
