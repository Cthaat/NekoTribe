# 帖子评论列表开发检查点

Nuxt `GET /api/v2/posts/{id}/comments` 原先只按帖子 ID 查询评论，没有校验帖子对当前用户是否可见。现先验证有效会话与帖子可见性，不存在、已删除或无权查看统一返回 404；评论计数和列表 SQL 也分别执行 `fn_can_view_post`。路由使用规范安全正整数 ID、私有缓存头及内部错误脱敏；这些是对原有行为的安全收紧。

Rust native 和 Go 新增相同接口，处理分页、排序、作者公开资料、回复关系、点赞状态和当前作者删除权限。每个实现对前置检查、计数和列表独立限定用户，避免仅依赖前置权限判断。查询之间不是一个事务快照，权限并发变化时计数与列表可能不一致。共同需求、待运行的完整验收场景和四份 OpenAPI 副本已同步；Flutter 增加分页与评论结构解析专项测试。

验证：Nuxt 全量隔离测试 568 通过、2 跳过，类型检查通过；Go 全量 test/vet 与后续作者权限专项通过；Rust 离线全量测试通过（新增作者权限测试以前），真实依赖测试仍忽略，随后评论专项 3 项通过；Flutter 接口契约测试及新增评论专项通过。Rust 新增评论实现和测试文件经 Windows rustfmt 检查。共同规范登记 76 份共享文件，整体仍为 `accepted:0`、`ready:false`。

测试使用隔离会话、数据库替身和模拟作者资料，不证明实际 Oracle 可见性函数、时区、CLOB、排序并列、权限竞争及两个客户端的真实联调；这些留待最后的隔离环境验收。本轮未启动 Docker 或访问日常数据库。
