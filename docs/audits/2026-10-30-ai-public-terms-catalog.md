# 公开条款资料目录检查点

现有公开条款页面 `app/pages/auth/terms.vue` 的默认中文及英文内容分别来自 `i18n/locales/zh.json` 与 `en.json`。目录只提取页面现有的接受条款、账户责任、用户行为、终止服务四节，包括行为警告和三条禁止行为；保留原文、语言及页面锚点，不创造或修改平台规则。

`node scripts/ai-public-terms-catalog.mjs --write` 从页面本地化文本生成 Nuxt 权威目录及 Rust/Go 契约副本；`--check` 和共同需求检查拒绝文本、副本或已检查的页面结构漂移。目录包含八个语言章节，属于静态源码构建资料，尚未接入检索、来源版本、会话引用或授权复核，不代表规则内容已经运营审核或 AI 可以回答平台规则问题。发布/撤回、动态更新、共享数据库/跨版本一致性及真实部署切换均需后续设计并验证；源码中现有条款不应因被收录而被推断为已获运营确认。

本次本地测试验证中英原文、告警列表、缺失/空文本拒绝、页面锚点漂移及三份目录一致；未运行 Docker、真实模型或数据库。

后续增量：Nuxt 新增独立条款来源组件，依据共同规范提供固定 ID、精确匹配和带版本的复核；独立生成的 8 条指纹和 3 条检索向量已在 Nuxt 组件测试。它尚未连接用户请求或来源恢复路径，Go/Rust 尚未实现组件；真实规则发布与跨实例同步仍未建立。

后续增量：Go 和 Rust 已实现相同的独立条款组件，并通过共同指纹和检索向量，以及内容变更后的旧引用失效等隔离测试。三端仍未把条款连入 AI 问答、引用恢复或部署版本同步；这些测试不能替代生产验收。

后续增量：共同 API 预留条款引用 `{kind:'terms',id,version}`；Web 使用固定的站内章节路径，Flutter 识别并显示条款编号，不把条款当作帖子。现阶段后端还不生成该引用，Flutter 也尚未配置可可靠跳转的 Web 站点地址。组件测试和 Flutter 客户端测试通过不等同真实后端或跨客户端验收。
