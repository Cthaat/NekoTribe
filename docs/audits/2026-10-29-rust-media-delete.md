# Rust 原生媒体删除检查点

Rust native 接入 `DELETE /api/v2/media/{id}`，按当前用户与媒体 ID 查询和删除；只有数据库执行器确认成功提交一行后才处理受管理文件。未找到或并发零行返回 404，异常行数与数据库失败不触碰文件；外部 URL 不当成本地文件删除，临时目录、路径穿越和静态链接拒绝，S3 不回退本地。生产路由使用显式存储配置，compat 模式仍沿用原有代理。

隔离测试覆盖数据库所有权绑定、零行竞争、异常行数及提交错误、身份、数值 ID 和真实临时文件；另测同源/外部地址、临时路径、穿越、符号链接和 S3。真实 Oracle 外键、共享对象引用与跨后端并发未验证；记录删除提交后清理失败可能产生孤立对象。Rust 静态链接检查和删除之间仍存在本机并发替换风险，未使用根目录约束句柄；真实 Windows 与跨机部署仍待验收。

WSL Linux 的 Rust 全量离线回归通过；依赖真实环境的既有测试仍按原设置忽略。共同需求检查仍为 `ready:false`，不能把此结果当成完整业务验收。
