# Go 通知 WebSocket 开发检查点

Go 原生 `/_ws` 已实现通知用户频道订阅、身份验证、来源校验、连接提示与 ping/pong。连接和事件投递前验证 JWT 与当前数据库会话；订阅失败返回不可用，不伪装成可接收通知的连接。通过共享 Redis 的用户频道接收已登记通知事件，限制消息大小和队列；断开或服务关闭时释放订阅。Redis URL、主机、端口、数据库与密码由显式环境配置，浏览器跨域来源须允许。

隔离测试使用真实回环 WebSocket 和本地模拟 Redis 协议服务，覆盖登录凭证、非法来源、同源 Cookie、用户频道、心跳、撤销后拒绝投递、订阅关闭和配置错误脱敏；Go 全量 test/vet 与 Linux amd64 静态构建通过。该检查点时 Rust 尚未实现通知连接，后续进度见下文；Go 的群聊、私信和在线状态也未实现。Nuxt 现有连接建立后尚需对齐事件投递前的会话复核。真实 Oracle/Redis 7、TLS、ACL、反向代理、多机器和两客户端仍待隔离验收；未启动 Docker 或访问日常数据。

实现使用 [coder/websocket](https://pkg.go.dev/github.com/coder/websocket)；通知连接的部分实现不能视作完整 `/_ws` 协议验收。

## Rust 原生连接补充

Rust native 新增通知用户频道订阅、来源和会话校验、连接提示及 ping/pong。投递前及定期复核 token 和会话；配置读取共享 Redis 地址、认证信息和可选 TLS。孤立回环 WebSocket 测试覆盖双用户隔离、心跳、非法来源、凭证优先级、同源 Cookie、订阅失败、撤销和过期；模拟 Redis 协议测试覆盖用户频道、事件接收和释放连接。帧与队列有大小限制，订阅失败不建立可接收通知的连接。

这些检查不代替真实 Redis、TLS、ACL、Oracle、代理、多机及客户端联调。Rust 和 Go 均尚未接入群聊、私信、在线状态及完整实时协议；通知发布组件也还没有接入所有原生业务。Nuxt 现有连接投递前的会话复核仍待对齐。

验证：Rust WSL 离线全量回归 161 通过、2 个真实依赖测试忽略，涉及文件格式检查通过；Nuxt 共同登记和通知事件专项 41 项通过，共同工作区检查仍为 `accepted: 0`、`ready: false`。本轮未启动 Docker 或访问日常数据库。
