# Go 通知 WebSocket 开发检查点

Go 原生 `/_ws` 已实现通知用户频道订阅、身份验证、来源校验、连接提示与 ping/pong。连接和事件投递前验证 JWT 与当前数据库会话；订阅失败返回不可用，不伪装成可接收通知的连接。通过共享 Redis 的用户频道接收已登记通知事件，限制消息大小和队列；断开或服务关闭时释放订阅。Redis URL、主机、端口、数据库与密码由显式环境配置，浏览器跨域来源须允许。

隔离测试使用真实回环 WebSocket 和本地模拟 Redis 协议服务，覆盖登录凭证、非法来源、同源 Cookie、用户频道、心跳、撤销后拒绝投递、订阅关闭和配置错误脱敏；Go 全量 test/vet 与 Linux amd64 静态构建通过。该检查点时 Rust 尚未实现通知连接，Nuxt 尚未对齐事件投递前会话复核，后续进度见下文；Go 的群聊、私信和在线状态也未实现。真实 Oracle/Redis 7、TLS、ACL、反向代理、多机器和两客户端仍待隔离验收；未启动 Docker 或访问日常数据。

实现使用 [coder/websocket](https://pkg.go.dev/github.com/coder/websocket)；通知连接的部分实现不能视作完整 `/_ws` 协议验收。

## Rust 原生连接补充

Rust native 新增通知用户频道订阅、来源和会话校验、连接提示及 ping/pong。投递前及定期复核 token 和会话；配置读取共享 Redis 地址、认证信息和可选 TLS。孤立回环 WebSocket 测试覆盖双用户隔离、心跳、非法来源、凭证优先级、同源 Cookie、订阅失败、撤销和过期；模拟 Redis 协议测试覆盖用户频道、事件接收和释放连接。帧与队列有大小限制，订阅失败不建立可接收通知的连接。

这些检查不代替真实 Redis、TLS、ACL、Oracle、代理、多机及客户端联调。Rust 和 Go 均尚未接入群聊、私信、在线状态及完整实时协议；通知发布组件也还没有接入所有原生业务。该检查点时 Nuxt 的通知投递前会话复核仍待对齐，后续进度见下文。

验证：Rust WSL 离线全量回归 161 通过、2 个真实依赖测试忽略，涉及文件格式检查通过；Nuxt 共同登记和通知事件专项 41 项通过，共同工作区检查仍为 `accepted: 0`、`ready: false`。本轮未启动 Docker 或访问日常数据库。

## Nuxt 通知投递前会话复核

本机通知发布和 Redis 用户频道的通知转发均按连接重新验证原始 access token 和数据库会话，再发送到目标用户；检查不使用 Oracle 查询缓存。撤销、过期、错误或 1.5 秒检查超时会停止投递并关闭该连接。单连接最多排队 16 条通知，超限关闭，避免慢连接无限积压。检查期间断开的会话不会收到随后完成的投递；数据检查与发送不是同一数据库事务，不承诺消除两者之间的撤销竞争窗口。超时不会取消已经开始的 Oracle 操作，连接会在该操作最终返回时关闭。

隔离测试执行实际通知服务、WebSocket 会话管理和路由回调，覆盖本机与 Redis 两条路径、用户隔离、撤销、检查错误、断连、积压和检查超时。真实 Oracle、Redis、网络和客户端仍待验证。当前改动仅保护通知投递；群聊、私信、广播、定期会话检查、来源校验、订阅失败与资源释放仍须继续对齐，不能标记完整 WebSocket 验收。

验证：Nuxt 全量测试 548 通过、2 项跳过，类型检查通过；共同规范检查仍为 `accepted: 0`、`ready: false`。本轮未启动 Docker 或访问日常数据库。
