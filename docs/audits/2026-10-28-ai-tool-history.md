# 2026-10-28 模型工具调用历史检查点

三套后端的内部非流式推理传输支持把模型的工具提议及对应工具结果作为历史发送给 Ollama 和 OpenAI 兼容服务。共同输入、合法顺序和错误行为见 `specifications/requirements/ai-tool-history.md`；Nuxt、Rust、Go 各自读取同一组 24 条合成场景。每批工具结果必须按调用顺序完整返回，不允许缺失、重复或错序；后续批次可重新使用已完成批次的调用 ID。

合成服务的双适配器往返测试覆盖模型提出工具调用、把合成结果加入历史并请求下一次响应。模型 capability 不包含 tools 时，不发送工具历史。历史名称不受当前工具列表限制，以便恢复历史，但不赋予执行权限。

这是传输组件，**没有执行工具，也没有实现知识检索、持久化上下文、Skills、Agent 权限或用户入口**。合成 HTTP 与隔离测试不证明真实模型多轮兼容，也不证明更换模型后所有历史都被新模型接受。后续必须接入受控工具、授权和审计，并用真实服务验证模型切换、上下文恢复与拒绝行为。旧情感分析代码及数据仍保留，退役需要单独完成兼容迁移。

不启动 Docker、真实应用、数据库或模型；真实 Oracle、Redis、跨机器和最终业务验收另行进行。共同登记仍为 `accepted: 0`、`ready: false`。

验证：Nuxt 工具传输专项 87 项通过；Nuxt 全套 499 通过、2 跳过，类型检查通过。Go 全套 `go test ./...` 与 `go vet ./...` 通过。Rust WSL 离线全套通过，2 项真实 Oracle/Redis 连接测试跳过；Rust 格式检查通过。工具历史场景生成器校验通过；工作区共同规范检查覆盖 42 份文件，OpenAPI 检查为 162 个操作。上述结果不代替真实系统验收。
