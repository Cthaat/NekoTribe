# 发帖引用权限检查点

Nuxt 创建回复、引用或转发时原本直接保存目标 ID，没有检查原帖对当前用户是否可见。现要求安全整数 ID、单一引用类型，写入前检查原帖未删除且可见，插入 SQL 再次限定同一作者与原帖。不可见或不存在返回 404；转发路径使用相同的安全 ID 规则。普通独立发帖无需目标帖权限查询。相关局部需求、两条待执行共同场景及 OpenAPI 已同步各工程。

隔离测试覆盖隐藏/删除/不存在、无效及多个引用、插入时权限变化、合法回复和转发通知、普通发帖；Nuxt 全量回归 572 通过、2 跳过，类型检查通过，随后增加的普通发帖和合法转发专项通过。数据库替身不证明 Oracle 的语句快照、触发器、真实并发及客户端互通。

这是完整发帖实现的一个安全切片。当前发帖、附件和通知分别自动提交；无可用媒体仍可能形成空帖子，完整输入、事务及失败恢复有待后续修复。Rust 和 Go 尚未实现发帖，规范条目保持未完整审查与未验收；不得将本地测试当作三后端完成。本轮未启动 Docker 或使用日常数据库。

后续已调整帖子及关联写入的事务边界和媒体校验，最新状态见 [发帖事务检查点](2026-10-28-post-create-transaction.md)；上述描述保留为当时检查结果。
