# 2026-10-28 帖子详情原生开发检查点

Nuxt 对帖子 ID 使用无前导零的安全正整数规则，对详情关闭响应缓存，并在安全错误边界保留帖子不存在的 404。Rust native 与 Go 已接线帖子详情：按当前查看者和数据库可见性函数查主记录，再加载作者、媒体、标签和提及，全部成功后才增加浏览量。作者或关联读取失败时不增加浏览量。Rust 和 Go 各自读取 `POST-DETAIL-VECTORS` 的 22 个合成场景；Nuxt 独立测试覆盖匿名可见性、错误 ID、不缓存及缺失媒体结构，但尚未运行所有共同样例。

OpenAPI 更新匿名/Cookie/Bearer 安全配置、参数约束、媒体空值和提及用户结构；记录 Nuxt 与原生后端目前不同的 503 HTTP 错误传输包装。Rust/Go 还分别用仓储替身检查 SQL 参数、匿名 NULL 和结果映射，不能证明真实 Oracle 驱动和函数行为。

Nuxt 全量隔离测试 524 通过、2 跳过，类型检查通过；Go 全量 `test` 和 `vet` 通过；Rust WSL 离线全量测试通过、2 个真实依赖测试忽略，改动文件使用 Windows rustfmt 检查通过。共同检查覆盖 53 份规范副本并报告 `accepted: 0`、`ready: false`。未运行 Docker、真实应用、Oracle、Redis 或模型，未修改日常数据。真实可见性函数、媒体 schema、并发计数、数据库时间与驱动、跨后端和双前端均需最终隔离联测。尤其各步骤通过独立查询执行，并不承诺一致性快照或失败后计数必然回滚。
