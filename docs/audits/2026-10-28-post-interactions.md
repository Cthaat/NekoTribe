# 帖子点赞与收藏开发检查点

Nuxt 四条点赞和收藏写接口增加规范 ID 校验以及目标可见性检查；写语句也使用 `fn_can_view_post`，零行时再次检查，避免把权限变化误判为重复操作。原点赞通知流程保持；数据库函数也会拒绝删除帖。旧行为允许知道 ID 的用户对不可见帖子写入，此次收紧。Nuxt 请求仍是独立自动提交，后续通知失败不能回滚已经提交的点赞。

Rust native 与 Go 新增原生收藏/取消收藏，使用本端认证会话 ID，绑定用户与帖子 ID、检查可见性、条件写入和零行重新检查；重复收藏/取消返回目标状态。三端共同需求及 12 个待执行验收场景已登记。原生点赞、通知存储及 Redis/WebSocket 推送尚未实现，不能把收藏进度称作完整互动能力。

后续补充：Rust/Go 已新增取消点赞，沿用认证和可见性边界；无论是否已有点赞，均返回数据库中当前计数。首次点赞仍未开放，待通知存储和实时投递的实现完成后一起接入。专项隔离测试覆盖无权、无效 ID、重复取消、权限变化及仓储绑定；变更后 Go 全量 test/vet 和 Rust 离线全量回归通过，Rust 两项真实依赖测试仍忽略。共同需求明确了通知偏好、元数据和跨实例推送格式。

通知存储基础：Rust/Go 将原登录提醒中的接收者偏好检查和插入抽为可复用的仓储函数，登录提醒继续通过此路径写入。隔离测试覆盖本人、缺失/停用接收者、类型偏好关闭、全局推送关闭但仍存储、写入失败和绑定用户/资源等情形；Rust 额外拒绝超出数据库整数范围的 ID。返回的通知 ID 与推送偏好供后续投递使用；当前没有新增实时推送，也没有接入点赞通知或声称真实 Oracle 已验证。

Nuxt 点赞/收藏专项及帖子兼容回归 20 项通过，类型检查通过；Node 根目录测试 533 通过、2 跳过；更新共同登记后再运行共同登记和帖子专项 60 项通过。Go 全量 `test ./...`、`vet ./...` 通过；Rust 离线全量 145 通过、2 项真实依赖测试忽略，格式检查通过。共同登记检查覆盖 61 份共享文件，`accepted:0`、`ready:false`。

隔离替身不证明真实 Oracle SQL、触发器、权限函数、并发唯一约束、事务快照或失败后的提交状态；真实数据库与跨后端、客户端联调、通知及竞争条件仍待验收。本轮未启动 Docker 或修改日常业务数据。

## 首次点赞通知的读取和发布基础

Rust 和 Go 增加按接收者与通知 ID 的只读仓储查询，复用通知列表的数据字段和 JSON metadata 映射；作者公开资料与头像归一化也抽成列表和后续推送可共用的逻辑。不存在通知返回空结果，数据库错误不向客户端暴露。Go 发布器接入应用生命周期，复用订阅端的 Redis 地址、数据库、凭据和 TLS 配置，但不会在启动时连接 Redis。

这些是首次点赞通知的前置组件，尚未实现原生首次点赞路由、点赞通知创建后关联读取和事件发布；Rust 发布器的生产接线也仍待完成。隔离仓储替身不证明真实 Oracle 查询、日期与 CLOB、Redis TLS 或跨进程投递。

验证：Go 全量 `test ./...`、`vet ./...` 通过；Rust WSL 离线全量测试 162 通过、2 个真实依赖测试忽略。本轮未启动 Docker 或访问日常数据。

## Go 原生首次点赞

Go 增加首次点赞写入，复用会话身份和帖子可见性检查；重复点赞和零行时重新检查可见性。新点赞读取计数、作者、点赞者名称和帖子摘录，按通知偏好存储后重新映射完整通知和接收者视角的 actor；允许推送时通过配置化 Redis 发布器发送 `notification_created`。点赞、通知存储和推送分别进行，通知存储/映射出错可在点赞已提交后返回 500；Redis 发布失败降级，不能保证到达。重复点赞不会重新创建通知。

隔离 HTTP、数据库驱动和发布替身覆盖首次与重复点赞、不可见、偏好、本人、缺失作者、通知失败、Redis 失败及 UTF-16 摘录边界。通知 JSON 保留有效元数据中的未配对 UTF-16 转义，避免读出后发布时变成替换字符。Go 全量测试和 vet 通过，Linux amd64 无 CGO 交叉构建通过；本机与替身不证明真实 Oracle SQL、触发器、唯一约束竞争、CLOB、Redis 7/TLS、跨实例或双客户端互通。Rust 首次点赞及共同真实验收仍未完成；本轮未启动 Docker 或访问日常数据。

## Rust 原生首次点赞

Rust native 增加首次点赞、重复检查、通知存储、完整数据/actor 映射与 Redis 事件发布；Redis 发布器惰性使用同一配置，每次发布建立连接，失败只记录安全降级日志。点赞与通知存储各自提交，后续通知失败不能回滚已提交点赞；重复点赞不会重发。隔离路由、仓储、模拟 Redis 协议与 WebSocket 测试覆盖权限、偏好、失败、重复与事件格式；连接复用与高并发性能仍待评估。

为保持 Nuxt 截断后的未配对 UTF-16 转义，Rust 对有效但无法转为 Unicode 字符串的 metadata 保留原始 JSON；通知列表、发布和 WebSocket 转发均覆盖该边界，内部标识不会输出。数据库实际 CLOB、Oracle 触发器与并发、Redis ACL/TLS、跨实例和两个客户端仍需真实隔离验收；不可用 Redis 时不保证实时送达。

验证：Rust WSL 离线全量测试 173 通过、2 个真实依赖测试忽略，格式检查通过；共同需求检查和 40 项登记测试通过，`accepted: 0`、`ready: false`。本轮未启动 Docker 或访问日常数据。
