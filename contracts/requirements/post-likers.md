# 帖子点赞用户列表

`GET /api/v2/posts/{id}/likes` 是三套后端原生实现的只读接口。需要有效会话。帖子 ID 必须是无前导零的正十进制安全整数，无效 ID 返回 `40001`。不存在、已删除或按正常读帖规则不可见的帖子统一返回 `40401`，不会透露是否有人点赞。

- 只返回可用公开资料的启用账号；请求人与点赞人之间任意方向存在拉黑时，名单和总数均排除该账号。本人可以出现在列表中。使用现有公开资料响应和头像规则，不返回实时在线状态或最近在线时间。
- 单条 Oracle 查询读取目标可见性、符合条件的总数和本页资料。点赞时间降序，同一时间以点赞记录 ID 降序。沿用 V2 分页与响应格式，越界页为空且保留符合条件的总数。有效且没有可见点赞人的帖子返回 200 与空名单。
- 响应使用 `Cache-Control: private, no-store`；Nuxt 同时绕过 HTTP 响应缓存和 Oracle 查询缓存，避免其他后端写入或拉黑以后仍返回旧名单。
- Nuxt Web 与 Flutter 均在帖子详情向登录用户提供点赞名单入口。按服务端返回分页，显示公开昵称与用户名，并链接公开资料。名单不以帖子卡片点赞总数推断可见用户。
- 关闭名单、切换账号或 Flutter 切换后端时取消在途请求并清除旧名单。已有点赞与取消点赞的操作沿用原入口。

共享 SQL 与隔离测试覆盖授权、关联过滤、计数、并列排序和越界页。真实 Oracle 权限快照、并发更新和六种客户端/后端部署组合待验收。
