# 当前用户头像上传

`PUT /api/v2/users/me/avatar` 先验证会话，再解析 multipart/form-data。优先取 `file` 的第一个文件，再取 `avatar` 的第一个文件。以分段的 `filename` 参数识别文件，分段可省略 `Content-Type`。没有文件名参数的分段按文本字段计入限额。总文件内容上限 10 MiB。接受 JPEG、PNG 和 GIF 的文件签名，实际媒体类型与扩展名由签名决定。对象地址由账号 ID、UTC 年月和 UUID 生成。原名只作为元数据，超出 255 字节或含路径、控制字符时使用安全的默认名称。

新对象写入成功后，在同一 Oracle 事务锁定启用用户行、插入 ready 媒体记录并更新头像指针，成功返回 `avatar_url` 和 `avatar_media_id`。并发替换按行锁串行化。历史媒体记录和对象保留，避免破坏其他资源对旧头像的引用。后续回收须核对全部引用。

提交前失败且确认回滚时，补偿清理本次创建的对象。提交结果未知或回滚失败时保留对象供对账。验证会话和 multipart 类型后，若选用的 S3 配置缺失或无效，V2 返回 503／50301「媒体存储暂不可用」，不读取文件、不创建暂存、不写头像数据，也不回退本地存储。解析、大小和格式问题返回固定 400，后续存储及数据库故障沿用安全 500。响应使用 private, no-store。真实 Oracle、S3 及客户端部署组合需独立验收。

Nuxt 启用 V1 兼容接口时，`POST /api/v1/users/me/avatar` 复用同一事务、文件签名校验和清理机制。兼容入口优先读取 `avatar`，缺少时读取 `file`，成功继续返回旧版 `data.url`。历史头像媒体和文件保留，底层存储或数据库错误返回固定的 500。
