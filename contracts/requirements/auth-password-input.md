# 新密码输入的共同规则

适用注册、公开密码重置及安全页的密码重置。以已有 Nuxt 三份表单的最少6位规则为来源：先按 JavaScript `String.trim` 规范化，再按 UTF-16 代码单元计数，至少6位。确认密码先执行相同规范化，再与新密码相等比较。内部空白保留；没有新增大小写/字符组合要求或最大长度。前端只提交规范化后的捕获快照。

JavaScript trim 去除 U+0009–000D、U+0020、U+00A0、U+1680、U+2000–200A、U+2028/U+2029、U+202F、U+205F、U+3000、U+FEFF；保留 U+0085 和 U+200B。不能用语言默认 Unicode trim 替代这个集合。6个UTF-16代码单元并非6个字形或6个Unicode码点，例如3个补充平面emoji达到这个既有门槛。

三后端沿用 v2 标量读取规则，字符串/有限数字/布尔值先转换再 trim，缺值/非标量/空值沿用原字段错误；因此数字123456可通过，布尔值转换后的true/false达不到6位。注册在全部必填字段、条款及确认相等检查之后校验长度；重置在必填字段解析后校验长度。非空但不足6位时固定返回400/40001 `密码至少需要6个字符`，必须在读取或消费OTP、生成新密码哈希及写库之前拒绝。

这是新密码API的有意收紧：以前后端只要求非空，现在落实既有Nuxt UI规则。**已有短密码不迁移、不强制修改；登录继续允许trim后任意非空密码**，客户端不能把新密码门槛套用到登录。既有bcrypt按UTF-8前72字节截断的跨语言规则保持不变。

`scenarios/auth-password-input.json` 的19个字符串样例由Nuxt实际SFC schema、Flutter工具与页面、三后端实际HTTP路由消费；另有8个API标量/非标量样例用于三后端注册与重置，合计27项API输入。旧短密码另有三后端真实路由装配的隔离登录回归。共同向量不证明极大指数、无效Unicode代理项等所有输入完全一致。

OpenAPI的结构schema保留既有标量兼容；`x-normalization: js-trim` 和 `x-canonical-min-utf16-code-units: 6` 描述规范化后的业务约束。不能用原始字符串`minLength: 6`替代，因为trim顺序与UTF-16计数和JSON Schema码点计数不同；结构schema通过并不表示业务密码有效。

注册邮箱/名字和新邮箱的后续共同规则见 `auth-account-input.md`。资料编辑等其他输入、限流、OTP尝试上限、完整会话撤销、真实数据库/浏览器/设备及六组合验收仍需完成，不据本切片声称认证完整验收。
