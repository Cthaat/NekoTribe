# 私信历史

`GET /api/v2/chat/direct-conversations/{conversation_id}/messages` 以当前已验证的 access token 和活跃会话确定用户。会话 ID 为正十进制安全整数，格式错误返回 40001。缺少或失效的凭据返回 40101。已删除、不存在或当前用户未参与的会话统一返回 40301。

每页选取未删除消息，按创建时间降序、消息 ID 降序确定分页窗口，再按创建时间和消息 ID 升序返回该窗口。使用共同分页规则，默认第一页、每页 20 条，返回 page、page_size、total 和 has_next。空页为数组。消息按 V2DirectMessage 映射，can_delete 仅对当前用户自己发送的消息为真。

历史读取与发送、删除使用同一会话行锁，以序列化首次建立和后续更新已读位置。成功读取非空第一页时，用本页最后一条消息 ID 推进当前用户已读位置，保留原位置和本次候选中的较大值。以前的消息或删除最新消息导致候选较旧时，已读位置不回退。其余页及空页不更新。已读更新失败时查询回滚并返回错误。客户端恢复后读取同一权威历史接口，须忽略已失效会话或端点的响应。

Nuxt Web 和 Flutter 每页读取 20 条，并提供加载更早消息的入口。旧页和当前消息按 ID 合并，保留期间收到的消息；如果旧页请求期间收到删除事件，回执不能恢复已删除消息。补读失败保留当前历史和重试入口，切换会话、账号或 Flutter 后端时丢弃旧结果。重新连接从权威第一页刷新。页码协议下并发插入和删除可能改变分页窗口，真实数据库并发仍待验证。

两端使用 `mark_read=false` 读取历史，在当前会话可见时向已读入口提交已显示的消息 ID。省略 `mark_read` 的既有调用继续沿用首页推进规则。后台读取失败保留可见消息。切换账号、会话或 Flutter 后端后，旧回执不更新当前界面。详见 `chat-realtime-details.md`。

客户端校验整页回执。页码与每页条数须匹配请求，分页元数据须包含有效总数和布尔型 `has_next`，正文须为数组。页内消息须归属请求会话、拥有唯一的正安全整数 ID 且未删除，并包含正安全整数作者 ID、文本内容和创建时间。异常页按读取失败处理。加载更早消息失败时保留已有消息和分页位置，方便重试。

响应使用 `Cache-Control: private, no-store`，服务端也须绕过响应缓存，确保每次核对权限并执行首页已读更新。
