# 媒体上传与持久化共同规则

版本：18。三套后端分别处理媒体上传、验证、文件存储和数据库事务。验收状态参见同步登记。

## 请求与文件

有效 access 会话先于 multipart 检查及创建临时目录。只接受 multipart/form-data。以分段的 `filename` 参数识别文件，文件分段可以省略 `Content-Type`。没有文件名参数的分段按文本处理，即使带有 `Content-Type`。字段 file 的第一个文件优先，其次 media 的第一个文件，其他文件不入库。每次请求最多 1000 个文件和 1000 个文本字段，文本合计最多 20 MiB。文件及总文件数据上限为 500 MiB，上传内容流式暂存。

公共网关对 `/api/v2/media` 与 `/api/v2/media/private` 允许 528 MiB 请求体，通过 HTTP/1.1 流式送往当前 API 上游。该限额包含 multipart 封装和文本。Go 仅在上传已经鉴权且请求类型为 multipart/form-data 时，将本请求的读取期限扩展到 15 分钟，响应期限额外保留 6 分钟。

`alt_text` 和 `description` 各取第一个文本值，空值绑定 null。长度分别按 UTF-8 字节限制为 500 和 1000，以兼容 Oracle 的字节长度列。超限返回 HTTP 400、业务码 40001 和固定消息「媒体替代文本或描述过长」。校验失败时清理请求暂存数据，跳过对象发布和媒体入库。

`access_scope` 取首个同名文本值，省略或精确等于 `public` 沿用公开上传。精确等于 `chat` 或 `post` 时创建私密对象。空白、不同大小写或其他值返回 HTTP 400、40001 和「媒体访问范围无效」。私密写入先确认 Oracle T19 的 `access_scope` 列存在，缺失或不可用时返回 HTTP 503、50301 和「媒体存储暂不可用」，不发布对象。公开写入无需 T19。

Nuxt Web 与 Flutter 的私密文件必须发到 `POST /api/v2/media/private`。专用入口要求首个范围字段为 `chat` 或 `post`，缺失或 `public` 返回同一 400。未知路径、错误响应或重定向都视为上传失败。客户端不把原请求体转发到其他地址或改用公开端点。旧 `POST /api/v2/media` 保持兼容，仍支持明确携带私密用途的既有调用。

上传收到 401 时，两端可刷新当前会话，文件重发必须由用户主动提交。两端核对统一的上传成功回执、正安全整数媒体 ID 与 `ready` 状态后才允许绑定附件。私密回执必须包含同一 ID 的相对鉴权路径和显式的空缩略图字段。公开回执必须包含非空地址，且该地址不能是鉴权下载路径。

文件类型及元数据沿用现有 Nuxt 验证能力：图片、GIF、音视频、文档、文本和压缩包；根据真实内容检测，无法识别时的 MIME/扩展回退规则需单列共同样例。图片尺寸及音视频时长探测失败不虚构结果，使用 null。存储 key 使用服务端 UUID、用户 ID 和 UTC 年/月，不使用客户端文件名决定目录。不得把暂存目录作为公开文件提供。

音视频探测限定到已识别的容器格式及本地输入，禁止 MP4 外部引用。Windows 使用服务端生成的可寻址暂存文件，使探测器读取末尾索引后仍可定位到视频样本。Linux 的 Go 和 Rust 通过已打开的文件句柄提供同样的定位能力。每个进程最多同时运行 4 次探测，等待与执行共用 8 秒预算，探测输出最多 64 KiB。读取首个视频流的正整数尺寸，时长优先容器，再取对应视频或音频流的非空时长，非负秒数四舍五入。工具缺失、超时、输出或元数据无效时仍可完成上传。WAV 在未取得时长时按合法的 RIFF PCM 或 IEEE float 的块头计算，不载入音频正文。三端支持用 `FFPROBE_PATH` 配置可执行文件，Nuxt 未设置时使用其随包分发的工具，Go 和 Rust 从 PATH 查找。

三套后端源码容器均提供 `ffprobe`，Nuxt 源码镜像默认使用系统包的可执行文件。Go 和 Rust 的 Windows／Linux 独立交付包可选附带匹配后端平台的 `ffprobe`，清单校验其哈希与平台。启动器优先保留非空 `FFPROBE_PATH`，否则使用交付包内工具。未附带时仍从 PATH 查找。

## 生命周期和失败处理

每次请求拥有独立暂存目录，仅递归清理本次创建的目录；成功、无文件、验证失败、解析错误和被忽略的额外文件均要清理。普通运行数据、其他并发请求目录和既有存储文件不属于该清理范围。临时清理失败记录固定安全信息，不暴露本机路径或替代原始业务结果。

先存储文件，再取得序列并只读检查媒体结构，使用一笔数据库事务插入 ready 记录、读取和映射响应，最后提交一次。缺少刚创建的记录也必须进入回滚和清理，不能从回调直接退出。入库字段包含同一 media_id、owner_user_id、类型、原名、key、公开地址、大小、MIME、可空元数据、alt_text/description；成功为 HTTP 200/code 200/`media uploaded`，meta=null。

私密对象使用 `private/<access_scope>/` 加常规生成 key 的 `posts/` 后缀。媒体行显式写入 `access_scope`，沿用原字段名的 `public_url` 保存相对鉴权路径 `/api/v2/media/{id}/content`，`thumbnail_url` 为空。成功响应沿用媒体结构并保留该相对路径，不返回存储 key 或 CDN 地址。未关联的私密对象仅上传者能下载。Nuxt Web 和 Flutter 按频道或帖子用途上传、绑定及下载，见 `storage-local-files.md`。

提交尚未开始且回滚确认成功时，可补偿删除本次新存对象。提交一旦开始，结果未知或已提交时必须保留对象，即使后续回滚调用成功也不能推断未提交。回滚本身失败时同样保留对象，避免删除可能被数据库引用的数据；此时可产生待对账的孤立对象，不能自动重试上传。补偿删除失败也只记录安全信息，后续清理须先核对数据库引用。

本地 provider 以排他复制保护已有对象；复制完成后若移除来源失败，目标对象可能已存在但尚未返回 key，需后续对账处理。不能为了清理失败请求而删除同名既有对象。

## 删除生命周期

`DELETE /api/v2/media/{id}` 先验证 access 会话，再以媒体 ID 和当前用户 ID 锁定 Oracle 媒体行。不存在或不属于当前用户返回 404。取得行锁后另起一条查询检查 `n_post_media`、`n_chat_message_media` 和 `n_users.avatar_media_id`。保留已有引用，包括软删除内容保留的关联。命中任一引用返回 HTTP 409、业务码 40901 和「媒体正在使用」。此时回滚释放锁，媒体行和对象均保留。

群帖附件通过 `n_group_posts.media_urls` 保存。删除事务按完整逗号分隔项检查公开地址、缩略图地址和标准路径别名下的完整 key，保留软删除群帖的引用。三套后端发帖时按媒体 ID 排序锁定可识别的受管附件，将其统一为锁定行里的公开地址。发帖先提交时，删除返回 409。删除先提交时，发帖返回 400 并回滚。

帖子创建、编辑与群聊发送在写入引用前按媒体 ID 升序锁定媒体行，附件展示仍按请求顺序。头像更新引用同一事务新建的媒体行。并发新增引用先提交时，删除会读取到引用并返回 409；删除先提交时，新引用无法取得媒体行。该约定要求同时部署三个后端的对应更新。

无引用时以媒体 ID 和用户 ID 删除媒体行。只有确认恰好删除一行且提交成功，才开始清理对象并在清理成功后返回 `media deleted`。零行返回 404。异常行数、提交异常或提交结果不明时保留文件。提交后物理文件清理失败时需对账。

群组图标和横幅按 URL 保存。删除事务会检查 `n_groups.avatar_url` 和 `cover_url`，匹配媒体的公开地址或缩略图地址。对旧客户端保存的绝对地址，也会比较 `/storage/`、`/uploads/`、`/upload/` 下的完整存储 key，忽略 origin、查询参数与片段。完整 key 相同的历史别名采取保留策略。

创建或编辑群组时，三个后端识别由上传服务生成的 `posts/`、`avatars/` 完整 key，覆盖标准存储 URL、旧路径别名和当前后端配置的存储地址。解析 key 后按媒体 ID 升序锁定相关行，并写入锁定行内的公开 URL。删除先提交时，群组写入返回 HTTP 400、40001 和「群组图片不存在或已删除」。群组写入先提交时，删除读取新引用并返回 409。外部 URL 和格式不符合当前生成规则的旧 URL 保留原有写入行为。Nuxt Web 和 Flutter 上传后提交服务端返回的 URL，显示时再解析。共用 key 规则和锁查询见 `media-delete-references.json`。

存储 key 优先，缺失时才从受管理的公开 URL 提取；非本站外部 URL 不作为本地路径删除。缩略图另行处理。其他通过 URL 或缩略图共享对象的历史数据需要独立对账。真实 Oracle 并发和文件提供方留待统一验收。

Nuxt Web 的发帖和回复编辑器在提交时上传附件，保留已确认的媒体 ID，用户重试时仅上传尚未完成的附件。已上传附件的替代文本和描述保持为上传时的值。Flutter 发帖和回复在选择图片或视频后上传，两类文件共用每篇四件的上限。超过 500 MiB 的文件不提交。原生视频从文件路径读取，Web 先按浏览器提供的文件大小校验整次选择，再逐个分块读取视频。浏览器上传适配器仍需组装当前文件的 multipart 请求体。收到 401 时，Flutter 刷新会话并返回原失败，由用户重新选择需要上传的文件，已消费的 multipart 不自动重放。帖子中的公开视频提供可复制的播放链接，私密视频使用鉴权下载。两端显式移除已上传的附件时调用删除接口，确认成功后移除预览。409 或其他失败保留预览并提示。处理中禁用上传、删除或发布的重复操作。账号变更时清空附件草稿，Flutter 切换后端时也清空。离开编辑器时不会自动删除对象。

Flutter Web 的公开帖子视频可在卡片内展开浏览器播放器。来源使用当前存储配置解析后得到的 HTTP(S) 文件地址。播放器默认折叠、不自动播放，关闭、文件地址变化或离开卡片时解除当前媒体来源。Flutter 原生端可手动在系统浏览器中打开同一公开视频，启动失败保留复制链接。私密附件继续使用鉴权下载按钮，不交给系统浏览器打开。

不支持的 Content-Type、空文件或明确验证失败为固定公开的 400 消息。解析错误不得返回临时目录、底层库或驱动错误正文；数据库、存储 IO 和未知异常返回安全 500。媒体结构不可用沿用安全 503。选择 S3 而配置缺失或无效时，公开和私密上传返回 HTTP 503、50301 和「媒体存储暂不可用」，不发布到本地，也不保存媒体行。响应 private/no-store。

本规则不证明 S3、完整原生上传、真实 Oracle 提交状态或两个客户端已经通过。Rust 和 Go 均已有开发中的原生上传路径，并尝试读取图片尺寸，但格式识别、音视频元数据和真实依赖验收尚不完整。后续还需完成三端内容检测/元数据共同样例、读删权限、流式限制和 Windows/Linux/跨机验收。当前公开文件服务也不能当作私有附件权限方案。

## S3 provider

Nuxt、Go 和 Rust 原生后端已接通 `STORAGE_TYPE=s3` 的公开帖子媒体及头像对象。配置使用 `STORAGE_S3_ENDPOINT`、`STORAGE_S3_BUCKET`、`STORAGE_S3_REGION`、`STORAGE_S3_ACCESS_KEY`、`STORAGE_S3_SECRET_KEY` 和可选的 `STORAGE_S3_SESSION_TOKEN`。端点填写服务的 HTTP(S) origin，应用按 path-style 访问普通存储桶。生产环境用 HTTPS 和专用桶，权限仅覆盖受管的 `posts/`、`avatars/` 对象。应用的公开 URL、上传数据库事务及回滚补偿沿用现有入口。

单个 PUT 从暂存文件流式发送，按实际请求体计算 SigV4 SHA-256，设置 `If-None-Match: *` 防止覆盖同名对象。GET 支持单一字节范围，DELETE 只清理受管 key。私密对象使用受保护前缀和私有缓存策略，分片上传另行开发。已有本地对象切换提供方前需迁移到同名 key。真实兼容服务和跨后端读取留到统一验证。 [AWS SigV4](https://docs.aws.amazon.com/AmazonS3/latest/developerguide/sig-v4-header-based-auth.html) · [AWS PutObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html)

### 已有本地对象迁移

在 Nuxt 源码目录准备 JSON 字符串数组。每项是审核确认可公开提供的 `posts/` 或 `avatars/` 原始存储 key。清单可从 `n_media_assets` 的 `ready` 记录导出并去重，再筛选公开对象。可以分批提供清单。

```text
node scripts/migrate-storage-s3.mjs --plan <local-storage-root> <manifest.json>
node scripts/migrate-storage-s3.mjs --apply <local-storage-root> <manifest.json>
```

`--plan` 在本地检查源文件并统计范围。`--apply` 使用上面的 S3 配置，把清单中的对象按原 key 流式复制，然后从 S3 读取并核对字节数和 SHA-256。同名对象已存在时仅在内容一致的情况下计为已迁移。内容冲突或缺失时命令停止，输出失败的 key，修复后可重新运行同一批清单。命令保留本地源文件及 Oracle 行，迁移结束后由运维统一切换存储提供方。最终批次期间暂停上游上传或通过更新后的清单补齐新增对象。
