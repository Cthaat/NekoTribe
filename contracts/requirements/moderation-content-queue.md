# 内容审核队列

`GET /api/v2/moderation/content` 要求有效会话及现有审核权限，响应头为 `Cache-Control: private, no-store`。三套后端查询同一个 Oracle 案件、帖子和举报数据。列表覆盖普通帖子案件，包括审核已移除的帖子。群组和评论案件仍由各自处置流程负责。

- `status`、`priority`、`reason`、`date_range`、`q` 和 `sort` 可组合。空值、省略或重复单值参数使用默认值。`all` 关闭对应枚举筛选，作为搜索关键词时按字面匹配。未知状态和原因沿用 `pending` 和 `other`，未知优先级或日期不限，未知排序按最新。
- 搜索去除首尾空格，忽略大小写，按字面子串匹配帖子内容预览、用户名或显示名。当天和昨天按 Oracle 服务器日历，近一周及一月分别为过去 7 天和 30 天。互动为点赞、转发及回复相加。
- 页面和筛选总数来自同一语句。排序用案件 ID 打破并列，越界页返回空数组及筛选总数。作者保留公开资料字段，附件按帖子原顺序，举报按提交时间与 ID 降序，原因去重后按字母排序，没有附件或举报时返回空数组。
- Nuxt 和 Flutter 已共享筛选契约。两端忽略旧请求，切换会话清除列表。Nuxt 帖子处置按帖子 ID 重新读取结果，避免受当前筛选或页码影响。
- 隔离测试覆盖权限、筛选、排序并列、举报明细和分页。真实 Oracle 方言、日期边界、查询性能及客户端部署矩阵留待验收。Go、Rust 原生处置动作是下一项。
