# 审核助手

`POST /api/v2/ai/conversations/{id}/moderation-generate` 接受 `target_type`、`target_id`、`locale` 和 `expected_sequence`。目标类型包括普通帖子、评论、公开群帖子与公开群评论。语言为 `zh` 或 `en`。服务端检查会话所有权、审核权限、已启用的 `moderation-advice` Skill 和会话序号。

可选 `skill_id` 仅接受 `moderation-advice`。省略时按会话用途选择默认 Skill。错误类型、空值、其他 ID 或重复字段返回 400。两个客户端仅在状态目录声明 `explicit_selection: true` 时显示手动选择，未勾选时继续省略该字段。

读取所选目标的现有公开正文，排除删除内容、不可见父帖、停用作者，以及当前审核员不可见的群、帖子或作者。私密或隐秘群内容、附件、举报说明和私信不作为模型输入。无可读正文或正文超过 1000 个数据库字符时返回 `insufficient_evidence`，由审核员继续人工核查。

使用服务端配置的 `moderation` 模型和当前已发布的对应语言规则。模型只返回风险类别、简短依据、建议和规则 ID。应用校验输出结构、取值和规则引用。建议包括无需处置、人工核查和考虑移除，审核员仍通过正常流程提交正式处置。模型缺失、结果无效、规则或技能配置不可用时返回 503。

成功生成后写入一条 assistant 消息。记录模型和配置版本、Skill 代数、规则代数与摘要、目标引用及正文摘要。保存时复核会话序号、当前审核权限、目标正文和规则；会话、目标或代数变化时返回 409。历史读取会再次验证公开正文和规则，资料失效后隐藏原建议及引用。客户端通过消息的 `moderation_advice` 字段读取结构化建议。

Nuxt Web 在内容审核详情和举报条目提供助手入口。Flutter 在内容、举报列表的目标卡片提供同一入口。普通帖子、评论、群帖子和群评论可打开助手，其中举报类型 `group_comment` 映射为生成接口的 `group_post_comment`。用户举报不显示此入口。

两个客户端在首次生成时创建 `purpose=moderation` 会话，约定标题 `moderation:<target_type>:<target_id>`。标题只保留目标类型和 ID。历史查询按所有者权限分页查找同标题会话，以建议本身的目标类型和 ID 再过滤。多个设备同时创建的同目标会话均可读取。生成使用选定可读会话的最后一个原始序号，包含已经隐藏的消息。遇到冲突或生成状态不确定时，先刷新历史再允许生成，客户端不自动重试写入。切换账号或 Flutter 后端时取消在途请求并隐藏旧建议。

打开或刷新审核助手时，从每个匹配会话读取最近 50 条原始消息，按建议时间和消息 ID 倒序展示。加载更早建议时，从每个仍有历史的会话继续读取一页，使用该会话当前最早的原始序号作排他游标。加载更早不改变生成所用的会话或最新原始序号。旧服务若忽略倒序游标并返回从 1 开始的满页，沿正向游标读到末尾并只保留最近 50 条原始消息。加载更早时，沿正向游标读到排他边界并保留紧邻边界的最多 50 条。两种分页方式都先按原始消息计算边界，再筛出助手建议。生成、删除后的读取从最近一页恢复。评分后定向回读已评分建议，保留打开的页，详见 `ai-moderation-feedback.md`。

Nuxt Web 与 Flutter 在推理请求期间提供停止按钮。停止后取消当前请求并丢弃迟到回执，刷新当前目标的已保存建议后才可再次生成。停止不会撤销已保存的建议，也不会提交审核处置。提交已经开始时，通过刷新核对实际保存结果。

收到匹配的保存回执后，若历史暂时无法读取，两端提示建议已保存，要求先刷新历史才可再次生成。权限变化继续按原规则处理，刷新不重发生成请求。

加载更早建议时，某个会话的消息读取返回 404，只移除该会话的已显示建议和分页游标，继续读取仍可用的会话。如果该会话原本用于生成，改用第一个仍可用的会话及其已确认的最新原始序号。没有剩余会话时，下一次由用户明确生成才创建会话。此流程只读，其他读取错误沿用原处理规则。

客户端展示结构化风险、理由、建议和规则版本。Nuxt Web 链接到对应语言的条款小节。Flutter 从与三个后端共用的条款目录读取同语言原文，校验版本摘要后再展示。两个入口均只写建议会话，确认处置沿用现有审核操作。

两端从仍可见的审核建议读取已复核的目标定位，可打开普通帖子、群帖子或准确的目标评论。评论通过父帖和评论 ID 定位，群内容同时要求群组 ID。目标不匹配时不采用建议；旧结果缺少完整定位时仍可展示建议和规则，但隐藏原文入口。按原权限读取目标，打开原文不会提交审核操作，也保留现有建议视图供返回。

审核员可在读取过历史后删除当前 AI 会话，即生成按钮下一次使用的会话。对于同时展示的其他会话，两端在各会话最新一条可列出的建议旁提供删除入口，确认时显示该条建议的时间并说明会影响整个所选会话。两端要求显式确认，调用现有 `DELETE /api/v2/ai/conversations/{id}`，只删除该会话及其建议和评分。确认受当前身份、后端和目标约束。成功后重新读取该目标下剩余的历史，保留其他会话与审核案件。结果不确定时清空旧显示，提示刷新核对，禁止自动重复删除。
