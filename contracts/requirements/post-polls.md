# 普通帖与群帖投票

普通帖和群帖的创建请求可附带 `poll` 对象，包含 `options`、`multiple`、`closes_at`。选项为 2–6 个不同的非空字符串，去掉首尾空白后每项最多 240 UTF-8 字节。`multiple` 为布尔值。截止时间采用 RFC 3339，创建时须晚于数据库当前时间。普通帖仍使用原有正文与附件规则。仅 `post_type=post` 可附带投票。创建帖子、投票及选项在同一事务内提交。

普通帖和群帖的读取结果可以包含 `poll`，返回 `poll_id`、`multiple`、`closes_at`、`closed`、`total_ballots`、`my_option_ids`、`options`。选项对象含 `option_id`（从 1 起的顺序编号）、`text`、`votes_count` 和 `percent`。`percent` 是选择该项的投票人数占总投票人数的百分比，保留一位小数。零票时为 0。多选时各项比例可以合计超过 100%。读取不公开投票人的账号。

`GET /api/v2/posts/{id}/poll`、`GET /api/v2/groups/{id}/posts/{post_id}/poll` 读取当前结果。原帖的可见性规则继续适用。群帖读取沿用现有鉴权。两条路径下的 `POST /vote` 需认证，以 `{option_ids: [...]}` 提交本人的一张选票。只有当前有群内容写入权限的成员可参与群帖投票。单选必须提交一个选项，多选可提交一个或多个互不重复、属于该投票的选项。选票及选项记录一起提交。截止后或同一账号已提交时返回 409；不存在、已删除或不可读的帖子及投票返回 404；不符合输入约束时返回 400。

Oracle 中按 `(poll_id,user_id)` 唯一约束保存一张选票，按 `(poll_id,user_id,option_id)` 唯一约束保存各选项，避免并发重复投票。三套后端使用 Nuxt 显式迁移生成的结构目录。新接口及含投票的发帖在结构未就绪时返回 503，普通历史仍可在投票表尚未整体应用时读取旧内容。

Nuxt Web 和 Flutter 在普通帖、群帖的撰写界面提供投票设置。帖子卡片和详情展示选项、票数、比例、截止状态和自己的选择。提交后即时用服务器回执刷新，活动页面定期对可见且开放的投票刷新结果。清除页面或切换账号后丢弃旧回执。
