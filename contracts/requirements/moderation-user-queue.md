# 用户审核队列

`GET /api/v2/moderation/users` 只向持有效会话并有审核权限的用户返回结果。此端点包含审核所需的账号邮箱，不进入共享缓存，响应设置 `Cache-Control: private, no-store`。

- `status` 按帐号状态精确筛选，省略、空值和 `all` 表示全部。 `q` 对用户名、显示名和邮箱执行忽略大小写的字面子串匹配，去除首尾空白。百分号和下划线作为普通字符。
- `sort` 支持 `newest`、`oldest` 和 `reports`。未知值使用 `newest`。创建时间相同时按账号 ID 排序，举报最多先按举报数排序，再按加入时间及 ID 降序。重复的单值筛选参数按省略处理。
- 总数与页面来自同一条语句。越界页返回空数组及筛选总数。举报数包括直接针对用户和针对其普通帖子的举报。限制类型和结束时间取开始最新、已生效且未过期的同一条记录，开始时间相同时取限制 ID 最大的记录。
- Nuxt Web 和 Flutter 共用查询参数与排序选项。刷新筛选时忽略旧请求结果，分页继续沿用已提交筛选，切换会话时清除审核数据并阻止发出旧会话的用户处置。
- 与真实 Oracle 数据、索引、时区及部署矩阵相关的验收留待依赖联调。内容审核队列与处置接口分别交付。
