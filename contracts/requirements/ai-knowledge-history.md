# 知识回答历史和引用恢复

状态：开发中。Nuxt、Go、Rust 已将编码和恢复组件接入内部消息写入、历史读取及内部知识生成流程，三后端均已接入知识生成 HTTP 入口；Nuxt Web 和 Flutter 已接入基础知识会话页面并进行隔离测试，真实 Oracle、模型及客户端端到端尚未验收，不能当作完整知识对话已验收。

知识助手消息保存在现有消息正文 CLOB 的版本化 JSON 信封中：`{"version":1,"answer":"...","sources":[{"kind":"post|comment","id":1,"version":"64位小写SHA-256"}]}`。只保存回答和被引用来源标识，不存检索到的来源正文、模型凭据或内部地址；消息角色、会话归属、模型及配置版本由现有列管理。整个编码后的 UTF-8 消息不得超过 65536 字节。信封字段须精确匹配，答案非空白且为有效 Unicode，来源 1–20 条、ID 有效、版本格式正确且同一来源不重复；未知版本、数据损坏或旧的无来源助手消息失败关闭，不直接显示。

恢复前先验证当前用户对会话的权限，再从当前业务数据按该用户重新复核所有引用的公开状态、访问权限和正文版本。任意来源不存在、撤权、删除或改动时，不返回该回答或旧引用，不将其加入模型上下文；数据库错误失败关闭。仅在全部来源通过时返回回答和来源标识，读取后仍需考虑权限变化和引用再次访问时的独立授权。恢复不能信任存储时的角色或用户声明；数据保留和删除继续遵循会话权限及级联规则。

三端内部知识助手写入在事务内锁定会话、检查序号并在写入前和提交前复核来源；普通助手写入不能写入知识会话。历史读取和最新上下文读取会检查知识助手信封及来源，并将通过的引用作为可选 `citations` 返回。失效或损坏历史当前导致整页失败；该行为仍须在三端和客户端定义稳定错误。两次查询并不锁定来源，不能证明撤权与提交竞争完全消除，真实 Oracle 并发策略仍需验证；推理期间不能持有数据库连接或锁。必须覆盖并发撤权、旧数据、分页、删除与真实 Oracle 验收。

引用返回 `{kind,id,version,post_id}`：`post_id` 从当前已复核的来源记录获取，而非来自模型、客户端或存储的历史信封；帖子引用的 `post_id` 必须等于其 ID。评论引用使用所属公开帖子的 ID，两个客户端可跳转到帖子；正文不会附带在引用中。复核失败或帖子 ID 不合法时整条历史读取失败关闭。旧后端未提供 `post_id` 时客户端仍显示评论编号。

三端内部生成流程先按当前用户读取知识会话和最新消息，关闭连接后按最新用户问题检索并生成，随后通过原序号检查写入带引用的回答，保存本次模型配置快照；无证据时不写入。当前未将较早历史送入模型，完整多轮上下文需要确保所有历史引用在推理后及写入时仍有权限，不能把此阶段称为完整多轮知识对话。

为支持自然语言提问，检索词与问题可分别提供：问题继续来自用户持久化消息，检索词仅用于受权限约束的精确搜索；未提供时保留原行为。Nuxt、Rust、Go 生成路由已接入可选的 `search_phrase`，Nuxt Web 与 Flutter 已提供独立输入并允许更改检索词重试，不重复追加问题。检索词有效性、大小限制和重试规则见 Nuxt 工程的 `docs/plans/2026-10-30-knowledge-search-phrase.md`；真实后端、模型和客户端共同验收仍待完成。

三端请求体验证共用 `ai-knowledge-search-body.json`：空字节或空对象表示缺省；其余请求必须是 UTF-8 JSON 对象且仅有一个字符串 `search_phrase`，重复字段拒绝。请求体最多 4096 字节；检索词按 ECMAScript 去除首尾空白后为 1–256 UTF-8 字节，不含控制字符，不能含孤立 Unicode 代理字符。错误请求不进入数据库或模型。路由按实际读取量限制请求，不能只检查 Content-Length；真实运行及跨实现共同验收尚待完成。

统一入口 `POST /api/v2/ai/conversations/{id}/knowledge-generate` 使用当前登录会话及服务端模型配置，不从客户端接受模型或凭据。生成成功返回 `status=generated` 及助手消息标识；没有有效来源时返回 `status=insufficient_evidence`、`message=null`，不追加消息。消息正文和已校验引用通过授权历史接口获取；该接口不得缓存私人内容。错误、并发变更和取消须统一处理，不暴露模型地址、凭据、正文或数据库错误。Nuxt Web 和 Flutter 显示来源标识并链接帖子；两客户端真实联调仍待完成。
