# 知识回答历史和引用恢复

状态：开发中。Nuxt 有内部编码与恢复组件；Go/Rust、数据库接线和公开接口尚未实现，不能当作知识对话已可用。

知识助手消息保存在现有消息正文 CLOB 的版本化 JSON 信封中：`{"version":1,"answer":"...","sources":[{"kind":"post|comment","id":1,"version":"64位小写SHA-256"}]}`。只保存回答和被引用来源标识，不存检索到的来源正文、模型凭据或内部地址；消息角色、会话归属、模型及配置版本由现有列管理。整个编码后的 UTF-8 消息不得超过 65536 字节。信封字段须精确匹配，答案非空白且为有效 Unicode，来源 1–20 条、ID 有效、版本格式正确且同一来源不重复；未知版本、数据损坏或旧的无来源助手消息失败关闭，不直接显示。

恢复前先验证当前用户对会话的权限，再从当前业务数据按该用户重新复核所有引用的公开状态、访问权限和正文版本。任意来源不存在、撤权、删除或改动时，不返回该回答或旧引用，不将其加入模型上下文；数据库错误失败关闭。仅在全部来源通过时返回回答和来源标识，读取后仍需考虑权限变化和引用再次访问时的独立授权。恢复不能信任存储时的角色或用户声明；数据保留和删除继续遵循会话权限及级联规则。

真正接线需把来源复核与助手消息写入、并发序号检查、提交前权限复核组合到同一事务；推理期间不能持有数据库连接或锁。返回历史与用于后续推理的最新历史均需应用恢复检查；各后端、OpenAPI 和客户端应共同定义不可用历史的稳定响应。必须覆盖并发撤权、旧数据、分页、删除与真实 Oracle 验收。当前内部组件尚未写数据库，不能宣称历史已受保护或可恢复。
