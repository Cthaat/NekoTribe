# 推荐反馈

有效会话可通过 `POST /api/v2/recommendations/feedback` 提交 `resource_type`、`resource_id`、`action` 和可选 `reason`。旧版 Flutter 使用 `{post_id, feedback}`，三套后端接受这一格式。混用两种格式返回 400。目标 ID 为正安全整数。动作支持 `not_interested` 和 `show_less`，原因去除两端空白后最多 500 UTF-8 字节。

写入前按目标类型校验帖子可见性、用户公开资料和拉黑关系、群组访问权限或标签存在性。不存在与不可见均返回 404。反馈以认证账号、目标类型、目标 ID 唯一存储。同一账号的请求串行写入，重复提交保留上次修改时间，改选动作或理由则更新记录。只有提交成功后才返回 `accepted: true`。

登录后的首页及热门推荐会读取帖子反馈。`not_interested` 从推荐结果及总数排除该帖。`show_less` 将该作者的帖子排到其他作者之后，同组内按原排序。搜索、关注、提及、详情和个人列表沿用原有视图。用户、群组和标签的反馈目前作为存储信号，现有排序只消费帖子反馈。

先用 `node scripts/migrate-db.mjs --plan` 检查新增迁移。反馈表缺失时写入返回 503，推荐列表维持迁移前行为。Nuxt 的相关推荐读取绕过缓存，以读取其他后端刚写入的反馈。部署验收需要在隔离 Oracle 库复核并发重试、迁移和两客户端的切换组合。
