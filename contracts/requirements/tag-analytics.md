# 标签统计共同需求

`GET /api/v2/tags/{name}/analytics` 要求有效 access token 和会话，Cookie 优先。名称是 URL 解码后的非空标签名，按数据库 `LOWER` 比较，使用绑定参数；标签不存在返回 404 `话题不存在`。查询失败返回安全 500，不泄漏数据库信息或输入。

返回 `name`、`total_posts`、`total_authors`、`total_views`、`total_likes`、`engagement_score`。计数按当前用户可见且未删除的帖子计算：左连接标签关系、帖子及统计，将 `fn_can_view_post(:viewer_id,p.post_id)=1` 与未删除条件放入帖子连接，统计 `COUNT(DISTINCT p.post_id)`、`COUNT(DISTINCT p.author_id)`，求可见帖浏览/点赞和及平均互动分（四舍五入到两位），没有可见帖则为零。用户 ID 来自认证会话，不接受请求参数覆盖。

这是有意修复 Nuxt 原 `v_tag_analytics` 将私密帖纳入聚合，以及计数可能包含已删除帖的问题；原数据库视图保留，接口不再直接使用它。标签可存在但对当前用户没有可见帖子，仍返回名称和全零统计。该变更可能使原统计值降低；各后端必须采用相同规则。接口结果随查看者变化，不允许共享缓存跨账号或跨后端返回旧值。Nuxt 对本接口禁用响应缓存，并对包含 `fn_can_view_post` 的 SQL 禁用查询缓存；这也会使单后端模式下其他调用该函数的查询不再命中查询缓存。

`tag-analytics.json` 是隔离路由场景；数据库函数、聚合准确性、并发与隐私隔离、Oracle 驱动和真实环境仍需隔离联测。错误或隐藏信息不得出现在响应或 handler 日志。

客户端通过现有话题入口显示帖子数、作者数、浏览量、点赞量和平均互动分。Nuxt Web 从 `#话题` 搜索进入，Flutter 从话题页进入。标签名称编码为一个路径段。统计与帖子列表独立请求，统计为零时显示零，话题不存在时隐藏统计区域，其他失败可单独重试。切换话题、账号或客户端后端后，旧统计不能写回当前页面。
