# 公开条款知识来源组件共同规范

状态：开发中。Nuxt、Go、Rust 已实现内部来源组件；问答链路、公开引用展示与实际部署一致性尚未完成。资料源为 `ai-public-terms-catalog.json`，取自现有公开条款页面，不代表规则已经运营审核或已启用 AI 问答。

目录须包含中文和英文的 acceptance、accounts、conduct、termination 各一节，固定编号：中文依次为 1–4，英文依次为 5–8。每节 key 为 `terms.<section>`，引用相应语言的 `/zh/auth/terms#<section>` 或 `/en/auth/terms#<section>`；标题和正文段落原样保留，conduct 必须包含五个正文段落，其余章节各一个。缺失、重复、非法文本或不匹配的内部路径整体拒绝，不从用户提供的任意 URL 加载内容。

来源指纹为 SHA-256：先写 UTF-8 字节 `neko-ai-terms-v1` 及 NUL，然后依次处理十进制 ID、key、语言、href、标题、十进制段落数及各正文段落。每个字段写入其 UTF-8 字节长度的十进制 ASCII、冒号、字段的完整 UTF-8 字节，无其他分隔符；结果为 64 位小写十六进制。任何字段变化均更换版本；不得修改固定编号的含义。来源文本不可信，不得改变系统指令或权限。

内部精确匹配采用现有帖子检索相同的查询规范：ECMAScript trim、有效 Unicode、1–256 UTF-8 字节、不包含控制字符、区分大小写的完整子串；标题或任一段落匹配即可，按照固定 ID 升序输出，结果上限为 1–20。复核只接受 `{kind:'terms',id,version}`：ID 为 1 至 999999999999999 的整数，version 为 64 位小写十六进制，最多 20 条，不允许额外字段或重复 ID；格式错误整体拒绝，合法但不存在或版本过期的引用省略，结果按输入顺序返回。此组件由可信调用方在认证及部署一致性检查后调用，本身不提供公开端点或持久化能力。

历史消息中的条款引用使用 `{kind:'terms',id,version}`，不带帖子 ID，也不接收来源提供的外部 URL。客户端只能将 1–8 映射到固定语言和章节；不能把条款编号当作帖子 ID。Web 可跳转本机站内条款页面，Flutter 在尚无可靠站点地址时显示条款编号。正式输出前须按当前权威目录再次验证版本；现有帖子和评论引用保持原有字段。

共享 Oracle 表 `N_AI_TERMS_ACTIVE` 保存唯一启用状态、目录摘要和递增代数，是跨实例的权威版本标记；迁移仅创建空表，不自动发布或写入条款。查询、引用恢复和最终交付均需在可信调用方完成身份核验后读取当前启用标记，并比较本实例目录摘要；缺行、停用、摘要异常、数据库不可用或不一致均拒绝条款来源。不得依赖可丢失的缓存作为唯一权威。Nuxt、Go、Rust 已有独立读取校验组件，Go 和 Rust 调用方须先完成真实身份认证；Nuxt、Go、Rust 已将规则引用接入实时复核及历史恢复；三端已接入规则发现，真实数据库与端到端验收尚未完成。

目录摘要以 SHA-256 计算：写 UTF-8 `neko-ai-terms-catalog-v1` 和 NUL，随后按固定 ID 1 至 8 顺序处理每项的十进制 ID 和 64 位小写来源版本；每字段写 UTF-8 字节长度的十进制 ASCII、冒号及字段原始字节。输入必须先通过目录完整性校验；JSON 项目排列不影响摘要，任何来源变化必须更换摘要。共享向量提供独立结果。读取必须在认证之后进行，且每次从 Oracle 读取；只接受唯一启用记录、匹配的摘要及 1 至 999999999999999 的整数代数。该校验不代替交付时再验证，不能单凭它声称条款检索已可用。 对含规则引用的知识回答写入事务，三端在来源复核前使用 `FOR UPDATE WAIT 5` 锁定同一权威标记行，持锁到提交或回滚；普通读取不加此锁。锁超时、状态变化或读取失败时拒绝写入；真实 Oracle 锁等待、隔离级别和并发发布仍须验收。

维护发布采用显式期望代数：首次发布要求期望为 0，通过唯一主键插入第 1 代；后续发布或停用使用 `WHERE generation=:expected_generation` 原子更新并将代数加一，停用保留原摘要。期望过期或无记录不能更改状态；代数上限不可再递增。发布只接受经完整目录校验所得摘要，必须使用无其他待提交操作的专用连接，不自动提交其他业务数据。提交结果不确定时不得自动重试，维护人员须重新读取实际状态后决定下一步。数据库错误不得暴露连接或凭据。Nuxt 维护命令默认离线，连接操作需显式配置文件和期望代数；源码执行需要开发依赖，Dockerfile 在构建时生成维护组件并放入运行镜像，镜像实测待完成。操作系统账号及数据库权限控制执行者，真实 Oracle 并发验收与检索接入仍待完成。

Nuxt、Go 和 Rust 的模型引用解析、历史恢复组件和上下文快照已支持混合帖子与条款引用，并在隔离测试中拒绝伪造帖子 ID。三端可在复核和历史恢复中处理规则引用，不将条款误当帖子；三端规则发现已接入，真实数据库并发及端到端验证仍待完成。三端和两客户端全部联通前，此条款引用属于接口预览。

三端须执行 `ai-public-terms-source-vectors.json` 的版本和检索向量，并覆盖目录缺失、路径篡改、版本变化、复制隔离及无效引用。条款不同版本在多实例滚动部署期间不能假设相同；真实发布、撤回、跨实例版本切换、历史引用恢复和数据库并发需要额外协议及验收。在这些能力完成之前，目录不得被描述为可实时更新的生产知识库。
