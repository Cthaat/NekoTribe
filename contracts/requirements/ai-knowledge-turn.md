# 知识回答来源复核边界

Nuxt、Rust、Go 的知识生成 HTTP 入口已接入编排、可切换模型传输、持久化和历史来源复核。客户端与写入契约见 `ai-knowledge-history.md`，真实服务验收仍待完成。

调用方须使用已认证的用户身份发现允许的知识来源，最多 20 条；发现结果仅用于提取类型、ID 和版本，不能直接作为模型输入。推理前重新按当前权限和版本读取完整正文，删除、改权、编辑后的候选省略；没有有效来源时不调用模型，返回无证据状态，禁止生成虚构回答。

推理只能使用刚复核通过的来源。输出前使用同一用户身份再次按类型、ID、版本读取所有使用过的来源，并比对正文、所属帖子与所属群。任一来源改变、不可见、删除或无法复核时，丢弃整条模型输出，不返回正文或旧引用。异常或未知来源失败关闭，不得回退到缓存。取消请求时不交付输出；回答正文限制为有效 Unicode、非空且不超过 65536 UTF-8 字节。输出的来源列表仅含类型、ID、版本，不附后台正文。

该检查是交付时刻的复核，并不能保证之后不发生权限变化。持久化回答及再次读取历史时必须重新校验引用；不能将含过期引用的回答直接显示。生成和持久化接线必须保护会话权限、并发顺序与事务边界，不能在等待模型时占用数据库事务或连接；模型调用和资料必须遵守上下文与资源上限。引用必须能与回答逐项对应和验证，不能仅因附带来源列表就声称回答正确或引用有效。索引覆盖普通公开帖子、评论、公开群内容和已发布的平台规则。真实 Oracle、Qdrant 和模型需集中验收。

三端内部服务以 `knowledge` 角色选择固定模型配置，将来源和问题作为非可信用户数据传入，按模型配置保守限制编码后的输入体积，超限拒绝；非正常结束或工具提议不得作为成功回答。提示词提醒模型资料不可信并不保证抵抗提示注入，回答准确性和模型对资料中指令的抵抗能力仍需实际评测。连接生命周期和超限行为须在真实环境逐端验收。

模型输出是仅含 `answer` 和 `citations` 的严格 JSON 对象。`answer` 是非空白有效 Unicode 文本，至多 65536 UTF-8 字节。`citations` 含 1–20 条不重复引用，必须对应本次推理已提供并经推理后复核的来源。异常、额外字段、未知来源或重复引用整体拒绝。服务端向调用方交付复核通过的 `kind`、`id`、`version`，引用不附正文。无有效证据时使用既有无证据状态。来源身份校验无法代替对回答内容的准确性评测。

模型配置声明 `structured-output` 时，按本次来源顺序向模型提供从 1 开始编号的 `{ref,kind,content}`。三后端使用共享的 `ai-knowledge-answer.json`，将可选引用编号限制为本次资料的 `ref`，交付前按已复核来源恢复 `kind`、`id`、`version`。未声明该能力时，按文本提示要求模型原样引用资料的 `kind`、`id`、`version`。两种模式共用来源权限、正文和版本复核规则。

三端需用共同场景验证：发现后失效不进入推理、推理中删改或权限变化不交付、无来源不推理、异常/重复/注入候选拒绝、取消、连接释放、真实 Oracle 并发以及持久化历史读取重新授权。隔离测试不替代真实依赖验收。
