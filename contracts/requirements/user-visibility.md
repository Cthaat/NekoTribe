# 用户拉黑与静音

Nuxt、Go、Rust 原生提供 `GET /api/v2/users/me/blocks`、`GET /api/v2/users/me/mutes`，以及两个列表各自的 `POST /{target_id}` 与 `DELETE /{target_id}`。服务从已验证且未撤销的会话取得操作者 ID。请求不能指定其他账号为操作者。

1. 目标路径段解码后须为正十进制安全整数，且无前导零。非法 ID 返回 400。新增关系时，本人目标返回 422，目标无法读取有效公开资料时返回 404。删除按当前账号和目标删除对应记录，已经删除或目标缺失仍返回 200。数据库失败返回安全 500。
2. 新增拉黑与静音先按较小 ID、较大 ID 顺序锁住两个用户行，再核对目标有效性。拉黑写入和取消双方现有的 active 关注在同一 Oracle 事务。重复拉黑不新增记录，取消拉黑不恢复旧关注。新增关注与拉黑的互斥规则见 `user-follow.md`。
3. 静音 POST 支持空请求体或对象。缺失、null 或空字符串表示长期静音。非空到期时间为带时区的公历日期，必须精确到秒，可带 1 至 9 位小数，转换到 UTC 后年份须在 0001 至 9999 内。服务返回 UTC 毫秒格式。无法解析或不合法的字段返回 400。已有同向静音更新到期时间，过程不改变关注记录。
4. 成功的写入响应含 `target_user_id` 与 `relationship`，其值分别为 `blocking`、`muted` 或 `none`。静音 POST 额外返回可空的 `expires_at`。
5. 列表仅返回当前用户的关系，使用同一条 SQL 得到可见数据及总数。到期静音与非活跃资料都不计入结果和总数。保持 followers_count 降序、created_at 降序并以 user_id 升序打破并列。空页返回空数组，并保留过滤后的总数。静音列表每项有可空的 `expires_at`，拉黑列表沿用公开资料形状。响应使用 `private, no-store`，并绕过 Nuxt 的 Oracle 查询缓存，使其他后端的成功写入在下一次读取时可见。

三后端共用 `user-visibility-sql.json`。隔离路由场景见 `scenarios/user-visibility.json`。Nuxt Web 与 Flutter 可在他人的资料页拉黑、静音 24 小时或长期静音，并在账号设置中分页管理和解除关系。拉黑前提示会取消双方关注。静音列表显示到期时间，删除本页最后一条后刷新至有效页，切换账号时丢弃旧会话的迟到结果。真实 Oracle 的行锁、触发器、时区、部署代理和两客户端交互仍待验收。
