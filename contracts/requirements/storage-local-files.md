# 本地存储路径与读取规则

版本：16。用于 Nuxt/Rust/Go 的本地文件操作、公开存储及私密附件读取。上传和删除的生命周期见 `media-upload.md`。

存储 root 由服务端显式配置，允许管理员将该 root 指向挂载目录；root 以下的组件不得为符号链接或 Windows junction/reparse 链接。任何读取、写入和删除均须验证规范 key 与实际目录边界。读取只接受普通文件，目录不能列举；新目录逐级创建并检查，不能先递归创建整个不可信路径再验证。服务管理该目录；对本机高权限并发替换目录的隔离还需平台专用文件句柄方案和部署权限验证，不把静态链接检查宣称为完整竞态防护。

文件 key 统一使用相对 `/` 分隔路径，兼容输入反斜杠后再验证。空 key、绝对路径、重复/末尾分隔符、`.`/`..` 段、ASCII 控制字符及 `< > : " | ? *` 拒绝。段末尾的点/空格和 Windows 保留设备名也拒绝，包括 CON、PRN、AUX、NUL、COM1..9、LPT1..9、对应上标 1/2/3、CONIN$/CONOUT$（含扩展名）。不在文件组件再次百分号解码；HTTP 边界只能解码一次。

新对象 key 冲突时必须失败并保留原文件，不以覆盖方式解决冲突。Nuxt 当前通过排他复制实现；跨文件系统复制的失败与孤立对象对账要求见 `media-upload.md`。

Range 仅接受 trim 后大小写不敏感的 `bytes=start-end`、`bytes=start-` 或 `bytes=-suffix`，不支持多段。无值/空白表示完整读取。越界结尾截到文件末尾，超长后缀表示整个文件；空范围、零后缀、起点不小于文件大小和反向范围为 416，空文件的任何 Range 也为 416。错误包含 `Content-Range: bytes */size`。成功范围是闭区间，读取长度为 end-start+1。不得为发一个范围将整个文件读入内存。

S3 读取在 Range 语法无效时只向上游请求 HEAD。上游 416 缺少合法的 `Content-Range: bytes */size` 时也只补发一次 HEAD。对象存在且可确定长度时返回 416 和总大小。对象不存在返回 404，元数据不可用返回 503。私密附件的读取及元数据请求均须先通过同一授权。

公开对象的 `HEAD /storage/{key}` 使用与完整 GET 相同的路径和访问规则，返回 HTTP 200 及完整文件的大小、类型和可用缓存元数据。HEAD 忽略 Range，无响应体。S3 模式下对受管对象发送上游 HEAD，提供方不会下载对象内容。无法找到默认头像文件时保留默认头像回退，HEAD 返回该头像的大小和类型。

本地和 S3 的公开 GET、HEAD 及 206 响应根据规范 key 的最后一个文件扩展名设置类型，比较扩展名时忽略大小写。WebP 和 AVIF 分别返回 `image/webp` 和 `image/avif`，`.oga`、`.ogg`、`.opus`、`.spx` 返回 `audio/ogg`，`.ogm`、`.ogv` 返回 `video/ogg`。只有前导点的文件名和未知扩展仍返回 `application/octet-stream`。私密读取按附件下载约定处理。

配置允许的跨域客户端可对 `/storage/{key}` 预检 `GET` 或 `HEAD` 并发送 `Range`，可读取 `Content-Range` 和 `Accept-Ranges`。公开对象的预检方法为 `GET,HEAD,OPTIONS`，沿用通用来源允许列表。允许来源收到的 206 和 416 响应均暴露范围头。

公开对象读取受当前提供方的公开访问能力限制。首段为 `temp` 或 `private` 的规范 key 均保留，比较时忽略大小写。公开 GET 和 HEAD 在读取文件或请求 S3 之前返回 404，不返回对象的长度、类型或范围。公共网关和兼容 Nginx 入口均由应用提供文件，不直接暴露存储根目录。S3 配置禁止静默回退本地。

选择 S3 但连接配置缺失或无效时，公开 GET 和 HEAD 对 `posts/`、`avatars/` 下的合法对象返回 503。同名本地文件不参与读取。非法 key 继续返回 400，保留命名空间及 S3 不管理的 key 返回 404，默认头像继续由应用内置资源提供。

带文件路径的旧 `/upload/` 和 `/uploads/` GET、HEAD 由三套后端返回 410 和 `Cache-Control: no-store`。GET 返回原有 JSON 退役提示及 `data.storage_base: "/storage"`，`requested_path` 保留原路径的百分号编码并省略查询串。HEAD 返回相同状态且无响应体。请求不访问存储。公共网关将两个旧前缀发给当前 API 后端。

## 私密附件接入约定

共享 Oracle 显式迁移 T19 添加 `n_media_assets.access_scope`，允许 `public`、`chat`、`post`。默认 `public`，且非空。旧记录和旧上传器继续使用公开用途。公开媒体写入不查询新列，迁移前也可用。

本地和 S3 已允许服务端发布及删除 `private/chat/` 和 `private/post/` 下的对象。私有发布排他创建，S3 同时签名 `Cache-Control: private, no-store`。私有对象不生成公开地址，公开读取仍拒绝两个命名空间。数据库行的可信存储 key 可以触发删除，旧公开 URL 和缩略图 URL 的回退路径忽略私有 key。S3 桶及 CDN 配置必须禁止直接公开这些对象。

三套后端通过 `GET /api/v2/media/{id}/content` 及同路径 `HEAD` 读取私有对象。ID 为正安全整数，使用无前导零的十进制。先验证 access 会话，再由共享查询 `media-private-read.json` 使用两条互相独立的权限路径之一：

- 未关联任何帖子或频道消息的媒体仅上传者可预览。
- 已关联媒体按当前内容权限读取。频道要求活跃群组、未删除的频道与消息，以及活跃或禁言成员资格。私密频道只允许群主、管理员和版主。帖子按当前非公开可见性及 Oracle 帖子访问规则判定。双方账号必须启用，双向拉黑任一方向都会拒绝。内容软删除后保留关联，不产生上传者预览通道。

查询须在访问存储前完成，返回的 key 必须与 `chat` 或 `post` 用途匹配。未登录返回 401，无效 ID 返回 400，缺失、已删除或无权限统一 404。T19 未部署或对象存储暂不可用返回 503。读取返回二进制附件，带 `Cache-Control: private, no-store` 和 `X-Content-Type-Options: nosniff`，不返回 key 或存储地址。GET 的可满足单段 Range 返回 206，无效或不可满足时返回 416。HEAD 忽略 Range 且无响应体。配置允许的跨域客户端可以发送 Range，并读取范围和下载相关响应头。公共部署网关把此接口交给 API 后端并关闭响应缓冲。

上传接口接收 `access_scope=chat` 或 `post`。返回的路径指向鉴权读取，未关联之前只向上传者开放。绑定附件时按媒体 ID 排序锁定现有记录，再查询用途与关联，确保取到行锁后能看到其他已提交的关联。共享查询见 `media-private-bind.json`。私密附件必须属于当前发布者、状态为 ready，且仅绑定一条内容。频道只接收未绑定的 `chat` 对象，`post` 对象只可绑定私密、关注者可见或被提及者可见的帖子。原帖子编辑可以保留其附件。将帖子改为公开时，必须明确移除或替换所有私密附件，否则整笔回滚。

客户端接入与部署须满足以下规则：

- 私有记录不得生成 CDN URL，也不得通过群组图标、头像、公开帖子或可粘贴的媒体 URL 转为公开对象。
- Nuxt Web 与 Flutter 的频道发送默认使用 `chat`。发帖时根据所选可见性使用公开或 `post`。客户端确认媒体 ID 与相对鉴权路径匹配，再提交绑定，保留发送失败时已确认的附件以便重试。跨公开与私密切换需先移除已上传的不匹配附件。
- 私密文件只从客户端发往 `/api/v2/media/private`。旧后端无法处理该入口时，客户端保留上传失败状态，避免旧公开上传逻辑忽略私密用途。专用上传禁止跟随重定向。
- 帖子和频道将私密附件显示为下载操作。用户点击后，通过当前配置的 API 和 access 会话取得二进制，再保存文件。账号、后端或目标切换时丢弃过期的响应。旧公开附件沿用原有预览。
- Flutter 桌面先让用户选保存路径，再用鉴权 HEAD 读取大小，并逐段请求最多 4 MiB 的闭区间，核对 206、实际字节数及 `Content-Range`。内容暂写到目标所在目录的临时文件，完整后才提交。取消、会话变更和请求失败保留原目标并清理未提交的临时文件。Flutter 移动端沿用系统保存方式。
- 浏览器提供文件保存接口时，Nuxt Web 和 Flutter Web 可先选择保存位置，再通过当前鉴权接口写入。Nuxt 将响应流写入文件，Flutter Web 沿用分段请求。取消或失败放弃未提交内容，浏览器没有文件保存接口时沿用 Blob 下载。私密请求禁止重定向，两端均提供取消操作。
- 帖子编辑改为公开时，用户需确认移除私密附件，保留现有公开媒体 ID，并在同一次更新提交。
- 部署先同步公开路径拦截、数据结构、授权读取和客户端，再启用私有写入。旧公开对象保留原地址。需要改为私有的历史附件另行迁移，并单独处理已发行链接和缓存。

共同样例为 `storage-local-policy.json`。Go 使用受根目录约束的文件句柄，Rust 检查目录的静态链接及 Windows reparse 属性。对本机并发替换的防护、真实 Windows/Linux 文件系统和跨机存储部署单独验收。
