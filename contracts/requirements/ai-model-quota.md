# AI 推理配额

Nuxt、Go、Rust 的知识问答、写作、群运营草稿和审核建议共用同一份 Redis 原子预留脚本、账号计数和服务计数。

- 账号按登录用户 ID 计量，后端从会话鉴权取得 ID。服务总额度在使用同一 Redis 数据库的后端间共享。
- 两个计数各以首次成功预留为起点，在 60 秒后过期。用户和服务均有足够额度时一次增加两个计数。超限不增加计数，以受限计数中最晚的过期时间计算整数秒，返回 429 和 `Retry-After`。Redis 不可用、状态异常或配额配置无效时返回 503。
- `AI_QUOTA_ACTOR_PER_MINUTE` 默认 20，`AI_QUOTA_SERVICE_PER_MINUTE` 默认 120。两者接受 2～100000 的十进制整数。连接同一环境的各后端应使用同样的配额值及 Redis 数据库。开发、测试和部署环境沿用各自的 Redis 配置。
- 问答、写作和审核每次预留一次推理额度，群运营一次预留两次。各入口先校验适用的权限、会话、Skill、资料及模型配置，再于第一次推理前预留。预留被拒绝时不会调用模型。后续取消、推理失败或资料失效仍计入本窗口，下一窗口自动恢复。
- Nuxt Web 和 Flutter 在生成请求遇到 429 时保留已有会话内容，显示 `Retry-After` 给出的等待秒数。重试由用户发起。
- Redis 键只包含账号数字标识、版本和计量范围，值只有短期计数。草稿、素材、模型密钥及工具参数均不进入配额记录。频率与日志审计由各自的机制管理。
