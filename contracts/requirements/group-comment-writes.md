# 群评论写入

- 创建、删除、点赞和取消点赞均要求会话与正安全整数路径 ID。响应使用 `Cache-Control: private, no-store`。事务先锁定群组再检查群组可见性、帖子所属群组及评论所属帖子。
- 创建要求活跃群成员权限。请求体必须为不超过 1 MiB 的 JSON 对象，`content` 去除首尾空白后非空且最多 1000 UTF-8 字节。`parent_comment_id` 和 `reply_to_user_id` 可省略或为 null，否则须为正安全整数。
- 父评论须属于当前帖子且未删除。回复对象默认推导为父评论作者。直接评论可省略回复对象，若传入则须对应帖子作者。传入的回复对象与实际作者不符返回 422。
- 创建在事务中写入并回读完整评论，提交后返回 `group comment created`。删除只允许作者或活跃管理者，软删除后返回 `group comment deleted` 及 null 数据。
- 点赞和取消点赞只操作当前查看者自己的记录，重复请求幂等，返回事务回读的 `likes_count` 及最终 `is_liked`。
- Nuxt Web 和 Flutter 校验回执的 `comment_id`、布尔点赞状态和非负安全整数点赞数，按回执更新当前评论视图。同一评论防止重复提交，返回 404 时移除对应评论，切换会话、后端或评论视图后忽略旧回执。
- 创建评论、回复、点赞和取消点赞均要求帖子作者启用，且与操作者任一方向均无拉黑。回复的父评论作者、被点赞或取消点赞的评论作者执行相同检查。写入前检查一次，提交前重新检查，失效时返回相应的 404 并回滚。删除仍以作者或管理权限为准，管理者可处置不可见内容。
- 参数无效返回 400，归属不匹配、已删除或不可见返回 404，权限不足返回 422，写入或回读失败回滚并返回 500。
- 创建提交后通知仍能查看群组且启用了通知的帖子作者和父评论作者，去重并排除发起者。发起者、帖子作者和收件人须启用，收件人与发起者或帖子作者存在任一方向的拉黑时不投递。定位父评论须同时匹配帖子和有效状态。通知标识使用评论 ID，携带群组、帖子和父评论 ID。通知失败不影响本次评论结果。

Nuxt Web 与 Flutter 均可从评论发起回复。客户端发送父评论 ID，由后端推导回复对象。提交前按 UTF-8 检查回复正文的 1000 字节上限，提交期间禁止重复发送，并核对返回的帖子和父评论。Flutter 在输入区显示并允许取消回复目标；引用视图可回复当前评论，回复成功后保持原引用视图。

两端只向活跃成员开放创建评论和回复入口，服务端仍负责最终鉴权。Nuxt 群评论的正文用相同的 1000 UTF-8 字节上限，并在收到匹配回执后才清空输入。提交失败保留草稿，关闭再打开评论视图、切换帖子或会话后，旧提交回执不会应用到新视图。
