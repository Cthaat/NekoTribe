# 公开知识向量索引

三套后端可共用独立的索引进程。索引使用自己的向量模型配置，和问答、写作及 Agent 的对话模型各自管理。检索服务及构建命令位于 `scripts/knowledge-index/`，服务进程可独立运行。

## 索引与切换

- 构建任务从 Oracle 一次只读快照读取公开普通帖子、所属帖子公开的评论、公开且启用群的帖子与评论，以及当前发布的平台规则。作者必须启用，群评论同时检查所属群帖与作者。私信、私密群、用户资料、已删除或非公开内容不进入索引。规则目录须与当前 Oracle 权威版本相符；尚未发布或已停用的规则跳过，已发布但目录不符时停止构建。
- 保留现有来源版本算法。正文按 Unicode 码点切为每段 768 字符，重叠 128 字符，空白段跳过。向量库只保存向量、来源种类、来源 ID、版本和段序号。实际正文由业务后端现读。
- 每次构建创建一个全新的 Qdrant collection。构建命令验证写入总数及检索，再提交完工标记。激活命令核对配置指纹、数量和向量维度后，将新配置以同目录原子替换写入激活文件。在途检索继续用读取时的配置及 collection。回退时重新激活旧构建。模型、模型修订、维度或分块规则变化需要重新构建。
- 首版支持独立 OpenAI 兼容和 Ollama 向量端点。向量模型及向量库地址来自受控服务配置。部署人员使用固定模型制品和修订号，每个构建使用新 collection 名。

索引完成标记保存固定文本的探测向量。构建将同一探测文本与每批新内容一起编码，并检查探测结果。增量同步在复用旧向量前检查当前模型与旧集合是否匹配。激活、回退和检索会比较当前探测向量与标记中的向量。比较使用方向而非长度，允许 Qdrant 的归一化和少量浮点误差，要求余弦相似度至少为 `0.999999`。检索短语和探测文本在同一次模型请求中编码。校验失败时本次操作停止，当前激活配置保留。更换向量模型后应使用新模型修订号重新构建，再激活新集合。探针用于发现明显的模型漂移，部署仍需固定模型制品和修订号。

## 内部检索契约 v1

`POST /internal/v1/knowledge/search` 仅供后端调用。请求使用 `Authorization: Bearer <内部密钥>` 与 JSON `{ "query": "检索短语", "limit": 20 }`。短语 trim 后须为 1～256 UTF-8 字节，禁用控制字符，limit 为 1～20。

三后端在向索引发请求前校验短语与条数。调用已经取消时不发送请求，也不启动 Oracle 文本检索降级。

成功返回 `{ "version": 1, "candidates": [{ "kind": "post", "id": 42, "version": "64位小写十六进制" }] }`，按相似度顺序保留每个来源的第一个命中，最多返回 limit 项。所有后端均可接收 `post`、`comment` 和 `terms`，规则 ID 为 1～8。请求头 `X-Neko-Knowledge-Group-Sources: 1` 声明支持 `group_post` 与 `group_comment`。索引服务为旧后端在向量排序前排除两类群来源。候选不携带正文、群 ID、用户身份或模型配置。拒绝认证、参数错误、繁忙及依赖故障分别返回 401、400、429 和 503，所有响应禁用缓存。

成功响应使用无 BOM 的 UTF-8 JSON，字段名区分大小写。字段大小写错误或带 BOM 的响应按无效响应处理，不能触发文字检索降级。

请求头 `X-Neko-Knowledge-Chunks: 1` 启用可选的候选字段 `chunk`，取值为 0～102 的整数。字段仅用于当前问答中的段落定位，保留候选同一来源得分最高的分块序号。未发请求头的后端继续收到三个字段。未返回序号时沿用字面命中或正文开头的摘录规则。

业务后端须对候选重新读取 Oracle，按当前登录用户校验可见性及版本，并遵守推理后与写入前的既有复核。配置切换及回退也执行这项检查。

`GET /internal/v1/knowledge/ready` 使用同一内部令牌。它重新读取激活文件并校验 Qdrant 完工标记和精确点数，成功返回 HTTP 200 和 `{"version":1,"ready":true}`。配置或完工状态不可用时返回 503，缺少有效令牌时返回 401。响应禁用缓存，探针无需调用向量模型。每次搜索先读取完工标记和探测向量，再核对精确点数。集合不完整时直接返回 503。集合通过检查后才调用模型编码查询，并用探测向量确认模型兼容。业务后端按各自已配置的降级策略处理该错误。

问答按检索顺序发送能放入上下文预算的来源摘录。向量检索提供 `chunk` 时，从复核后的正文中按 `chunk × 640` 个 Unicode 码点定位，最多取 768 个码点。推理前逐个跳过偏移超出正文或选中空白片段的候选，保留其他有效候选的顺序。非空向量结果全部失效时，若已开启文本补查，则补查一次。预算不足时缩短或省略后续摘录。推理后的校验仍使用实际采用来源的完整正文和版本。

## 内容更新

`node scripts/knowledge-index/cli.mjs sync` 同步一次。`node scripts/knowledge-index/cli.mjs watch` 持续同步，成功后默认等待 900 秒，可通过 `AI_INDEX_SYNC_SECONDS` 设置为 60～86400 秒。首次失败后等 60 秒重试，连续失败时每轮加倍，最长等到正常同步间隔。一次成功即重置失败间隔。同步需要与构建相同的 Oracle、向量模型和 Qdrant 写权限。每个激活文件部署一个更新进程。

停止更新、构建或激活时，取消信号传递到 Qdrant 的集合创建、向量写入、数量和检索校验及完工标记请求。发布事务开始前收到停止信号时保留已有激活配置。已送达 Qdrant 的请求可能已执行，候选集合保留供检查或后续显式激活。发布事务一旦开始，会完成激活文件和日志的写入再退出。

`node scripts/knowledge-index/cli.mjs watch-status` 只读激活文件旁的 `.sync-status.json` 状态记录，可离线运行。`phase` 表示最近报告的同步中、回收中、等待或已停止状态，未有记录时为 `unknown`。`lastOutcome` 区分已发布更新、检查后无变化、失败及取消。时间字段为 Unix 毫秒，`lastSuccessAt` 在重启和后续失败时保留，`nextAt` 仅在等待时提供。记录不包含正文、模型配置、地址或凭据。强制退出可能留下旧状态，结合 `updatedAt` 和进程状态核查。状态写入失败只报告诊断错误，更新器继续工作。

构建、首次部署、校验、切换、激活、回退及同步命令通过标准错误流输出 `type: "index-progress"` 的结构化进度。阶段切换立即输出，持续的来源扫描和向量写入最多每十秒报告一次。可用计数包含来源数、已经确认写入的向量点数及其中复用旧向量的点数。进度不记录正文、来源标识、地址或凭据。标准输出保留原有结果格式，发布阶段的进度仍须以最终结果或退出码确认。

服务收到 `SIGINT` 或 `SIGTERM` 后关闭监听并等待已接收的请求结束。更新器收到信号后停止等待和后续同步，在扫描、嵌入及写入批次之间检查停止状态。已开始的发布事务和单个退役集合的删除与登记先完成。Compose 默认分别给检索服务 20 秒和更新器 60 秒停机时间。

同步检查当前 Oracle 公开来源及版本摘要。发现变化后建立新快照。向量模型配置保持一致时，按来源版本和分块序号复用旧向量，新内容和编辑后的版本才重新向量化。删除、取消公开和停用的来源不进入新集合。已有旧格式集合首次同步会完整重建。现有集合升级后可运行 `sync` 纳入新增群来源，同版本的旧来源可继续复用向量。回退到旧版检索服务前应切回支持的旧集合。

索引扫描在 Oracle 分页前按知识契约过滤来源 ID、所属帖子 ID 和群组 ID，允许范围为 1 至 999999999999999。越界记录不进入来源摘要或向量集合，其他公开来源仍可继续同步。

Qdrant 确认当前集合不存在、按 ID 查询完工标记成功但返回空列表，或在完工标记及模型校验通过后发现实际点数与标记记录不符时，`sync` 和 `watch` 从 Oracle 快照重建。精确点数包含一个完工标记。恢复不复用旧向量，只有新集合验证通过且激活配置仍匹配时才发布。成功日志用 `recoveredMissingCollection: true` 表示集合不存在，用 `recoveredIncompleteCollection: true` 表示集合存在但不完整。网络故障、鉴权错误、无效响应、模型不匹配或已有标记无效时停止当轮同步。回收仍要求已有集合通过其完工标记校验。只有点数、来源快照摘要和激活配置都匹配时，才报告无变化。

同步或核对失败时保留已激活的集合。人工激活、回退和自动发布共用激活文件旁的锁。人工激活在探测前读取当前配置指纹，回退在选取退役集合时同时读取当前指纹。若构建或核验期间当前模型或集合已切换，发布返回 `ACTIVE_PROFILE_CHANGED`，保留最新配置。进程若在发布时异常退出，确认没有写入进程后可移除遗留的 `.lock` 空目录。

影响集合登记的发布先写入 `.publication.json`，再原子替换激活文件，最后补写集合登记并清除发布日志。异常退出后在确认写入进程已退出并处理遗留锁的前提下，可以执行 `node scripts/knowledge-index/cli.mjs recover`。激活文件已指向新集合时补齐登记，仍指向旧集合时放弃该次发布。激活文件与日志中的前后版本均不匹配时保留日志并报错。同步、回退和回收也会在持锁后处理待恢复的日志。恢复只协调本地元数据，未激活的构建仍按现有流程由运维管理。

自动同步采用 Oracle 快照扫描，向量计算仅针对变化内容。后续构建留下的旧自动集合登记于激活文件旁的 `.collections.json`，可用 `rollback <collection>` 重新验证并激活。人工命名的集合和未发布的失败集合由运维管理。

`prune` 预览回收名单，`prune --apply` 执行。持续更新进程可显式设置 `AI_INDEX_AUTO_PRUNE=1`，在一轮同步成功后执行回收。默认保留最近退役的两个集合，并保护退役未满七天的集合。可通过 `AI_INDEX_KEEP_RETIRED`（1～100）和 `AI_INDEX_RETENTION_DAYS`（1～365）调整。回收期间持有激活锁，排除当前集合，删除前校验退役集合的配置标记。曾经删除成功但尚未更新登记的集合可在下次回收时清除登记。

缺少或不匹配完工标记的退役集合保留登记，并在 `skipped` 中报告集合和原因。回收继续处理其余符合条件的集合。手动执行 `prune --apply` 时，存在跳过记录则输出结果并返回非零退出码。自动更新器写出跳过记录并继续下一轮同步。网络故障或无效依赖响应停止本次回收，已确认的移除会保留在登记中。

使用回收时，所有检索进程须读取同一个激活文件，或共用读取该文件的检索服务实例。需长期保留的集合用人工构建的配置管理。回收只管理该激活文件登记的集合，部署者负责将激活文件与集合登记一并备份。

## 配置和启动

首次部署可在设置 `AI_INDEX_ACTIVE_PROFILE` 后运行 `node scripts/knowledge-index/cli.mjs bootstrap <profile.json>`。未激活时按初始配置构建并核验集合，再原子激活。集合已经构建完成且匹配时可直接验证并激活。已有激活配置时核验当前集合完工标记和精确点数，集合不完整则返回 `INDEX_INCOMPLETE`，由同步或显式发布恢复。构建或核验期间有其他进程完成激活时保留其配置。已有但未完成的同名集合保留供排查，修复原因后用新的集合名重试。换模型或切换现有索引继续使用 `build` 和 `activate`。

已有激活配置时也可运行 `switch <profile.json>`，一次完成候选集合的构建、验证和发布。命令在构建前固定当前激活指纹，使用候选向量模型完整重建，不复用旧集合向量。已封存的候选可重新验证并发布。若构建期间其他进程发布了更新，则保留当前配置，可核对后重试同一候选。与当前配置完全相同的重复调用只检查完工标记和精确点数。修改模型时须使用不同集合名，同名不同配置返回 `INDEX_COLLECTION_IN_USE`。

`verify [profile.json]` 单独执行激活流程使用的校验，包括模型探测、配置指纹、精确点数和试检索。省略参数时校验 `AI_INDEX_ACTIVE_PROFILE`，并在结束前确认激活配置未变化。成功输出 `verified: true`、集合名和向量点数。校验只访问模型端点和 Qdrant 读接口，不写集合、激活文件或集合登记，也不连接 Oracle。

- Qdrant 地址使用 `AI_INDEX_QDRANT_URL`，令牌使用 `AI_INDEX_QDRANT_KEY`。构建身份需要写权限；检索进程可使用只读密钥。向量提供方密钥使用配置指定的 `AI_EMBEDDING_KEY_*` 环境变量。保留模型的准确 ID，服务返回的模型名、向量数量和维度必须与配置一致。
- 配置示例为 `{ "version": 1, "collection": "neko_knowledge_20261118_a", "adapter": "ollama", "baseUrl": "http://127.0.0.1:11434", "model": "your-embedding-model:version", "modelRevision": "your-pinned-revision", "dimensions": 768, "keyEnv": null }`。使用实际模型维度。选择 `openai-compatible` 时，基址包含服务的 API 前缀，例如 `/v1`。
- 构建进程使用 `AI_INDEX_ORACLE_USER`、`AI_INDEX_ORACLE_PASSWORD`、`AI_INDEX_ORACLE_CONNECT`。在有当前 Oracle 驱动和条款目录的 Nuxt 源码目录运行 `node scripts/knowledge-index/cli.mjs build <profile.json>`。构建帐号需能读取同一业务数据的 `n_posts`、`n_comments`、`n_users`、`n_groups`、`n_group_posts`、`n_group_comments` 和 `n_ai_terms_active`。构建和同步排除停用作者的帖子及评论（评论的父帖作者也须启用）。拉黑关系由各业务后端按当前查看者复核。
- 部署时可运行 `node scripts/knowledge-index/cli.mjs check-sources`，独立包使用 `node --env-file=.env.updater index.mjs check-sources`。该命令仅使用 Oracle 只读事务，通过不返回正文的查询检查四类内容来源的表、字段及访问权限，并用同一事务核对当前已发布规则目录。规则未发布或已停用时报告 `published:false`。输出限于来源类别和固定错误码，任一检查失败时退出非零。
- 每次新建候选集合前，构建器执行同一 Oracle 源检查。来源结构、读取权限或规则目录校验失败时返回 `ORACLE_SOURCES_NOT_READY`，可用 `check-sources` 查看来源结果。检查通过后关闭预检事务，构建阶段另开只读事务读取内容快照并重新校验规则。运行中发生的后续故障按候选集合恢复流程处理。
- 设置 `AI_INDEX_ACTIVE_PROFILE` 为私有目录下的激活文件路径，再运行 `node scripts/knowledge-index/cli.mjs activate <profile.json>`。回退时把参数改为旧的构建配置。同一检索进程每次请求固定所读配置，切换无需重启。
- 设置至少 32 个可打印非空格 ASCII 字符的 `AI_INDEX_SERVICE_TOKEN`，运行 `node scripts/knowledge-index/cli.mjs serve`。默认监听 `127.0.0.1:3818`，可用 `AI_INDEX_HOST`、`AI_INDEX_PORT` 配置。跨机部署把服务放在私有网络、TLS 或反向代理之后。
- 检索进程启动时校验本地配置及已有的激活文件。配置的激活路径尚无文件时，检索进程可先监听。首次激活完成前，就绪与检索请求返回 503，且不访问 Qdrant 或向量模型。Qdrant 暂时不可用或集合未就绪时也返回 503。激活文件发布或依赖恢复后，后续请求重新读取配置并检查集合，无需重启。激活路径未设置或已有激活文件无效时，启动失败。
- 各业务后端设置 `AI_KNOWLEDGE_INDEX_URL` 和与索引服务一致的 `AI_INDEX_SERVICE_TOKEN`。该地址为空时使用 Oracle 文本检索。配置了索引时，默认在服务故障时返回 503。
- 非空检索地址沿用模型服务的 HTTP(S) 地址格式，上限为 2048 字节。允许显式端口和反代路径前缀。配置中的凭据、查询、片段和未编码空白无效，即使启用了文字降级也在发送请求前拒绝。
- 同一 Docker 主机可通过可选 Compose 附加文件，将独立项目的检索容器与 Nuxt、Go、Rust 接入同一个外部桥接网络。检索端口仅供该网络访问。各后端在保留原依赖网络的同时统一使用 `http://knowledge-index:3818`，仍需提供匹配的令牌。独立环境使用不同网络名。

需要在索引中断时保持问答可用的部署，可以在三后端设置 `AI_KNOWLEDGE_INDEX_FALLBACK=lexical`。未收到响应头的网络错误或索引请求超时，以及 HTTP 429、502、503、504，可改用同一检索短语执行现有 Oracle 文本检索。取消、配置错误、重定向、鉴权失败、无效或读取不完整的响应、有效的空结果均保持原处理。降级只影响这次候选查询，下一次请求重新尝试索引。Oracle 文本候选仍按现有权限、来源版本和上下文预算规则处理。客户端继续使用同一问答接口。

启用同一设置后，若索引返回了有效的非空候选批次，但实时权限和版本复核未留下任何候选，本轮在推理前用同一短语补查一次 Oracle 文本检索。补查候选继续使用当前账号的权限和正文版本，复核通过后才进入推理，推理后及保存前继续复核。只要有一个索引命中通过复核就沿用有效命中。数据库查询异常、候选格式错误或推理后的资料失效继续按原规则处理。
