# 帖子审核处置

`POST /api/v2/moderation/content/{post_id}/actions` 与 `POST /api/v2/moderation/content/bulk-actions` 要求有效会话和既有审核权限。响应设置 `Cache-Control: private, no-store`。单帖返回完整队列条目，批量返回 `processed_count`。

- 单帖支持 `approve`、`reject`、`flag`、`remove`、`restore`、`claim`、`release`。批量支持前五项。省略动作沿用 `flag`。无效动作或参数返回 400。
- 帖子 ID 是正安全整数，数组中也可用无前导零的十进制字符串。批量要求 1 至 100 项，锁定前按 ID 去重并升序校验全部目标。目标不存在时返回 404。备注和原因须为字符串，去掉首尾空白后最多 1000 和 200 个 UTF-8 字节。
- 启用 `require_note_on_reject` 时，`reject` 和 `remove` 要求非空备注。禁用 `allow_moderator_claim` 时，领取或释放返回 403；其他审核员已领取时返回 409。缺省设置沿用系统种子值。
- 已确认的动作语义延续原规则。`approve` 和 `remove` 软删除帖子，`reject` 和 `restore` 恢复帖子，`flag`、领取和释放不改帖子删除状态。案件和关联举报更新对应状态，进入非终态时清除解决时间。每个成功处置写入一条审核记录。
- 帖子锁、必要时建案、更新帖子和举报、记录审计及单帖结果读取在同一 Oracle 事务完成。任一目标、写入或读回失败则回滚全批。同一批内重复 ID 只处理一次。重复发送整个请求仍可生成新的处置记录。
- Nuxt Web 拒绝动作打开备注表单，校验失败保留草稿。Flutter 拒绝前可填写备注。两个客户端可在审核队列手动勾选至多 100 条帖子，确认动作及备注后调用同一个批量接口。刷新、筛选条件变更或切换会话清空选择，旧会话表单无法提交。成功后展示服务端处理数并重读队列，失败保留草稿供检查。
- 审核队列展示服务端返回的领取人。未领取的待审或标记案件可领取，当前审核员可释放自己领取的同类案件。写入仍以服务端的设置和权限为准，成功或收到 409 后重读队列。客户端切换会话时丢弃旧结果。
- 隔离验证覆盖权限、输入、审核配置、去重、锁顺序、事务读回和批量审计失败。真实 Oracle 的通用锁、并发、时间边界和客户端部署矩阵待验收。
