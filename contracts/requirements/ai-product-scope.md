# 三组 AI 产品共同范围

用户已确认三个方向全部纳入、首期仅使用公开帖子、评论、平台规则，模型可切换。知识问答和写作已有原生端点，真实模型与部署组合仍待验收。

## AI-KNOWLEDGE-WRITING：知识问答与写作

- 仅已登录用户可调用，按账号和服务资源配置配额。普通用户不能提交任意提供方 URL、模型密钥或系统工具权限。
- 知识回答检索当前仍公开且可访问的帖子、评论、规则，给出可核对的来源；证据不足时明确说明，不捏造帖子/引用。
- 写作、润色、标签和长讨论总结产出草稿或建议，由用户决定发布；正式发布继续通过正常业务权限和校验，不由模型绕过。
- 问答和写作输入显示本次消息的 UTF-8 字节数。写作模式指令与正文分隔符计入 65536 字节上限，检索词按自己的独立规则计算。超限时保留草稿并禁用发送，缩短至上限后可以继续。
- 两端可从公开帖子的完整详情进入总结模式。只把非空正文和最多 20 条已加载、确实属于该帖的可见评论加入可编辑草稿，总计最多 16 KiB UTF-8。不复制附件、账号资料或私密内容。文本只在客户端内存传递，进入写作页面不会调用模型或保存会话，用户提交后才开始现有写作流程。
- 普通公开帖和公开群动态的完整讨论采用同一刷新规则。客户端按当前排序重新读取评论首页，只带入此前已加载、仍在该页且属于该帖的唯一评论，采用刷新后的正文。随后重新读取帖子并核对可见性和归属，群动态同时复核群组仍公开。非公开内容、单评论定位页或重新读取失败时不带入内容。
- Nuxt Web 与 Flutter 可手动复制可见的助手回复。写作回复不超过 280 个 UTF-16 代码单元时可选「用作帖子」，把正文一次性带入普通发帖编辑器；正文不写入 URL，仍需用户确认发布。切换身份或 Flutter 后端会清空已带入的草稿。较长回复可复制后手工编辑。
- 登录用户可在发帖编辑器内打开写作助手，只将当前正文带入内存中的可编辑输入。有正文时默认选择润色，空稿保留普通写作模式。打开不提交或发起推理。用户可手动将不超过 280 个 UTF-16 代码单元的非空回复用到原编辑器。仅替换正文，保留附件、可见范围、位置、手动话题和回复或引用对象。关闭助手保留原稿。会话、编辑目标或 Flutter 后端已经变化时不应用旧结果。
- 用户在当前请求主动输入的写作文本可作为这次生成材料，但不自动进入平台知识库或训练集。平台私信、私密群内容不在首期检索/训练范围。
- 来源编辑、删除、改权及引用读取须正确失效；不同用户缓存不能跨权限泄漏。

## AI-GROUP-AGENT：群运营 Agent

- 仅目标群的群管理员可使用。身份/群管理权限由当前选定后端的真实权限逻辑判断，不由模型提示词或前端角色字段决定。
- 首期工具仅检索已批准的公开内容、计算公开内容相关统计，支持生成周报、FAQ、公告和活动策划草稿。群私密讨论及其衍生统计后续接入。
- 群公告发布、删帖、成员处置等实际操作必须由管理员明确确认并经正常业务 API 鉴权/审计；首期不授予 Agent 无限制管理员能力。
- 每项工具有结构化输入、超时/取消、调用次数与资源上限，记录结果与失败状态。来源内容中的指令不改变工具权限。

群运营公开资料读取在三个后端共用同一份 Oracle 查询，详见 ai-group-evidence.md。三后端已接通模型发起的一轮只读工具调用、草稿生成和会话保存，见 ai-group-draft.md。Nuxt Web 和 Flutter 已接入群管理中的草稿生成、历史、工具记录、引用、删除及人工确认发布。真实服务验收待统一测试。

## AI-MODERATION-AID：审核辅助

- 仅具有平台审核权限的人员使用；输入限首期公开内容及有效规则。
- 输出风险类别、相关内容/规则引用、简短判断依据及处置建议。记录模型/配置版本，便于核对误判与申诉。
- 模型结论只是辅助，不能仅凭一次生成就自动封禁、删除或处置用户；正式处置继续走人工确认、权限和审计流程。
- 反馈与纠正用于评测；进入训练数据须另行授权、清洗与审核，不把模型输出或普通点赞直接当正确训练标签。

Nuxt、Go、Rust 已接通审核建议生成和持久化，当前采用已公开的正文和规则。Nuxt Web 和 Flutter 的内容审核及举报队列已接通按目标生成建议、恢复历史和查看规则引用。真实服务验收待统一测试。见 ai-moderation-advice.md。

审核反馈已有共享评分契约、显式存储迁移和按模型配置版本分组的离线汇总。三个后端已原生接通评分写入与历史评分，两客户端已接入评分与恢复。见 ai-moderation-feedback.md。

## 公共要求

三后端实现相同业务契约。Nuxt Web 和 Flutter 使用共同入口，由各自相连的后端处理鉴权与错误。模型切换见 `ai-model-switching.md`。平台已统一旧情感分析接口的停用响应和客户端入口，独立 Python 服务、源码和历史模型数据供原有用途保留。迁移细节见 `sentiment-retirement.md`。

四个 AI 生成入口共用账号和服务级 Redis 配额，见 [AI 推理配额](ai-model-quota.md)。

群运营及审核建议共用失败、取消、限额及完成事件约定，见 [AI 运行审计](ai-run-audit.md)。
