# 三组 AI 产品共同范围

用户已确认三个方向全部纳入、首期仅使用公开帖子/评论/平台规则、模型可切换，以及以下权限分配。本文件登记产品行为，尚无产品端点或真实模型验收；配置组件单元测试不能代替这些要求。

## AI-KNOWLEDGE-WRITING：知识问答与写作

- 仅已登录用户可调用，按账号和服务资源配置配额。普通用户不能提交任意提供方 URL、模型密钥或系统工具权限。
- 知识回答检索当前仍公开且可访问的帖子、评论、规则，给出可核对的来源；证据不足时明确说明，不捏造帖子/引用。
- 写作、润色、标签和长讨论总结产出草稿或建议，由用户决定发布；正式发布继续通过正常业务权限和校验，不由模型绕过。
- 用户在当前请求主动输入的写作文本可作为这次生成材料，但不自动进入平台知识库或训练集。平台私信、私密群内容不在首期检索/训练范围。
- 来源编辑、删除、改权及引用读取须正确失效；不同用户缓存不能跨权限泄漏。

## AI-GROUP-AGENT：群运营 Agent

- 仅目标群的群管理员可使用。身份/群管理权限由当前选定后端的真实权限逻辑判断，不由模型提示词或前端角色字段决定。
- 首期工具仅检索已批准的公开内容、计算公开内容相关统计、生成该群周报/FAQ/公告草稿。群本身的私密讨论及其衍生统计后续接入，不从索引或工具偷偷扩大数据范围。
- 群公告发布、删帖、成员处置等实际操作必须由管理员明确确认并经正常业务 API 鉴权/审计；首期不授予 Agent 无限制管理员能力。
- 每项工具有结构化输入、超时/取消、调用次数与资源上限，记录结果与失败状态。来源内容中的指令不改变工具权限。

## AI-MODERATION-AID：审核辅助

- 仅具有平台审核权限的人员使用；输入限首期公开内容及有效规则。
- 输出风险类别、相关内容/规则引用、简短判断依据及处置建议。记录模型/配置版本，便于核对误判与申诉。
- 模型结论只是辅助，不能仅凭一次生成就自动封禁、删除或处置用户；正式处置继续走人工确认、权限和审计流程。
- 反馈与纠正用于评测；进入训练数据须另行授权、清洗与审核，不把模型输出或普通点赞直接当正确训练标签。

## 公共要求

三后端分别实现相同业务契约，Nuxt Web/Flutter 使用同样业务入口；保留独立 Python 服务，三后端统一接入、鉴权和错误处理，不能依赖 Nuxt 业务进程。模型可替换见 `ai-model-switching.md`。旧情感分析功能的退役是独立迁移任务，不要求 Rust/Go 补写旧情感预测/训练功能，也不等于删除 Python 服务、源码或现有模型数据。当前旧 API 尚在，版本化迁移时同步修改路由、规范、副本、调用与部署，不能仅删除面板就记为完成。
