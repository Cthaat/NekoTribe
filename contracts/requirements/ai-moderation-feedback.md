# 审核建议反馈与离线评测

Nuxt、Go、Rust 已原生接通评分写入和历史评分字段，并共用 Oracle 增量迁移与离线评分汇总。Nuxt Web 和 Flutter 的审核助手已接通评分和历史恢复。

审核员可为自己的可见建议标记有帮助（`helpful`）、有误（`incorrect`）或依据不足（`insufficient`）。每条助手建议只有一个当前评分。重复提交相同选择不增加样本，也不更新修改时间。三种标签为结构化人工反馈，禁止附带正文、举报内容、人工意见、账号信息或模型提示。评分与已确认的案件处置各自独立。

接口为 `PUT /api/v2/ai/conversations/{id}/messages/{message_id}/moderation-feedback`，仅接受 `{"rating":"helpful"}` 一类的单字段 JSON 对象。成功回执的数据为 `{"message_id":"<uuid>","rating":"helpful"}`。非法请求体返回 400，匿名调用返回 401，当前审核权限不足返回 403。未知会话、他人会话、非审核会话、其他会话消息及非助手消息返回 404。已失效建议返回 409。反馈表未就绪或存储错误返回 503。

同一事务锁定用户自己的审核会话，核对当前审核权限、目标消息及其来源和规则版本。共享 `queries.save` 的受影响行数为 0（同值重放）或 1（插入或更新）。提交前复核权限及建议可用性，失败回滚。历史中只在建议仍可展示且已评分时返回同一消息的可选字符串 `moderation_feedback`。反馈表尚未迁移时省略此字段，继续返回原有建议。写入及历史响应使用 `Cache-Control: private, no-store`。

两个客户端在仍有效的建议下显示三个评分选项，并标记已保存项。同一目标的历史可能来自多个会话，客户端按该条建议所属会话和消息 ID 保存。验证写入回执后，按原序号重新读取这一条建议。只有消息身份、目标、可见性和评分都匹配时才显示成功，并保留当前已加载的历史和游标。提交期间暂时禁用相关操作。记录失效或保存结果不确定时清除已展示的建议，审核员可刷新历史核对。账号切换或 Flutter 更换后端时取消请求、清除记录。

`n_ai_moderation_feedback` 通过消息主键外键随会话及消息删除，无独立正文副本。开发及部署共用 Nuxt 的显式 Oracle 迁移工具。版本追溯来自原建议消息的 `model_id`、`model_version` 和 `config_revision`，由服务端生成。

从 Nuxt 目录运行 `node scripts/ai-moderation-feedback-report.mjs --print-query` 查看只读汇总 SQL。请在有权访问评测数据的环境执行查询，将结果保存为 JSON 数组。运行 `node scripts/ai-moderation-feedback-report.mjs <汇总文件>` 输出按模型和配置版本分组的分类计数、样本数及有帮助占比。该占比只使用已评分建议，属于审核员主观反馈。未知模型身份、缺少有效配置版本的记录不进入评测。历史意见只在汇总计数中使用，建议失效后的原文和引用仍受会话历史保护。原建议删除后其评分不再参与新报告。

评分汇总用于评测、回归和人工复核。将材料用于训练需另行授权、筛选并审核，报告不会触发写入、重新推理或自动训练。
