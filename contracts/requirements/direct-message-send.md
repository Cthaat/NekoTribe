# 发送私信

`POST /api/v2/chat/direct-conversations/{conversation_id}/messages` 使用当前认证用户。会话 ID 按私信历史规则解析，仅未删除会话的参与者可以发送。收件人必须是该会话的另一位活跃用户。任一方拉黑对方时拒绝发送。仅在收件人允许陌生人私信、关注发送者、与发送者互关或同属活跃群时允许发送。

内容去掉首尾空白并要求非空，按当前 Oracle `VARCHAR2(4000)` 的字节容量验证，超出时返回 40001。会话无权访问或收件人拒绝时返回 40301，收件人不存在或停用时返回 40401。响应使用私信消息 DTO 和 `direct message created` 消息。

消息、会话摘要、发送者已读位置和符合收件人偏好的收件通知应在一个事务内提交。通知类型偏好决定是否存储通知，全局推送偏好决定是否实时推送该通知。提交前不发布事件。提交后将 `direct_message` 定向给双方的本机连接及用户 Redis 频道；远端失败不撤销提交或阻止本机投递。同一连接仅在收到完全相同的本机已入队事件回声时去重。

发送者的已读位置与历史读取共用更新规则，取原位置和新消息 ID 中的较大值。

两客户端只使用公共实时协议的 `direct_message` 事件更新私信消息。外层 `data.conversation_id` 须与内层消息一致，会话、消息及作者 ID 均为 JSON 正安全整数。消息必须包含文本、创建时间及明确的未删除状态。格式错误或会话归属冲突时忽略事件。

发送不自动重试。发送路径绕过查询缓存，每次读取当前收件权限与偏好。两客户端校验回复中的会话 ID、有效消息 ID、未删除状态和去除首尾空白后的发出内容。发送失败保留当前草稿，只有同一会话中的发送获得确认且草稿未被改动时才清空。过期响应不更新当前聊天。真实 Oracle、Redis 和六种前后端组合待验收。
