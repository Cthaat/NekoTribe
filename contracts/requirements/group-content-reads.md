# 群帖子和评论读取

- 三个读取端点都要求有效会话和正安全整数路径 ID。只读取活跃、未删除且对当前用户可见的群组。公开群组可直接阅读，私密和隐秘群组要求活跃成员身份。
- 帖子须属于路径群组且未删除，评论须属于路径帖子且未删除。不存在、不可见或归属不匹配返回 404。语法或枚举无效返回 400。
- `GET /api/v2/groups/{id}/posts` 按置顶、公告、普通依次分层，每层按创建时间及 ID 降序。`type` 默认为 `all`，也可选 `pinned` 或 `announcement`，筛选先于计算总数和分页。
- `GET /api/v2/groups/{id}/posts/{post_id}` 返回单个帖子，`meta` 为 null。它不受列表筛选影响。
- `GET /api/v2/groups/{id}/posts/{post_id}/comments` 支持 `sort=newest|oldest|popular`。默认按创建时间、ID 降序。最早按时间、ID 升序。热门按点赞数降序并用最新顺序打破并列。
- 帖子与评论查询过滤停用作者及查看者与作者之间任一方向的拉黑。父帖不可见返回 404。列表与总数使用同一过滤条件。被回复用户停用或与查看者存在任一方向的拉黑时，保留可见评论并返回空的被回复用户。
- 可选 `comment_id` 为规范十进制安全正整数，重复或格式无效返回 400。精确读取固定第一页且每页一条，只有属于路径群组和帖子、符合评论可见性的目标才返回。目标缺失、已删除、被过滤或属于其他帖子时返回 200、空数组和总数 0。
- 列表在同一条 SQL 里判断可见性，计算总数并截取当前页。空结果和越界页仍返回有效分页信息和空数组。
- 响应保留作者公开资料、帖子媒体和查看者点赞状态。评论保留父评论 ID 和被回复用户，`can_delete_by_me` 仅对作者或活跃的群组管理者为 true。响应带 `Cache-Control: private, no-store`。

两个客户端的全部群组动态读取已加入群组的全部成员列表页，再合并各群组动态的分页结果。全局顺序与单群接口相同：置顶、公告、普通分层，各层按创建时间及帖子 ID 降序。加载更多会继续读取各群后续页，不受单次请求的页容量限制。改变群组或类型时从第一页开始；置顶或删除成功后重读，避免继续使用旧分页边界。

两端识别 `/groups/posts?group=<群组 ID>&post=<帖子 ID>`，可选 `comment` 定位评论。群组和帖子 ID 必须各出现一次且为规范正安全整数。链接直接读取指定资源，不依赖目标是否在已加载列表里，仍由后端校验会话、群组可见性和资源归属。Nuxt Web 复制链接时只保留目标群组和帖子。Flutter 登录及双因素验证后只继续到根据合法数字重建的站内目标。

Flutter 帖子详情可复制分享链接，定位评论时保留该评论 ID。部署者可用独立的 `groupPostShareBaseUrl` 指向同一社区的 Nuxt Web 地址，禁止从当前 API 地址推导分享地址。未设置时 Flutter Web 使用当前部署入口与站内路由，Flutter 原生版提示配置。链接只含定位目标，不含帖子正文、会话、其他页面参数或凭证。

两端群评论列表使用服务端的最新、最早、热门排序和分页。切换排序重读第一页并作废旧响应；加载更多保留当前排序，并按评论 ID 合并。新增、删除或热门排序下点赞成功后重读评论，避免沿用变化前的顺序。单条引用视图保持精确查询，返回全部评论后才显示排序和分页。
