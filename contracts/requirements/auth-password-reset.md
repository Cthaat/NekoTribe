# 密码重置的共同兼容行为

本文件定义从 Nuxt 现有接口提取的过渡行为，用于三后端对齐，并非安全增强或最终验收。`POST /api/v2/auth/password-reset` 是公开接口，不能依赖另一个后端进程。

1. 按顺序读取 `email`、`verification_id`、`code`、`new_password`；按 v2 标量字符串规则转换并去除首尾空白，任意字段为空返回 400 `<字段> 不能为空`。支持现有 JSON 和表单输入。
2. 直接按邮箱、用途 `password_reset`、验证码标识查尚未过期的 OTP，不要求先访问独立验证码校验接口。无记录返回 400 `验证码不存在或已过期`；bcrypt 不匹配返回 401 `验证码错误`。校验成功后写入并读取 `verified_at`，读取结果即使为空也不妨碍继续；写入与读取失败均安全返回 500。
3. 用 bcrypt 成本 10 生成新密码哈希（与 Nuxt 一样按 UTF-8 前 72 字节计算）；按邮箱绑定参数更新用户，零行返回 404 `用户不存在`，成功返回 `{code:200,message:"password reset success",data:null,meta:null}`，不设置 Cookie。不得把密码、验证码、内部异常或连接信息输出到响应与日志。
4. 现有数据库操作逐项提交，OTP 标记可能先于用户更新失败；不能误称本流程原子。当前兼容规则既不消费 OTP，也不撤销现有会话。它们是需要三端共同修复的安全缺口，不能视为最终安全设计；另需统一限流、密码强度、并发和错误信息策略。

`scenarios/auth-password-reset.json` 保存合成的隔离用例，覆盖校验顺序、不同 OTP 状态、数据库失败及副作用。真实 Oracle、并发、会话安全、跨后端登录和 Windows/Linux 跨机器部署必须另行验收。
