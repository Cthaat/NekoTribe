# 帖子评论点赞共同需求

`POST` 和 `DELETE /api/v2/comments/{id}/likes` 要求有效会话与规范安全正整数 ID，响应 `private, no-store`，内部错误脱敏。评论和所属帖子必须未删除，两个作者均须处于启用状态。帖子必须对当前用户可见，当前用户与评论作者之间任一方向均不能存在拉黑关系。条件不成立时返回 404 `评论不存在`。

点赞或取消前查询可见评论；写入语句本身再次检查上述条件并绑定当前用户和评论 ID。点赞已存在、取消未存在均可重复执行；零行时重新检查可见性，不可见返回 404。随后读取点赞数时再次限定可见性；无统计行时为零。成功返回 `success`、`comment_id`、目标 `is_liked` 和当前 `likes_count`。首次新增点赞向评论作者发送 `like` 通知；本人、通知类型和推送偏好沿用统一通知规则，重复点赞和取消点赞不发送。元数据包含 `post_id`、`target_post_id`、`comment_id`、评论及帖子摘要和 `comment_like` 事件；摘要沿用 160 个 UTF-16 单元规则。

发送通知前按相同条件读取评论摘要。如果此时评论已不可见，跳过通知。点赞写入、统计读取和通知分开提交，写入后失败时点赞可能已生效。Redis 发布失败只降级推送。并发唯一约束、触发器、统计、真实 Redis 与双客户端在隔离环境统一验收。

Nuxt Web 和 Flutter 的普通帖子详情及精确评论引用页支持点赞和取消点赞。单条评论一次只允许一个请求，成功后以服务端的状态和计数更新展示，收到 404 时移除该评论。账号或后端切换后丢弃旧会话的回执。
