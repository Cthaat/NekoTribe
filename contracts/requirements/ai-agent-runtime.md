# Agent、知识库、上下文与 Skills 共同需求

状态：需求登记，尚未实现或验收。用户明确要求知识库检索、对话上下文持久化和 Skills 等完整 Agent 能力；三个业务方向、角色权限及首期公开数据范围见 `ai-product-scope.md`，可切换模型要求见 `ai-model-switching.md`。本文件是三后端共同目标，不把现有模型配置和单次推理传输称为 Agent。

## 用户可用能力

1. 登录用户使用知识问答/写作，目标群管理员使用群运营 Agent，平台审核人员使用审核辅助；角色和内容权限由当前所选后端检查。Nuxt Web 与 Flutter 使用统一业务接口，无需根据后端语言编写不同业务流程。
2. 知识库首期接入公开帖子、评论和平台规则，数据入库及检索按当前可见性过滤。每条可引用资料有稳定来源标识、版本和引用入口；内容新增/修改/删除或变为不可见后，检索和引用不能继续暴露过期内容。资料不足明确说明，不编造来源。私信和私密群不默认入库，后续单独授权和实现。
3. 支持多轮对话：会话、消息、必要的工具调用结果和状态可持久化、按用户/群授权读取，支持列出、恢复和删除；使用模型上下文窗口、输出预算、历史裁剪或摘要等机制处理长对话。摘要不能扩大原有权限或伪造来源；数据保留和删除策略需明确。模型服务地址和凭据不暴露给普通用户。
4. Skills 是可版本管理、明确授权的任务能力包，定义说明、适用场景、输入输出、可用工具和执行约束；包括知识问答/写作、群周报/FAQ/公告草稿、审核建议等首期能力。用户可显式选用适用 Skill；自动选择需记录选择结果和依据，不能越过用户/群权限。支持查看、启用/停用和版本变更；未知、禁用或无权 Skill 应明确拒绝。可加载的 Skill 内容来自受控来源，普通帖子或用户输入不得自行安装技能或改变系统权限。
5. Agent 以有限步骤组合模型和经过注册的工具：工具有结构化输入、独立鉴权、超时和次数限制；无效参数、不支持工具调用的模型、提供方失败、取消或超时均返回可理解的状态，不能把模型提议当作工具已执行。首期群运营只能检索已批准公开内容、获取公开统计及生成草稿；实际发布、删帖、成员处置等由有权人员明确确认并经正常业务接口执行与审计。
6. 各请求固定模型与配置版本；对话模型、向量模型独立配置。更换对话模型不得改写既有对话，更换向量模型/版本或分块规则需重建并验证新索引后切换。仅具备兼容协议的模型可直接配置切换，新增不兼容协议需要适配器；不能将填写模型名误称为模型可用。

## 可维护与验收

对话/知识/技能记录须通过统一版本化结构迁移和显式部署配置管理；三后端各自接入真实鉴权和业务数据，不依赖 Nuxt 进程。可共享独立的模型推理或检索基础服务，但不能绕过当前后端权限。用户消息与检索文本是不可信资料，不能修改系统约束、工具权限或其他用户的上下文。日志与审计记录模型、技能、来源和工具结果的必要元数据，不记录密钥或无必要的敏感正文。

`scenarios/ai-agent-runtime.json` 是待实现验收场景而非执行记录。最终需验证真实模型 A→B→A、知识更新与删除、跨账号/群隔离、对话恢复/删除、显式及自动 Skill 选择、工具调用/拒绝、取消/限额、人工确认、前端接入、Windows/Linux 和真实跨机部署。框架、向量索引/数据库选型及发布实施应以真实兼容性、资源和测试结果为依据；尚未决定或安装 LangGraph 等编排框架，也不声称真实模型、RAG 或 Skills 已可用。
