# 群运营草稿生成

`POST /api/v2/ai/conversations/{id}/group-generate` 接受 `kind`（`weekly_report`、`faq`、`announcement` 或 `activity_plan`）和 `expected_sequence`。读取现有会话消息后，客户端以最新序号请求生成，空会话使用 0。服务端绑定会话所有者与目标群，检查活跃公开群的活跃群主或管理员，验证已发布的 `group-brief` Skill 配置。

活动策划使用最近 30 天的公开材料，草稿包含活动目标、流程与分工建议。未有公开资料证实的日期、场地、负责人和预算标为待确认。管理员可在 Nuxt Web 和 Flutter 的草稿类型菜单选择活动策划，生成结果沿用草稿历史和人工审阅流程。

可选 `skill_id: "group-brief"` 显式选择该技能，省略时根据 `group` 会话用途选择。未知技能、其他用途的技能、空值和重复字段返回 400。两种选法共用当前权限、启用状态、工具授权及保存前复核。`ai.run` 记录选择方式与配置代数。

生成请求可选 `search_term`。Nuxt Web 和 Flutter 在群运营面板接受管理员输入，去首尾空白后发送，留空时省略。超过 256 UTF-8 字节或含 ASCII 控制字符时禁止提交。后端拒绝空值、重复字段和非法文本，初次资料检查按给定词筛选，未找到资料时直接返回资料不足。

首次检查确认有公开资料后，选择声明 `tools` 能力的 `agent` 模型。第一次推理接收草稿类型、可选检索词和 `group-brief` 授权的工具定义。模型须请求一次 `public_search`，也可在同一轮请求一次 `public_statistics`。`public_search` 接受空对象或仅含一个合规 `search_term` 的对象。管理员已给定检索词时，空对象沿用该词，替换词会被拒绝。`public_statistics` 仅接受空对象。群、时间窗口与可见性由后端根据会话和草稿类型确定。

验证整批提议后，重新检查会话所有权、群角色、会话序号和 Skill 代数，并读取当前公开资料。两个工具使用同一个快照。提供检索词时只筛选摘录，帖子数与评论数仍覆盖完整时间窗。摘录工具返回时间窗和摘录，统计工具返回时间窗、帖子数和评论数。群资料为空时返回 `{status:"insufficient_evidence",message:null}`。第二次推理按调用顺序收到对应结果，仅可生成草稿正文。参数异常、工具名越权、重复请求或再次提出工具调用返回 503。

两次推理共用固定模型和配置版本，复用推理传输的单次超时和取消处理。每次调用采用共用提示词和保守字节预算。三端使用紧凑 UTF-8 JSON 计量，保留普通 HTML 字符，转义 Unicode 行和段分隔符。超过预算时依次移除最早的摘录，仍放不下一条时返回 503。私密讨论、以往草稿或会话用户消息均不进入模型素材。

推理完成后，在会话写事务中重新验证群权限、序号、技能配置代数和公开资料快照。序号或快照变化返回 409。成功保存一条 assistant 消息，并通过 `{status:"generated",message:{message_id,conversation_id,sequence_no,role}}` 返回确认。发送前和保存前检查取消，提供方失败、取消、技能停用和配置不可用返回 503。请求和响应遵守既有认证和不可缓存约定。

保存的消息包含模式、窗口、资料摘要、实际采用的摘录数量、Skill 代数和草稿。新消息的 `tools_used` 记录成功调用的工具名及顺序，模型和配置版本由现有消息字段保存。缺少工具记录的旧草稿仍可恢复。有检索词的草稿在内部记录 `search_term`，历史和发布前按相同检索词复核。新记录同时以内部 `match_excerpt: true` 标记包含命中的摘录规则，旧记录按其原规则复核。响应和运行日志不新增检索词字段。摘要覆盖快照统计与实际提供给模型的摘录，使用 SHA-256 按 UTF-8 字节数加冒号的格式连接字段。字段顺序为版本标记 `group-evidence-v1`、窗口开始、窗口结束、帖子数、评论数，随后按查询顺序对每条摘录追加类型、来源 ID、所属帖子 ID 和内容。恢复时以同一窗口和摘录数量检索，当前权限或快照失效时隐藏草稿、引用和工具记录。通过复核且有工具记录的消息返回按调用顺序排列的 `group_tools`，Nuxt Web 和 Flutter 在草稿历史中显示工具名。

首次推理前一次预留两次调用额度，见 [AI 推理配额](ai-model-quota.md)。

Nuxt Web 与 Flutter 从群管理打开草稿页面，进入时刷新群状态和角色。两端只显示当前群的各页历史，恢复会话后用最后一条消息的序号生成。取消生成会终止等待并要求刷新，以便查明请求是否已经保存。切换登录身份或后端时，清空先前的数据并废弃在途结果。删除会话需显式确认，沿用会话删除接口。

打开、刷新或加载更早草稿时，若该会话的消息读取返回 404，移除失效会话和本地审阅状态，显示会话不可用。保留当前群、所选草稿类型、Skill 和检索词供用户主动开启新会话。此恢复过程只读历史，不会自动生成、发布或删除。其他错误继续按相应权限、连接状态和刷新规则处理。

加载更早草稿或更多会话时，临时请求失败或收到格式错误的分页响应，保留已加载内容、当前审阅输入和分页位置，可重试同一页。401、403 和确认会话失效的 404 继续按现有权限及会话规则处理。

客户端只有收到当前群的 `is_active: 1`、公开隐私状态和活跃群主或管理员角色时，才显示群运营入口并加载历史。停用、缺失或格式错误的启用状态不开放该入口。打开面板或主动刷新时重新核对，服务端继续在读取和生成时执行权限检查。

打开或刷新草稿会话时，两端先用 `before_sequence=10000000000` 读最近 50 条原始消息，按最新草稿在前展示。加载更早时用当前首条原始消息的序号作排他游标。继续生成仍使用最近一条的序号，包含已隐藏的占位。若旧服务忽略倒序游标并返回从 1 开始的满页，客户端沿用正向游标追到末尾，只保留最近 50 条。主动加载更早时，旧服务按正向游标读到排他边界，保留紧邻边界的最多 50 条。刷新正在编辑但已经落在最近一页之外的草稿时，只额外读取该草稿的序号并按原规则复核。

收到匹配的保存回执后，两端结束生成状态并回读已保存草稿。若历史暂时无法读取，提示草稿已保存，要求先刷新历史才可再次生成或审阅。权限变化按原规则处理。刷新不重发生成请求。

重新选择当前会话等同于刷新。两端重新检查群管理权限及草稿来源；草稿和来源核对通过后保留编辑正文与公告选项。草稿或来源变化时清除旧编辑并提示冲突。重新选择不会生成或发布内容。

用户可以打开引用所属帖子。只有带有有效来源的草稿可进入审阅。打开编辑器和确认发布时都会重读草稿及来源，内容或来源变化时要求刷新。编辑后由用户决定是否作为群公告，并通过现有群发帖接口提交。正文沿用群发帖的 4000 UTF-8 字节限制。发布结果不确定时提示查看群动态，保留当前编辑供核对，重新确认前需刷新。

评论引用携带群、父帖和评论 ID。两个客户端打开父帖后精确查询被引用的评论，并提供查看全部评论的入口。目标已不可见时显示不可用。身份或后端变化会使旧引用结果失效。

刷新时先复核群角色，再重新读取所选会话和草稿。收到相同的消息 ID、序号、正文及有效来源时恢复正在编辑的文字和公告选项。权限、身份或来源失效时丢弃旧编辑。临时读取失败期间隐藏编辑器，保留同一视图内尚待核对的输入供再次刷新。刷新只读。此前发布结果未知时，用户需先查看群动态，再决定是否重新确认发布。

最终发帖请求沿用本次审阅的取消信号。关闭页面、切换群组、切换账号或切换 Flutter 后端会中止等待并忽略旧回执。客户端只接受匹配请求群组且包含有效安全正整数帖子 ID 的成功回执。发帖请求已经发出但结果未知时，Nuxt Web 提供在新标签页打开当前群动态的入口，Flutter 把群详情压入当前路由以便返回草稿。打开群动态和刷新均为只读，刷新后若仍恢复同一草稿就继续提供入口。已确认成功或清除当前草稿后移除入口。

两个审阅编辑器实时显示去除首尾空白后的正文 UTF-8 字节数。超过 4000 字节时保留编辑内容、显示错误并禁止提交；缩短到限制内即可继续。发布确认还要求回执的布尔值 `is_announcement` 与实际提交的选项一致，否则按结果无法确认处理。

发布结果未知时，刷新确认同一草稿仍可审阅后，管理员须勾选已核对群动态且需要重新发布，才可再次提交。勾选本身不会发帖；发出新的请求后，如结果仍未知，须重新刷新并确认。
