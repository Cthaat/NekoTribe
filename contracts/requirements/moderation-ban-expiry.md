# 定时封禁到期恢复

Nuxt、Go 和 Rust 的 V2 密码登录在读到暂停账号时检查平台封禁期限。到期由 Oracle 时间判断，与请求内的密码、客户端时间和部署机器的时钟无关。恢复前后，登录均按原有规则校验密码和双因素身份，并在签发前复核账号和密码版本。

- 只有 `status = 'suspended'` 且 `is_active = 0` 的账号可以恢复。至少有一条已到期、状态仍为 `active` 的平台封禁记录。若有另一条未到期、尚未开始或无限期的活跃封禁，继续暂停。已撤销的历史封禁、禁言记录和禁用状态均不会触发恢复。
- 登录读到候选账号后尝试锁定同一用户行。恢复条件在取得锁后重新计算，以便与新封禁、手动解封、重复登录和其他账号更新串行。账号恢复和到期封禁标记为 `expired` 同时提交，失败回滚。无资格时释放锁并沿用当前账号状态。
- 到期恢复不修改已撤销会话和原审核审计记录。旧会话的访问令牌和刷新令牌保持失效。恢复后重新读取登录依据，正常签发新的会话或双因素挑战。
- 原生后端每 60 秒扫描一次，每次最多取 100 个候选账号。后台扫描跳过正在加锁的账号，下一轮重试。多实例可以连接同一库，由行锁和事务内条件保证同一条封禁只处理一次。到期时间以 Oracle 为准，V2 登录立即尝试恢复，无需等后台扫描。
- 实时 Oracle 双连接竞争、混合部署实例和后台任务在高负载下的处理能力仍需验收。
