# 发帖写入和媒体事务共同要求（局部）

本规则适用于 `POST /api/v2/posts` 和创建转发的共用发帖路径，补充 `post-create-reference.md`，不能代替完整发帖需求。新帖子、帖子媒体、标签（含新标签）、帖子标签及提及关联必须在单个数据库事务写入：插入、关联和检查都成功后显式提交；提交前发生错误须尝试回滚并返回安全错误。提交或回滚过程自身失败时提交结果可能不确定，不能假定一定回滚或自动重试。

最多附加按首次出现去重后的前四个媒体；每项必须在插入语句中限定为当前作者拥有且状态为 `uploaded`、`processing` 或 `ready`。私密附件还须在媒体行锁内复查 `post` 用途、ready 状态及关联。只有私密、关注者可见或被提及者可见的帖子可以附加私密对象。任何选中媒体不能附加时返回 400 `媒体不存在或不可用` 并回滚，不应静默创建缺少附件的帖子。非转发帖子必须有非空内容或至少一个实际附加的有效媒体，不能仅靠无效媒体 ID 创建空帖子。无文字且无媒体的转发仍可创建。过滤、转换和接受哪些输入类型仍以完整发帖规范及后续安全收紧为准。

标签和提及沿用已有去重、数量限制及数据库规则；本事务不包含通知与实时推送。提交成功后再创建回复、转发、引用和提及通知；通知或最终读取失败时帖子可能已提交，多个通知可能部分成功；发布失败不能回滚帖子。真实 Oracle 约束、触发器和并发、连接故障导致的未知提交结果、媒体状态变化、Redis 及两个客户端均须在隔离环境验证。Rust/Go 须分别实现相同事务边界，不能依赖 Nuxt。
