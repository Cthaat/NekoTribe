# 一般设置的身份、快照和保存生命周期

适用Nuxt Web与Flutter的一般设置页；user-settings-snapshot.md仍定义完整响应与原生事务。共同可执行断言为user-settings-client-lifecycle.json，两个客户端消费相同计数/允许值。界面可以采用Nuxt草稿批量保存或Flutter逐控件保存，但不得因交互方式不同改变安全边界。

- 页面必须先成功读取当前身份设置；首次加载/失败不把默认值作为已知设置展示或提交。显式重读互斥，失败不自动循环。
- 同一页面远程读取和保存互斥。按钮/开关/下拉禁用只是呈现，实际回调入口也必须校验；重复调用不得重复派发。Flutter本地主题/语言不发送设置API。
- Nuxt仅提交相对已读取快照实际修改的字段，不在修改登录提醒时顺带覆盖其他后端刚更新的可见性、2FA或旧AI字段。无修改不发送PATCH。Flutter逐控件只发送该字段。两端采用服务端返回的完整快照，不把本地预期当作已保存结果。
- 保存失败可能发生于提交之后，不保证已回滚。将远程快照标为未确认，阻止另一个PATCH；提示显式重新读取，再依据服务端结果编辑。不得自动重放写入或用旧快照伪装回滚成功。已发出的后端写入不能由UI保证撤销。
- 复用现有身份意图版本。包括同账号重新登录、退出开始、TokenStore变化或Flutter API/repository实例替换，旧页均失效；换会话后隐藏已显示偏好，待身份意图结束后由用户显式重开。普通同会话令牌刷新不强制关闭页面。Nuxt不同app/SSR请求之间隔离。
- 所有await之后核对owner、生命周期和当前请求/视图版本；旧读取/写入成功或失败不更新新身份状态、toast、错误或busy。Flutter取得设置后、调用旧Python配置/模型/统计之前也须检查，不能把旧链路后续请求发给新身份。卸载后不setState/通知；旧控件回调不能把已失效的输入发送给重开后的身份。
- 旧profile_visibility可以是任意字符串；不能默改成public，也不能让Flutter下拉因无匹配项崩溃。允许兼容显示不可选择的当前未知值；新选择仍只有精确public/private。Nuxt对其他字段提交时不附带未改变的未知privacy。followers不是新增可选值。
- 初次读取失败、保存结果不确定、身份变化均有可理解的中英文反馈和显式重读/重开入口；状态不只依赖toast。忙状态可见；使用既有视觉组件。窄屏不溢出，自动化widget/内存renderer验证不代替真实浏览器或设备。

Nuxt把偏好状态放在可卸载的独立组件中，账户安全组件保持父级存活以接收当前会话清理后的导航回执；不要用整个安全父组件卸载导致合法退出/注销导航丢失。Flutter用单调视图generation配合AuthRepository身份版本与repository实例，拒绝保存完成前的旧frame回调。

本阶段只做静态/隔离验证。真实浏览器/平台存储、完整API地址与认证范围切换、两客户端×三原生后端及多机部署仍是最终验收，不据本规范或局部通过标accepted。
