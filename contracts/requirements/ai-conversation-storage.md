# AI 对话持久化共同基础

三后端的共享会话存储已供问答、写作、群运营和审核辅助使用。真实 Oracle 与客户端组合仍待集中验收。

会话使用服务端生成的 UUID，归属于一个登录用户；用途为知识问答、写作、群运营或审核辅助。群用途可记录目标群 ID，但读取、写入和恢复时必须重新核对真实用户权限，不能仅凭会话 ID、历史角色或 group ID 授权。首期不把私信、私密群消息放入知识库。模型提供方 URL、密钥和系统权限不得写进会话或消息。

V2 创建会话和追加用户消息均使用 UTF-8 JSON 对象，请求正文最多 1 MiB（1048576 字节），按实际读取字节计数。表单正文、非对象 JSON、无效 UTF-8、重复顶层字段和超限正文返回 400／40001，且不调用会话存储。字段名按 JSON 解码结果判重，中文标题和消息内容须为合法 Unicode 字符串。

消息按会话内正整数顺序记录用户、助手或工具回合；每个消息具有独立 UUID。生成记录可以保存模型标识与配置版本，用于模型切换后追溯，不得改写已有记录。消息内容和结构化工具历史使用 CLOB，写入时限制大小，禁止在日志中输出正文或凭据。消息追加须在同一事务锁定所属会话、核对权限、分配顺序并持久化，避免并发重复和不同用户混写；提供方请求、工具调用不得在持有数据库锁时执行。

用户消息内容必须是非空字符串，按 UTF-8 编码最多 65536 字节，原样保存；由服务端生成消息 UUID 和 role=user，客户端不得指定序号、助手或工具角色。锁定当前用户拥有的会话后，再以同一事务中最大序号加一分配序号，写入消息并更新会话时间，提交前再次核对群或审核权限。序号不得超过数据库 NUMBER(10) 的正数上限；执行或复核失败回滚，提交结果不确定时报告失败但不声称已回滚。该规则不授予直接创建助手或工具回合的权限。

模型回复只允许可信服务端代码追加，正文同样为非空且最多 65536 UTF-8 字节；保存模型配置 profile ID 和正整数配置版本（因数据库 NUMBER(15)，上限 999999999999999）。推理前记录读取到的最后消息序号，模型请求不能持有数据库锁；回复写入时锁定会话并检查当前最后序号仍等于该值，不一致返回冲突并回滚，不把旧上下文生成的结果附到新消息后。写入前及提交前复核当前访问权限，记录 role=assistant、服务端生成 ID 和配置快照，不能由客户端指定。各生成用途的取消、模型调用与来源复核由对应业务流程约束，详见 `ai-agent-runtime.md`。

消息历史采用序号游标：after_sequence 为 0 至 9999999999 的整数，limit 为 1 至 50 的整数；返回严格大于游标的记录，按序号升序排列。查询必须限定当前用户拥有的会话，并在读取前和返回前重新核对群或审核权限；无权或其他人的会话不得泄露消息。返回消息 ID、会话 ID、序号、角色、正文、模型标识和版本、配置版本与创建时间；正文必须完整读取 CLOB。工具调用结构化历史的读取和恢复另行实现，不能凭普通正文重建工具结果。

消息历史也接受互斥的 `before_sequence`，取严格小于该序号的最近一页，页内仍按序号升序。游标为 1 至 10000000000 的规范十进制整数。读取最近一页使用 10000000000，加载更早页使用当前首条的序号。两种分页方向执行相同的鉴权及历史来源复核。无有效引用的知识回答仍保留占位和序号，推理历史的裁剪规则独立处理。

Nuxt Web 与 Flutter 的问答和写作在恢复及刷新时显示最近 50 条消息，用户可按需加载更早一页。翻早页保留当前消息，失败可重试。知识问答的主动引用复核会清除当前显示的旧页并读回经过复核的最近页，更早的引用须随更早页重新读取。旧后端忽略反向游标时，两端确认最新序号后改用正向接口。较早消息序号不连续时，以当前首条序号为排他边界补查，返回紧邻边界的最多 50 条。

Nuxt Web 和 Flutter 的问答、写作、群运营和审核助手只接收每条消息都属于所请求会话的历史页。页内必须有非空且不重复的消息 ID，序号不得超过 9999999999。任一消息校验失败时整页拒绝。加载更早页失败时保留当前页，主动引用复核仍先清除旧引用。成功读到不足请求页大小的一页时，即使首条序号大于 1，也结束该会话向前翻页。空页保留当前历史并视为已读到最早处。

会话列表按会话 UUID 的字典序升序分页，初始游标为空；后续游标是上一页最后一个返回给用户的会话 UUID，limit 为 1 至 50。返回 `{items, next_cursor}`，下一页存在或可能存在时提供游标，结束时为 null。仅返回当前用户拥有且当时有权访问的会话；查询中限制所有者，并按群管理员及审核权限筛选，返回每项前再次复核当前权限。游标不能包含未授权会话的 UUID；遇到权限在查询期间变化，可继续扫描有界批次，不能为了补满页泄露无权会话。数据库错误和权限检查异常必须失败关闭，不可当成空列表；持续权限变化导致无法安全完成时返回安全错误。分页顺序稳定但不代表最近使用顺序；恢复和删除时仍须独立鉴权。

Nuxt Web 与 Flutter 的问答和写作页面可通过 `?conversation=<UUID>` 恢复已保存会话。客户端仅接受单个 v4 UUID，先按当前账号读取会话资料，确认回执 ID 和当前页面用途匹配后才读取消息。页面地址仅保存会话 ID，在创建成功后即更新，无需等待消息追加或生成。停止和失败保留已确认的会话入口，未发送的内容留在当前页面。开始新会话、确认删除或已链接的会话返回 404 时清除旧入口。嵌入发帖器的写作流程保留父页面地址。

删除会话按授权执行并删除其消息；群管理员失权后禁止恢复对应群会话。历史内容、工具结果和检索资料都是不可信输入，不因持久化变成系统指令。正常用户只访问本人有权查看的会话，删除、保留期限、审计和模型切换时的上下文裁剪需要共同场景验证。

Nuxt Web 与 Flutter 的知识问答及写作可在第一条消息前填写可选会话标题。标题去首尾空白后最多 200 个 UTF-16 代码单元，空标题省略；仅在创建会话时发送，输入正文不用于推导标题。历史继续读取服务端保存的标题。

共享迁移 `ai-conversations-title-char` 将 `N_AI_CONVERSATIONS.TITLE` 转为显式 `VARCHAR2(200 CHAR)`。三后端通过 Oracle 字典确认长度语义，避免 UTF-8 中文标题提前触及老列的字节上限。迁移保留历史标题和既有迁移记录。升级时在维护窗口同步替换三后端，再由 schema 所有者运行显式迁移并复核就绪；应用启动不会修改数据库结构。

会话列表可选 `purpose=knowledge|writing|group|moderation`。空值、重复或未知用途返回 400。预先按用途过滤再取分页候选，所有权和业务权限仍须检查，未传则继续返回全部可见用途。游标须与原过滤条件一起使用；第一个和后续历史页都由客户端发送当前用途。

Nuxt Web 与 Flutter 的问答、写作、群运营和审核助手验证会话列表的分页边界。每页最多 50 条，会话 ID 非空并按字典序严格递增，且第一条大于请求游标。非空的 `next_cursor` 必须等于该页最后一条返回记录的 ID。校验失败时不应用异常页。问答、写作和群运营可重试分页，审核助手可重新加载当前审核对象的历史。群运营与审核助手继续核对会话用途和对应的群组或审核对象。

仅在 `purpose=group` 时可附加一次 `group_id`，必须为无前导零的正十进制安全整数，非法或重复返回 400。按群组过滤后再分页，读取范围仍须满足当前群权限。群运营客户端每次请求都传当前群组及用途；审核助手每页指定审核用途，客户端保留按当前审核目标的核对。

共享迁移 `ai-conversations-group-id-precision` 将 `N_AI_CONVERSATIONS.GROUP_ID` 扩为 `NUMBER(19)`，与群组主键保持一致。原写入与查询继续限制为正安全整数，既有记录无需改写。三后端以完成扩列后的 Oracle 字典为准。

仅在 `purpose=moderation` 时可同时提供一次 `target_type` 和一次 `target_id`。支持 post、comment、group_post 和 group_post_comment；ID 为不超过 15 位的规范正十进制数。缺项、重复、非法用途或类型返回 400。用服务端构造的既有审核会话标记匹配后再分页，仍要求会话所有权与审核权限，并在读取建议时独立复核实际审核对象。两端审核助手每页发送当前对象。

首个迁移创建共享会话及消息基础表；后续版本按共享迁移清单逐步补充。迁移必须显式运行、可重复检查、保留旧数据，并在隔离 Oracle 上验收。
