# AI 对话持久化共同基础

状态：开发中。此规范定义三后端共享存储边界，不表示 AI 对话接口、知识库或 Agent 已可用。

会话使用服务端生成的 UUID，归属于一个登录用户；用途为知识问答、写作、群运营或审核辅助。群用途可记录目标群 ID，但读取、写入和恢复时必须重新核对真实用户权限，不能仅凭会话 ID、历史角色或 group ID 授权。首期不把私信、私密群消息放入知识库。模型提供方 URL、密钥和系统权限不得写进会话或消息。

消息按会话内正整数顺序记录用户、助手或工具回合；每个消息具有独立 UUID。生成记录可以保存模型标识与配置版本，用于模型切换后追溯，不得改写已有记录。消息内容和结构化工具历史使用 CLOB，写入时限制大小，禁止在日志中输出正文或凭据。消息追加须在同一事务锁定所属会话、核对权限、分配顺序并持久化，避免并发重复和不同用户混写；提供方请求、工具调用不得在持有数据库锁时执行。

用户消息内容必须是非空字符串，按 UTF-8 编码最多 65536 字节，原样保存；由服务端生成消息 UUID 和 role=user，客户端不得指定序号、助手或工具角色。锁定当前用户拥有的会话后，再以同一事务中最大序号加一分配序号，写入消息并更新会话时间，提交前再次核对群或审核权限。序号不得超过数据库 NUMBER(10) 的正数上限；执行或复核失败回滚，提交结果不确定时报告失败但不声称已回滚。该规则不授予直接创建助手或工具回合的权限。

模型回复只允许可信服务端代码追加，正文同样为非空且最多 65536 UTF-8 字节；保存模型配置 profile ID 和正整数配置版本（因数据库 NUMBER(15)，上限 999999999999999）。推理前记录读取到的最后消息序号，模型请求不能持有数据库锁；回复写入时锁定会话并检查当前最后序号仍等于该值，不一致返回冲突并回滚，不把旧上下文生成的结果附到新消息后。写入前及提交前复核当前访问权限，记录 role=assistant、服务端生成 ID 和配置快照，不能由客户端指定。模型调用、失败状态、取消、知识库、工具执行和完整对话协调仍需分别实现。

消息历史采用序号游标：after_sequence 为 0 至 9999999999 的整数，limit 为 1 至 50 的整数；返回严格大于游标的记录，按序号升序排列。查询必须限定当前用户拥有的会话，并在读取前和返回前重新核对群或审核权限；无权或其他人的会话不得泄露消息。返回消息 ID、会话 ID、序号、角色、正文、模型标识和版本、配置版本与创建时间；正文必须完整读取 CLOB。工具调用结构化历史的读取和恢复另行实现，不能凭普通正文重建工具结果。

删除会话按授权执行并删除其消息；群管理员失权后禁止恢复对应群会话。历史内容、工具结果和检索资料都是不可信输入，不因持久化变成系统指令。正常用户只访问本人有权查看的会话，删除、保留期限、审计和模型切换时的上下文裁剪需要共同场景验证。

首个迁移只创建共享会话及消息基础表；分布式索引、检索、消息追加接口、并发控制、上下文截断、Skills 和实际模型调用均需后续实现。迁移必须显式运行、可重复检查、保留旧数据，并在隔离 Oracle 上验收。
