# 注册资料与新邮箱输入

行为来源为Nuxt现有Zod/v3注册、找回密码和改邮箱schema。三后端新增资料接口与Nuxt/Flutter交互使用共同输入规则，复用既有JS trim和v2标量转换，不自动转小写或改写已有账号。

1. 注册email和更换邮箱new_email匹配Nuxt已安装Zod/v3的email规则：ASCII本地部分支持字母/数字/下划线/加减号/内部点/内部单引号，禁止起始点、连续点、@前的点或单引号；域标签以ASCII字母数字起始、后续可含连字符，顶级域至少两个ASCII字母。不另行加强Zod现有边界，例如标签尾部连字符仍沿用其接受行为。Unicode邮箱、显示名称格式、IP字面域等不在当前接受范围；这不是完整RFC或邮箱投递验证。判断在标量转换及JS trim之后，保留大小写。
2. 注册username/display_name按trim后的UTF-16代码单元计数，至少2；单个补充平面emoji计2、单个中文计1。没有新增最大长度、用户名字符集或大小写策略。数字/布尔标量仍按v2转换；数字42作为名字可用，7不足2位，true/false长度满足。前端表单仅提供字符串输入。
3. 注册依次保留原必填字段、条款、密码确认、新密码门槛，再检查email、username、display_name；错误依次固定400/40001 `邮箱格式错误`、`用户名至少需要2个字符`、`昵称至少需要2个字符`。在查OTP、查重、取业务序列、哈希或写库前拒绝。改邮箱先鉴权及解析三个必填字段，再校验新邮箱，早于查重/查OTP/消费/更新；不能跳过会话检查。
4. OTP创建先执行原account/type/channel检查、SMS501，再对email通道且用途register/change_email校验邮箱，错误固定400 `邮箱格式错误`，早于取序列、生成/哈希验证码、插入或SMTP调用。password_reset用途及已有OTP验证继续使用原账号非空规则，保留旧账号接口兼容。登录不使用这些新资料规则，旧名字/邮箱不迁移；客户端找回密码继续遵守既有Nuxt邮箱表单规则。
5. Nuxt找回/安全页和Flutter注册/找回/安全页在发码前拒绝无效邮箱；Flutter注册在OTP验证前拒绝过短名字，提交归一化快照。安全页邮箱监听、OTP绑定及提交统一JS trim，旧会话/迟到响应防护保持。服务器校验仍为安全边界。

`scenarios/auth-account-input.json`含55项注册输入、25项邮箱、15项名字（后两组复用，不可合计为95个不同输入）。三后端实际HTTP注册路由消费55项；新邮箱OTP/凭据修改的非法输入走实际鉴权/路由边界；现有OTP/邮箱事务场景继续覆盖正常路径。Nuxt三个实际SFC schema消费93项字符串组合；Flutter纯校验器使用原始值，Widget使用实际输入框。Flutter单行EditableText按SDK规则删除LF，因此该唯一向量额外记录widgetValid/widgetNormalized；原始接口仍拒绝内嵌换行。

OpenAPI结构schema保留标量兼容，扩展描述JS trim、Zod/v3邮箱与UTF-16最小长度；不能直接用format/minLength替代转换或计数语义。新注册/新邮箱输入有意收紧；现存账号与数据库不批量改写。资料编辑、完整Unicode/超大JSON数字、限流/尝试次数及并发撤销仍需后续统一。隔离回归不证明SMTP投递、Oracle约束、浏览器Cookie/设备存储或六组合验收。
