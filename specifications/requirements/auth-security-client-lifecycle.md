# 安全页动作与会话归属

适用双因素初始状态读取、setup/confirm/disable、注销、改邮箱及已登录安全页中的密码重置表单。两客户端绑定页面创建时的会话版本；Flutter还绑定原AuthRepository实例。状态、密钥、恢复码、错误提示和导航只能交给发起者，卸载或切换身份后丢弃迟到结果，不能用旧finally释放更新动作的状态。

1. 不能只禁用按钮：函数入口检查pending/busy。输入在发起前按JS trim规范化并捕获，不能await后重新读取密码/确认/验证码。验证旧密码时不套用新密码长度。Nuxt组件绑定创建时的会话，过期页面不再发起动作，卸载时清空密钥/恢复码/密码等本地引用；Flutter逐次校验捕获版本与仓储实例。初始状态读取也须归属检查。
2. 2FA setup/confirm/disable的业务密码/验证码错误也可401，禁止自动刷新、重放或清理有效会话；请求仍携带鉴权，保持通用身份/取消守卫。完整安全动作成功envelope及secret/URI/enabled/recovery_codes按auth-security-client-response.md严格解码；状态读取字段和真实OTP等仍待验收，不能据此声称2FA全功能已验收。
3. 注销失败保留客户端会话，成功要求deleted字面true和正安全整数user_id，受控清理原版本。Flutter调用AuthRepository条件本地清理，既有清理队列及全局收尾只属于原版本；迟到完成不能退出较新登录。无receipt或receipt过期不导航，持久化失败不伪造成功。
4. Nuxt注销必须与同app登录、2FA登录完成、刷新及退出串行到响应完成，避免较早注销的Set-Cookie覆盖后续登录；发起时捕获app、版本与提交参数，不能await后读取表单或新app。已有身份变更排队/执行中时拒绝新注销；注销等待期间发生身份变更时在发送前取消，完成时版本过期也取消发布。普通刷新不变更身份，可先刷新再注销。不同app/SSR用户使用各自队列，异常不能阻塞后续动作。此策略仅保护同app调度，不代表跨标签页、跨设备或真实浏览器Cookie已验收。

5. 身份变更在开始时同步发布无token/用户数据的通知。Nuxt队列跟踪登录/2FA完成/退出从排队到响应结束的在途状态，Flutter TokenStore/AuthRepository跟踪相应网络动作及本地清理；失败也释放在途标志。普通刷新、普通读取不改变身份、不销毁当前安全页。观察者按app/store隔离且支持取消订阅，不应阻止认证动作；Flutter仓储实例替换也使页面过期。
6. 收到变化后，在下一次正常UI更新中移除整组旧安全表单，不等待另一个请求或OTP倒计时。即使同一账号重新登录也必须过期。身份变更在途时不允许重新打开；结束后用户显式“重新打开安全设置”才创建新owner、空表单并重读状态。过期页面所有入口（包括保留回调）拒绝操作，旧结果不能发布秘密或释放新页面busy；复制恢复码也须校验owner。卸载时取消观察/OTP定时器、清理secret/URI/恢复码/敏感输入引用。不承诺不可变字符串的物理内存擦除。
7. 注销/改邮箱/安全页密码重置自身引发清理时，旧子表单也卸载；后续导航由仍挂载的父页面持有并核对当前app/仓储及版本receipt。当前有效receipt可在子表单已卸载后导航登录，过期receipt或父页面已卸载则不导航；失败不伪造清理成功。Nuxt父页面重新进入捕获app上下文执行导航。

设置完整响应与安全页未知/加载/显式重读按user-settings-snapshot.md执行，不得把缺字段或失败解释成2FA关闭。

仍待：原生设置读取事务/缺用户错误/cache统一、一般设置页完整生命周期、跨实例/端点切换时认证存储、真实浏览器Cookie/cache/SSR及跨标签页并发，以及六组合。秘密失效/重开、完整安全响应及未知状态已有隔离回归；原生2FA接线不代表实际OTP应用、Oracle及完整客户端已验收。
