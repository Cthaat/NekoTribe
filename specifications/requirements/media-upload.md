# 媒体上传与持久化共同规则

版本：1。适用 `POST /api/v2/media`。最终 Nuxt/Rust/Go 均需自行处理上传、验证、文件存储和数据库事务；共享模型服务不能代替媒体业务。当前实际实现进度另见登记，不把公共规则或组件当作已接入原生接口。

## 请求与文件

有效 access 会话先于 multipart 检查及创建临时目录。只接受 multipart/form-data；字段 file 的第一个文件优先，其次 media 的第一个文件，其他文件不入库。alt_text、description 取第一个文本值，空值绑定 null。文件及总文件数据上限为 500 MiB，不能把整个上传体加载到内存；临时目录、文件数和字段上限继续在各实现接线时核对，不能假定默认值一致。

文件类型及元数据沿用现有 Nuxt 验证能力：图片、GIF、音视频、文档、文本和压缩包；根据真实内容检测，无法识别时的 MIME/扩展回退规则需单列共同样例。图片尺寸及音视频时长探测失败不虚构结果，使用 null。存储 key 使用服务端 UUID、用户 ID 和 UTC 年/月，不使用客户端文件名决定目录。不得把暂存目录作为公开文件提供。

## 生命周期和失败处理

每次请求拥有独立暂存目录，仅递归清理本次创建的目录；成功、无文件、验证失败、解析错误和被忽略的额外文件均要清理。普通运行数据、其他并发请求目录和既有存储文件不属于该清理范围。临时清理失败记录固定安全信息，不暴露本机路径或替代原始业务结果。

先存储文件，再取得序列并只读检查媒体结构，使用一笔数据库事务插入 ready 记录、读取和映射响应，最后提交一次。缺少刚创建的记录也必须进入回滚和清理，不能从回调直接退出。入库字段包含同一 media_id、owner_user_id、类型、原名、key、公开地址、大小、MIME、可空元数据、alt_text/description；成功为 HTTP 200/code 200/`media uploaded`，meta=null。

提交尚未开始且回滚确认成功时，可补偿删除本次新存对象。提交一旦开始，结果未知或已提交时必须保留对象，即使后续回滚调用成功也不能推断未提交。回滚本身失败时同样保留对象，避免删除可能被数据库引用的数据；此时可产生待对账的孤立对象，不能自动重试上传。补偿删除失败也只记录安全信息，后续清理须先核对数据库引用。

本地 provider 以排他复制保护已有对象；复制完成后若移除来源失败，目标对象可能已存在但尚未返回 key，需后续对账处理。不能为了清理失败请求而删除同名既有对象。

## 删除生命周期

`DELETE /api/v2/media/{id}` 先验证 access 会话，再以 media ID 和当前用户 ID 读取媒体；不存在或不属于该用户返回 404。以同样的两个条件删除记录，只有数据库确认恰好删除一条记录后才开始清理本次记录指向的文件；零行表示并发删除或记录消失，返回 404 且不清理文件。异常行数或提交异常返回安全错误且不清理文件，提交结果不确定时不能假定已提交或回滚。确认删除后返回 `media deleted`；物理文件清理失败时，记录可能已删除而对象仍存在，需后续对账，不声称事务原子。

存储 key 优先，缺失时才从受管理的公开 URL 提取；非本站外部 URL 不作为本地路径删除。缩略图另行处理。当前规则尚不证明不同媒体、头像或其他记录没有共用同一对象；共享引用、关联帖子外键与并发引用必须在真实数据库和对象归属机制上进一步验证，不能把上述行数检查当成完整的共享对象安全保证。Rust/Go 须原生实现并共享相同鉴权、响应和失败边界。

不支持的 Content-Type、空文件或明确验证失败为固定公开的 400 消息。解析错误不得返回临时目录、底层库或驱动错误正文；数据库、存储 IO 和未知异常返回安全 500。媒体结构不可用沿用安全 503。尚未实现的存储提供方必须明确返回不可用，不冒充本地或忽略配置。响应 private/no-store。

本规则不证明 S3、完整原生上传、真实 Oracle 提交状态或两个客户端已经通过。Rust 和 Go 均已有开发中的原生上传路径，但格式识别、元数据和真实依赖验收尚不完整；Rust 所有上传元数据目前为空。后续还需完成三端内容检测/元数据共同样例、读删权限、流式限制和 Windows/Linux/跨机验收。当前公开文件服务也不能当作私有附件权限方案。
