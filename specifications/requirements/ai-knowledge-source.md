# AI 知识来源的实时复核

Nuxt、Go、Rust 独立复核普通公开帖子、评论和平台规则。平台规则使用独立的条款发布权威，见 `ai-public-terms-source.md`。

三后端的内部复核器支持 `group_post` 和 `group_comment`。这两个类型使用同一份 `ai-group-knowledge-source.json` 查询，只从启用、未删除且当前公开的群读取未删除的群动态及评论。帖子和评论作者均须启用，双方拉黑任一作者即省略来源。群成员权限不会扩大知识来源范围。版本沿用下文的 SHA-256 算法，并以独立的类型值区分可能同号的普通来源和群来源。群引用从当前群帖获取 `group_id` 和 `post_id`；群帖的 `post_id` 等于自身 ID。持久化引用只包含 `kind`、`id`、`version`，模型交互见 `ai-knowledge-turn.md`。恢复会话时，群来源全部复核通过才返回回答及当前定位字段。Nuxt Web 和 Flutter 支持按有效群引用打开群帖子或定位到评论。打开时重新检查群仍公开且启用，并通过现有群内容接口读取目标。精确文字检索与向量索引均支持公开群来源。

索引或检索服务只提交 `{kind,id,version}` 候选，每次使用时由当前后端以有效登录用户重新读取来源。候选最多 20 条。文字检索与来源复核支持 post、comment、terms、group_post 和 group_comment，向量服务向声明群来源能力的后端返回全部五类。帖子和评论 ID 为 1 至 999999999999999 的整数，规则 ID 为 1 至 8，版本为 64 位小写十六进制。额外字段、重复来源或非法候选整体拒绝。

文本检索在 Oracle 分页前过滤超出该范围的来源 ID、所属帖子 ID 和群组 ID。复核按已校验的来源 ID 查询，同时过滤越界的所属帖子和群组。更宽的 Oracle 数值列可以保留历史数据，受支持的公开记录仍能独立检索。

帖子必须同时满足 `visibility='public'`、`is_deleted=0` 和当前调用者的 `fn_can_view_post`。评论也必须未删除，且其所属帖子满足这些条件。过滤条件必须包含在读取正文的 SQL 中；即使作者或关注者有权查看非公开帖子，也不得将其作为本阶段知识来源。禁用跨用户及过期查询缓存，不读取群聊、私信或私密群。无权、删除或不存在的候选统一省略，不暴露存在性；数据库或数据异常失败关闭，不以旧索引内容回退。

文字检索和候选复核均要求帖子作者处于启用状态。评论还要求评论作者处于启用状态，并排除当前查看者与评论作者任一方向存在拉黑关系的记录。上述检查必须在读取正文的 SQL 内完成。账号停用与拉黑生效后，历史引用按原有失效规则处理。

来源版本计算为 SHA-256：UTF-8 编码 `neko-ai-source-v1`、NUL、kind、NUL、十进制来源 ID、NUL、十进制所属帖子 ID、NUL，再接 UTF-8 编码的完整正文。帖子自身的所属帖子 ID 等于其来源 ID。不可规范化、截断或重编码正文；无效 Unicode 失败关闭，空正文或超过 65536 UTF-8 字节的正文不进入此次结果。SQL 在读取 CLOB 前按字符长度限制为 1 至 65536，再进行 UTF-8 字节检查，避免无界读取遗留数据。当前来源内容计算的版本必须与索引候选完全一致，更新后的旧片段直接丢弃；来源重新编辑回原内容时等价内容可复用相同版本。

结果返回当前正文、类型、来源 ID、所属帖子 ID 和版本，供受控检索及引用使用。来源正文是不可信数据，不能更改系统指令或工具权限。推理可能耗时且期间内容可能变更，生成结果交付前仍须再次检查引用的当前权限和版本；本组件的单次读取不保证之后权限不变，也不代替索引删除、向量模型切换、来源引用 UI 或真实并发验收。

`ai-knowledge-source-vectors.json` 是各语言须执行的确定性版本向量；真实 Oracle 权限函数、CLOB、多字节、删除改权竞争和三后端一致性仍须使用隔离环境验收。
