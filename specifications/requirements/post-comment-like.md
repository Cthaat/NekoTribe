# 帖子评论点赞共同需求

`POST` 和 `DELETE /api/v2/comments/{id}/likes` 要求有效会话与规范安全正整数 ID，响应 `private, no-store`，内部错误脱敏。目标评论必须未删除，所属帖子必须未删除且当前用户可见；否则返回 404 `评论不存在`。这是对旧接口的安全收紧。

点赞或取消前查询可见评论；写入语句本身再次检查上述条件并绑定当前用户和评论 ID。点赞已存在、取消未存在均可重复执行；零行时重新检查可见性，不可见返回 404。随后读取点赞数时再次限定可见性；无统计行时为零。成功返回 `success`、`comment_id`、目标 `is_liked` 和当前 `likes_count`。首次新增点赞向评论作者发送 `like` 通知；本人、通知类型和推送偏好沿用统一通知规则，重复点赞和取消点赞不发送。元数据包含 `post_id`、`target_post_id`、`comment_id`、评论及帖子摘要和 `comment_like` 事件；摘要沿用 160 个 UTF-16 单元规则。

点赞写入、统计读取和通知分开提交，写入后失败可能返回错误但点赞已生效；Redis 发布失败只降级推送。语句级检查无法消除所有提交竞争；并发唯一约束、触发器、统计、真实 Redis 与双客户端必须在隔离环境验收，不能由模拟测试代替。
