# 密码重置的共同事务行为

已登录安全页密码表单另遵守auth-security-client-lifecycle.md：owner过期后禁止发码/提交，身份通知使整组旧表单卸载并清除密码/验证码/定时器；自身清理后的当前receipt交由父页面导航，迟到或父页已卸载时不导航。公开忘记密码页面仍按其既有独立请求生命周期执行，不因安全页门控而新增登录要求。

`POST /api/v2/auth/password-reset` 是公开接口，三后端独立执行同一流程，不能依赖另一个后端进程。版本 3 将挑战和设备信任撤销并入密码重置事务。真实 Oracle 并发验收仍需完成。

1. 按顺序读取 `email`、`verification_id`、`code`、`new_password`；按 v2 标量字符串规则转换并去除首尾空白，任意字段为空返回 400 `<字段> 不能为空`。支持现有 JSON 和表单输入。字段解析后按 `auth-password-input.md` 要求新密码trim后至少6个UTF-16代码单元；不足时固定400/40001 `密码至少需要6个字符`，不得读/消费OTP或写库。现有短密码登录不受影响。
2. 直接按邮箱、用途 `password_reset`、验证码标识查尚未过期的 OTP，不要求先访问独立验证码校验接口。无记录返回 400 `验证码不存在或已过期`。比对前按 `auth-otp-verification.md` 预留同一验证码的共享额度，耗尽返回 429，Redis 不可用返回 503。bcrypt 不匹配返回 401 `验证码错误`。随后用 bcrypt 成本 10 生成新密码哈希，按 Nuxt 的 UTF-8 前 72 字节计算。
3. 在同一数据库事务中，按邮箱、用途、标识、查到的原验证码哈希和过期时间条件更新 OTP；同时写入 `verified_at`、过期时间和不可验证的 `!consumed!` 哈希标记。更新零行返回 400；多行视为数据库异常。条件更新旨在让同一验证码的并发请求只有一个成功，但真实 Oracle 行为仍需实测。
4. 同一事务按邮箱绑定参数更新唯一用户密码，零行返回 404 `用户不存在`，多行按数据库异常处理；再撤销该用户尚未撤销的会话、将该用户所有未消费的双因素挑战标记为已消费，以及撤销该用户尚未撤销的受信设备，然后提交。既有 TOTP 密钥和未消费的恢复码可继续使用。任一步失败时回滚，不能保留部分成功的验证码消费或密码更新。提交或连接关闭异常可能使客户端无法确定实际提交结果，不能承诺一定未提交。
5. 成功返回 `{code:200,message:"password reset success",data:null,meta:null}`，不设置 Cookie；错误安全返回，不得把密码、验证码、内部异常或连接信息输出到响应与日志。
6. 密码入口在会话签发或创建新挑战前按 `auth-login.md` 锁定同一用户行并重验密码版本。登录写入先提交时，重置事务随后撤销该会话。重置先提交时，已验证旧密码的请求不能再签发会话或创建新挑战。重置提交后，旧挑战不能再完成，旧设备指纹登录需重新完成双因素。在途挑战在同一事务消费挑战与恢复码并写入设备信任和会话，事务先锁定用户行并核对最新密码哈希。重置先提交时，这次挑战完成返回 401，事务不写入。已建立的 WebSocket 在下一次应用帧处理、推送前或约 30 秒的空闲会话例行校验时，从数据库识别撤销并关闭连接。真实 Oracle 双连接、跨实例推送和浏览器重连待验收。密码强度和统一错误信息策略仍有独立缺口。

`scenarios/auth-password-reset.json` 保存合成的隔离用例，覆盖校验顺序、不同 OTP 状态、事务失败及提交后副作用。真实 Oracle、并发、会话安全、跨后端登录和 Windows/Linux 跨机器部署必须另行验收。
