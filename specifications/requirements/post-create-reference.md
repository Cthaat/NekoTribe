# 发帖的引用权限共同要求（局部）

本文件只覆盖 `POST /api/v2/posts` 中的回复、转发、引用，以及 `POST /api/v2/posts/{id}/retweets` 的目标帖子；并非完整的发帖需求。两个接口要求有效会话；客户端提供的引用 ID 为 1 至 9007199254740991 的安全整数或不带前导零的十进制字符串，缺省、null、空字符串表示无引用。转发路径 ID 必须为规范安全正整数。同一个发帖请求最多指定一种引用；错误输入返回 400。

引用目标必须存在、未删除且对当前用户可见，否则在分配新帖子 ID 前返回 404 `帖子不存在`。写入语句必须使用当前会话用户及目标帖子 ID，在同一条 SQL 中再次检查目标未删除和 `fn_can_view_post`；权限或状态变化导致零行时返回相同 404，不应创建引用帖子或发送通知。成功的帖子结构和通知仍遵循既有发帖行为，必须覆盖回复、转发、引用和各自通知类型。语句检查受数据库快照及并发提交影响，不能承诺完全消除权限变化竞争。

Nuxt 其他发帖行为仍需独立还原：内容与媒体的有效性、媒体所有权和状态、标签和提及的规范化、回复/转发/提及的通知、完整响应和错误、客户端契约及多步操作的事务边界。当前 Nuxt 写入帖子、媒体、标签、提及和通知分别自动提交，后续失败可能留下部分结果；仅传不可用媒体也可能造成空帖子。这些是待修复和待验收项，不能把本文件作为完整发帖验收或将其问题复制到 Rust/Go。

隔离测试需覆盖不存在、已删除、不可见、合法、非规范或超出安全范围的目标 ID，多个引用字段冲突，写入时目标权限变化和安全错误。最终需使用隔离 Oracle 验证真实绑定、触发器、并发、两客户端及跨后端数据一致性。Rust 与 Go 均须独立实现，不允许将引用写入代理给 Nuxt。
