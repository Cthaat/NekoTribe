# 帖子与用户统计

三套后端原生提供 `GET /api/v2/posts/{id}/analytics`、`GET /api/v2/users/{id}/analytics` 和 `GET /api/v2/users/{id}/analytics/daily`。接口要求有效会话和无前导零的正十进制安全整数 ID。响应使用 `Cache-Control: private, no-store`，只读查询不会增加浏览次数。

- 帖子统计仅向作者返回。不存在、删除或对请求人不可见的帖子统一返回 404。请求人可见但不归其所有时保留 422。统计记录缺失时返回 404。点赞率用点赞数除以浏览数并保留四位小数，零浏览时为零。
- 本人概览包含本人所有未删除帖子，以及本人发出的点赞和未删除评论。访问其他账号时，只计算公开帖子及其收到的互动，发出的点赞与评论字段返回 `0` 以兼容既有响应结构，公开资料页省略这两项。账号停用、资料为私密、任一方向拉黑或不存在时，其他访问者收到 404。
- 每日统计只供本人查看，其他账号返回 404。天数默认为 14，有效数量截为整数并限制为 7 至 90 天。使用 Oracle 的日历，从最早日期排到今天，无活动日返回零。每日互动分数等于收到的点赞、评论和转发之和。
- 概览最近 7 和 30 天使用数据库当前时间计算，点赞与互动平均值保留两位小数。三套后端复用同一组 SQL。真实 Oracle 时间边界及两客户端与三后端的部署组合待验收。

Flutter 帖子统计按本人发帖列表继续分页。汇总只使用已加载且收到完整、帖子 ID 匹配的统计，不以动态计数填补失败或不匹配的结果。页面显示已加载范围和取到统计的条数。账号或后端变化时清除先前页面的数据。

Flutter 本人动态列表可直接打开选中帖子的统计，仅查询该帖子，不依赖统计汇总页已经加载的内容。返回 ID 不匹配或读取失败时提供重试，不展示其他帖子的统计。

Nuxt Web 与 Flutter 的本人分析页提供 7、14、30、90 天选项，默认 14 天。切换范围只刷新趋势；趋势加载失败可重试，概览仍可查看。账号或 Flutter 后端变化时，先前的每日统计请求结果不再有效。
