# 删除私信

`DELETE /api/v2/chat/direct-conversations/{conversation_id}/messages/{message_id}` 无请求体。两个 ID 都是十进制正安全整数，首位不能为 0。先鉴权，再验证会话参与者和消息归属。发送者可删除自己的消息。无权进入会话或试图删除他人消息返回 403，指定会话中没有该消息返回 404。发送者重复删除已删除的同一消息返回相同的成功响应 `code=200`、`message="direct message deleted"`、`data=null`、`meta=null`。

同一事务先锁会话再锁消息，与发送路径的锁顺序一致。实现使用共享的 Oracle 语句，标记消息删除并更新删除者和时间，重算未删除消息数及最新消息。会话没有剩余消息时，最新消息及时间均为空。已读位置保留。站内通知原有正文摘要替换为「私信已删除」。失败回滚，提交结果未确认时返回安全错误。读取历史时由现有过滤规则排除已删除消息。

Nuxt Web 的独立私信页和群聊内私信窗口、Flutter 的会话页均提供发送者删除与确认。按钮由当前用户 ID 及消息权限共同控制。确认成功或收到当前会话的删除事件后移除该条消息，旧的在途历史响应不能恢复它，Web 同时刷新会话摘要。账号、后端或会话切换使旧响应失效。

首次提交成功后向双方发布 `direct_message_deleted`，通过本机连接及各自的 Redis 用户频道转发。`data` 仅含 `conversation_id`、`message_id` 和可选的字符串 `server_id`。不含被删除正文。服务端向连接发送前复核该账号属于会话、消息归属正确，且数据库标记已删除。重复成功和事务失败不发布事件。投递失败不改变 HTTP 删除结果，重连时从历史补读。真实 Oracle 并发验证需覆盖同时发送和删除、重复删除、回滚、最新摘要回退和通知摘要替换。

两端会话列表在收到删除事件时立即隐藏对应的旧摘要，随后重新读取。Flutter 聊天首页也在私信新增和实时连接恢复时刷新。切换账号或后端时清空旧列表并取消排队刷新，旧响应不能写回新列表。

客户端只使用 `direct_message_deleted` 的 `data` 中两个 JSON 正安全整数作为会话及消息标识。小数、字符串和超出安全范围的 ID 不触发删除或摘要变更。
