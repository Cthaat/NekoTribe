# 公开知识来源的基础检索

状态：开发中。Nuxt、Rust 和 Go 提供内部精确文本检索；它不是向量检索、问答或 Agent。不得直接作为公开接口或将结果交给模型，直到调用流程具备来源实时复核和推理结束后的再次复核。

有效登录用户以查询文本及 1–20 的整数上限检索普通公开帖子、公开评论及平台规则。查询去除 ECMAScript `String.trim` 定义的首尾空白；余下内容须为有效 Unicode、1–256 UTF-8 字节，不得包含 U+0000–U+001F 或 U+007F。非法输入或未认证拒绝，不执行查询。搜索是区分大小写的完整文本子串匹配，不解释通配符；SQL 使用绑定参数。

分别按来源 ID 降序获取最多上限条帖子和评论；平台规则按照固定 ID 升序获取匹配项。三组按照帖子、评论、规则顺序轮流合并，最终结果不超过上限。规则按标题或段落做同一查询规范的精确子串匹配；每项正文为标题与所有段落以换行拼接，超过 65536 UTF-8 字节则省略。若有规则匹配，先读取当前权威标记并验证本机目录；缺失、停用、不一致或数据库异常时本次检索失败关闭。无规则匹配时不读取权威标记，原有帖子和评论检索不因此依赖规则初始化。每条结果包含类型、来源 ID、当前完整正文和版本指纹；帖子与评论包含所属帖子 ID，规则不包含帖子 ID，并使用 `ai-public-terms-source.md` 的版本指纹。结果按当前业务数据库读取；不得读取索引中缓存的正文，不得使用跨用户查询缓存。正文、身份、公开状态、删除状态和当前查看权限的判断遵守来源实时复核要求；空正文或超过 65536 UTF-8 字节的正文省略，数据损坏或数据库错误失败关闭。

首期不包括公开群内容；后续必须补齐。返回数量上限不限制数据库扫描工作量，直接 CLOB 子串查询不可视作可扩展的生产索引；应后续加入索引、增量更新、过期清理、检索质量和实际资源评估。查询期间权限可能变化，使用前和推理后仍须按来源 ID 与版本复核。文本是不可信资料，不能改变系统指令或工具权限。

`ai-knowledge-discovery-order.json` 是三后端共用的隔离排序与规则启停场景，不代表真实数据库验收。三后端还应共同验证非 ASCII、参数与身份校验、查询参数绑定、公开/删除/权限过滤、排序合并、正文大小、损坏数据及真实 Oracle CLOB 行为。当前隔离测试不是 Oracle、跨后端或模型端到端验收。
