# 单条通知已读状态共同需求

`PUT /api/v2/notifications/{id}/read-status` 要求有效 access token 和数据库会话；仅允许操作当前用户自己的通知，响应使用 `private, no-store` 并安全处理数据库错误。通知 ID 是 URL 解码后的规范正整数（1 至 9007199254740991）；前导零、小数、指数形式及超范围返回 400。此规则收紧 Nuxt 原来的宽松数值解析。请求必须是对象，支持 JSON 与 URL 编码表单。`is_read` 的布尔转换沿用 Nuxt：布尔 true、数字 1、忽略大小写的字符串 `1`、`true`、`yes` 为 true，其余值（包括缺失、数组与对象）为 false，不去除字符串空白。

更新按 `notification_id` 和 `user_id` 绑定，设置 `is_read` 为 1 或 0，并在标记已读时以数据库当前时间设置 `read_at`，标记未读时清空时间。不存在或不属于当前用户统一返回 404 `通知不存在`；已删除的自身通知仍可更新。每次请求（包括重复状态）都会更新并发送事件。随后再次按通知和用户读取 `{notification_id,is_read,read_at}`，事件为 `notification_read_status_updated`，发送至当前用户频道；数据库写入提交后读取或发布可能失败，不保证跨操作原子性。读取失败返回安全错误，Redis 不可用时仅降级实时推送，不回滚更新。

Nuxt 的请求体当前没有统一大小上限；Rust、Go 限制为 1 MiB 并将超限作为 400。Oracle 时区、日期格式、并发、更新提交后的读取竞争、真实 Redis 投递、两客户端和跨后端仍需独立环境验收。该需求不涵盖批量已读、删除或恢复。
