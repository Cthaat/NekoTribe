# 帖子详情及可见性：共同实现要求

目标是 `GET /api/v2/posts/{id}`，Nuxt 是现有行为基准；Rust、Go 须独立实现同样的业务，不代理 Nuxt。Rust、Go 原生路由已接入并通过隔离场景；真实数据库和前端联测尚未验收。

## 身份与可见性

- 对符合现有匿名路由规则的十进制正整数 ID，未带凭据可访问；带凭据时仍需验证签名、access 类型与 Oracle 会话，并 touch 会话。失效 Cookie 优先于 Bearer，不能静默降级为匿名。非规范路径在未登录时先被中间件拒绝；登录后只接受无前导零的十进制安全正整数（1..9007199254740991），原 Nuxt 的宽松 `Number()` 解析已统一收紧。
- 使用当前会话用户 ID 或匿名 NULL 作为 viewer_id，与 post_id 一起绑定到 `v_post_feed_item` / `fn_can_view_post(:viewer_id, v.post_id)=1`；数据库函数是现有权威。缺失、已删除或不可见均返回 404，不能泄露私密帖子存在与否。数据库仓库中函数的意图包括作者、公开、关注、提及、屏蔽和删除条件；真实数据库函数/视图可能漂移，须另行检测和真实 Oracle 验证，不能用代码中的简化权限替代。
- 作者资料按同一 viewer 读取活跃的 `v_user_profile_public`，并执行现有在线隐私及关系映射；作者不存在返回 404。提及用户的查询不包含在线计算列，现有映射因此通常输出 offline/null，不应冒充已经实时查询。公开资料不含邮箱、电话或认证数据。

## 数据及副作用

- 主记录包含 content（Oracle `DBMS_LOB.SUBSTR(...,4000,1)`）、类型、可见性、语言、位置、引用/回复 ID、计数、互动状态和时间；加载作者、按 sort_order 排列的媒体、按名称排列的标签、按用户名排列的提及用户。媒体及头像 URL 由共同存储地址规则转换。媒体完整字段包括尺寸、时长、缩略图、alt_text、description 和状态，null 语义按 Nuxt mapper。
- 加载媒体前执行只读媒体结构检查，列、owner 与迁移账本不满足时返回安全 503；不可在业务请求中执行 DDL。本文关联的 `media-schema-catalog.json` 和 `media-readiness.json` 定义媒体检查增量。媒体查询、作者、标签或提及读取失败时不得增加浏览量。
- 成功构建全部资料后执行 `UPDATE n_post_stats SET views_count = views_count + 1, updated_at = CURRENT_TIMESTAMP WHERE post_id = :post_id` 并提交，再返回先前读取的数据：响应中的 views_count 是本次增加之前的值。UPDATE 影响 0 行时 Nuxt 仍成功；提交或连接关闭错误可能在写入已提交后返回失败，不承诺幂等或回滚。并发查询与多条 SQL 不保证一致性快照。
- Nuxt 当前默认共享模式绕过结果缓存；帖子详情在单后端模式也绕过响应缓存，避免缓存命中跳过浏览量增加；其他缓存一致性仍由共同缓存要求处理。数据库错误需安全收口，不能泄露 SQL、地址或帖子内容。

## 最终验证

三端均需通过相同的匿名、授权、私有/关注/提及/屏蔽、缺失、作者缺失、媒体结构不兼容、读取失败和计数副作用场景；隔离模拟只验证路由及绑定，不证明真实 SQL 权限函数。实际验收还需分别阻断 Nuxt 上游，使用隔离 Oracle/Redis，覆盖真实函数、并发计数、事务/断连、文件地址、时间、跨后端和两个前端。使用同一迁移版本，不改写日常数据库。

`scenarios/post-detail-vectors.json` 是共同隔离路由场景；Nuxt、Rust、Go 均执行全部样例，使用合成仓储和数据。这些测试不证明真实 Oracle 可见性函数或运行环境。
